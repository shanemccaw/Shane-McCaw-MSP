## What shipped (all real GitHub data, no fixtures)
1. **Per-Epic & per-Feature % rollups.** Extended the board GraphQL to pull `subIssuesSummary.completed` + `.percentCompleted` (was `total` only); carried through `GitBoardIssue` → `GitIssue`; `CreateIssueHeader` now renders a completion pill (e.g. `89% (8/9)`) on any issue that has sub-issues — which is exactly what a "Feature" is here (a parent issue with children). Completion is GitHub's own (a sub-issue counts done iff CLOSED), so it's accurate even though the board fetch is OPEN-only.
2. **Fix Feature-level issue visibility.** The rollup pill above makes a Feature's real content + progress visible without expanding it (the core "I can't see what's under a Feature" complaint — the audit confirmed children DO render, it was a discoverability gap). Plus: the active working epic's real `ParentNumber` ancestor chain now auto-expands, so the path down through intervening Features to the in-flight item is open on load.
3. **GATE card.** New `GateCardHost` in IssuesView. Surfaces every OPEN issue whose title starts `GATE:` (real convention — live-confirmed #1281/#1269/#1918) in the currently-shown milestone(s), as a purple card: eyebrow `GATE · BLOCKS RELEASE`, the title (prefix stripped), and a real fraction — sub-issue rollup (`3/7` for #1281) or, failing that, a `- [ ]`/`- [x]` body-checklist parse, or no fraction when neither exists (honest). Click → issue detail tab. Collapsed when no gate is in view.
4. **FOCUS badge.** Rendered on the milestone header that is the current `FocusModeService` active milestone (`IsActive` + `ActiveMilestoneNumber`), per Shane's final correction — surfaces existing state only, no new data model, no ACTIVE/UNASSIGNED (both dropped).
5. **WORKING/LOCATE bar** — preserved as-is (untouched).
