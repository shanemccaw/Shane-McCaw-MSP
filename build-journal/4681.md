## Changes Made
The issue's proposed fix ("resolve the checkout from the queue row's own `repo_owner/repo_name`") does **not** work on the live data, so the change is "tracking repo first, then discover the bookend's home" (full reasoning in the plan). Live: every one of the 3,066 `bt_build_queue` rows — including the M365Architect builds #4650/#4651/#4652 — has `repo = shanemccaw/Shane-McCaw-MSP` and an empty `cwd`. `repo_owner/repo_name` is the *tracking issue's* repo; the bookend's repo is recorded nowhere structured.

- **New** `desktop/BuildConsole/Services/BookendSourceResolver.cs` — maps an `owner/repo` to a real local checkout, accepted only when its `origin` remote equals it (`<secondary-root>\<owner>__<repo>`, then `<main-parent>\<repo>-clone`, `\<repo>`, then any sibling real clone). Never clones or downloads.
- `DoneBookendVerifier.cs` — `GetSatisfiedAsync` / `IsSatisfiedAsync` / `GetBlockedAsync` take an optional tracking-repo hint (existing callers compile unchanged). The tracking repo's checkout is read first (the pre-change read for this repo, unchanged); if it holds no bookend, the other configured repos (#3581 registry) are probed through **one cached `git ls-tree` per repo**. Exactly one hit is used and its commit is verified (`cat-file -t`, `merge-base --is-ancestor`) **in that repo against that repo's branch**; several hits = ambiguous = fail closed; an unresolvable tracking repo = fail closed (as an unresolvable root always was). Caches re-keyed `(repo, number)`; secondary repos fetch on a 5-min cooldown, only when actually probed.
- `BuildQueuePostgresClient.GetDoneOrVerifyingGithubRowsAsync` — also returns the row's `repo_owner/repo_name`.
- `FalseDoneReconciler.cs` — Shape A **and** the Shape B DONE check group rows by their own repo, call the verifier with that repo as the hint, and match results back by **row id** (never by bare number). Shape B had the same blind spot: a `done` row whose work landed in another repo read "no bookend" and was reset to `canceled` (a wrongful re-run).
- `BuildQueuePostgresClient.cs` / `BatterUpQueueService.cs` — corrected the now-stale "only checks THIS instance's own clone" comments at the #3582 sites. **Behavior there is unchanged**: the `itemIsPrimaryRepo` gate stays, because those calls pass bare numbers.
