  Real fix (points 2–3): `BuildQueuePostgresClient.GetDoneGithubRowsAsync` renamed to
  `GetDoneOrVerifyingGithubRowsAsync`, query widened to `WHERE status IN ('done', 'verifying')`
  (returns each row's real originating status too, for honest logging).
  `MarkFalseDoneReconciledAsync`'s reset guard widened to `status IN ('done', 'verifying')` —
  `canceled` is confirmed still the correct/safe reset target from a `verifying` start: every
  dedup dead-check (`BatterUpQueueService.RefreshAsync`, `QueueRowAsync`'s `IsTerminalStatus`
  check) only inspects the row's CURRENT status, never what it transitioned from.
  `FalseDoneReconciler.ReconcileAsync` updated to consume the widened row set and log the row's
  actual originating status (`'done'` or `'verifying'`) instead of assuming `'done'`.
