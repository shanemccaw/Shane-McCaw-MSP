## Audit adaptations from ShaneBuilder (per #2798's audit-each-capability instruction)
- **PAT storage** — ShaneBuilder's paste-PAT card wrote `SettingsStore.Set("secret:token:github", …)`; BuildConsole keeps its PAT in `BuildConsoleSettings.GitHubPat` (`%AppData%\BuildConsole\settings.json`, the same store `GitHubApiClient` reads), so `ApplyGitDoctorPastedPatAsync` does a `Load()` → set → `Save()` round-trip there (#2770-safe, not a torn write).
- **Theming** — ShaneBuilder's `Brush.*/FontFamily.*/FontSize.*/FontWeight.*` semantic resource keys are registered into the view's `Resources` in the ctor (mapped to BuildConsole's Catppuccin palette) so the ported render code resolves them unchanged.
- **Layout** — ShaneBuilder's version is a wide 3-pane document; BuildConsole hosts ActivityBar views in a narrow, resizable sidebar, so the same full capability is laid out vertically (findings → detail → branches → commit lookup → bridge → log), with action rows in WrapPanels so buttons wrap. Honest adaptation, not a reduced port.

## Note (not filed as a finding)
`GitDoctorService` spawns `git`/`cmd` via raw `ProcessStartInfo` (faithful to #2194), not BuildConsole's `SubprocessRunner` (the documented single git/gh spawn helper with the ancient-git-2.20.1 crash-retry/gate, memory #2539). The doctor's checks run on-demand from a manual rail click, not in the concurrent-launch bursts that trigger #2539, and the service already has timeout+kill handling — so this is a latent robustness consideration, not a proven bug or a fix I worked around; left as parity with the landed source rather than filed as a separate issue.
