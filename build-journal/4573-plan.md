## Problem Description

`CATALOG_DRIFT_BACKLOG` in [`sourceKeyContract.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/d734bc70ccc90d6196fd215483fb3339ce83e709/lib/dashboard-registry/src/sourceKeyContract.ts#L336-L408) enumerates 65 registry `sourceKey`s (66 metrics — `security:active-alerts` backs two) that name no row in the live `monitor_checks` catalog. Each resolves to `unknown_check_key` for every tenant forever, which every consumer renders as an empty cell indistinguishable from "not collected yet". #4560 recorded them as a dated backlog the guard passes but cannot grow. #4573 is the per-check audit: for each key, remap to a real successor **only** if that successor's real `extractedProperties` shape measures what the metric claims, else retire to the `not_collected:` sentinel, else leave it in the backlog with its blocker named.

## Root Cause Analysis

The registry (`metrics.ts`) was authored from a catalog document, not from the live catalog, and the catalog is DATA edited in SQL. Confirmed live this session:

- **None of the 65 exist in any status.** `select key,status from monitor_checks where key in (<65>)` → 0 rows (not even inactive). `tenant_monitor_profiles` holds 0 rows under any of them, so there is no historical data to preserve either.
- **A name-similar successor is frequently NOT a successor.** Four concrete traps found while auditing (each is the exact failure mode the issue warns about — a confidently wrong number, not an empty cell):
  1. `devices:os-patch-compliance` maps `count(osVersion)` to a field *named* `outdatedOsDeviceCount`. That counts every device with an OS version ([`monitor-executor.ts` `case "count"`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/d734bc70ccc90d6196fd215483fb3339ce83e709/artifacts/api-server/src/lib/monitor-executor.ts#L1543-L1560)), not the outdated ones. `filter_params`/`select_params` are NULL.
  2. `exchange:auto-forwarding-rules` counts outbound spam-filter **policies** with `AutoForwardingMode -eq "On"` ([`cmdlet-catalog.ps1:387-413`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/d734bc70ccc90d6196fd215483fb3339ce83e709/services/ps-execution/cmdlet-catalog.ps1#L387-L413)) — 0 or 1 — so remapping "External Auto-Forwarding Mailboxes" to it would print a policy count under a mailbox caption.
  3. `security:secure-score-by-category` for `security.secureScoreControls`: live `raw_response.value` is 90 daily score snapshots and `controlScores_values` is an array of 90 arrays. `aggregateGroupBy(..., "controlCategory")` would render **one bucket, `unknown = 90`** (verified by running that grouping over the real stored row).
  4. `cost:duplicate-assignments` (`countDuplicates(skuId)` over `/users`, `select_params` NULL): `skuId` is not a top-level `/users` field, so it is structurally always 0 (live value 0 over 27 users). `license:unused-assigned` stores a bare `countWhere` with no predicate, which the executor classifies as malformed ([`monitor-executor.ts:1496-1511`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/d734bc70ccc90d6196fd215483fb3339ce83e709/artifacts/api-server/src/lib/monitor-executor.ts#L1496-L1511)) and leaves unset.

## Proposed Changes

Registry edits are in [`metrics.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/d734bc70ccc90d6196fd215483fb3339ce83e709/lib/dashboard-registry/src/metrics.ts) and [`sourceKeyContract.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/d734bc70ccc90d6196fd215483fb3339ce83e709/lib/dashboard-registry/src/sourceKeyContract.ts). **REMAP** = change `sourceKey`, keep everything else. **RETIRE** = `sourceKey: "not_collected:<old-domain>-<tail>"`, `status: "not_collected"`, `smartEligible: false`, smart config removed (the registry tests require all three to travel together). **REMAIN** = stays in the backlog with its blocker.

Every REMAP's target field is confirmed to be the one `pickMappedValueField` selects for that exact `(metricKey, checkKey, targetFields)` — run against the real function; a permanent test will pin it.
