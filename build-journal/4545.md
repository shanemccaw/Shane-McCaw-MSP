## Changes Made

All four call sites named in the issue now call the same shared
`resolveTenantWritePreconditionRefusal` / `loadRequiredLicenseSkuListsByTemplate`
pair (`artifacts/api-server/src/lib/tenant-write-preconditions.ts`) that Config Pack
runs, `execute_action`, and SOP runs already used — no per-site reimplementation:

- `artifacts/api-server/src/lib/tenant-write-preconditions.ts` — exported one shared
  `PRECONDITION_HTTP_STATUS` map so the new HTTP routes don't each carry their own
  copy of the refusal-code → status mapping.
- `artifacts/api-server/src/routes/admin-baseline-templates.ts` — the
  `POST /admin/baseline-templates/:templateId/test` test-run route now refuses
  (422/409, no write) before calling `runBaselineTemplateAgainstTenant`.
- `artifacts/api-server/src/routes/admin-write-actions.ts` — the
  `POST /admin/write-actions/:templateId/execute` simulator execute route, same fix.
- `artifacts/api-server/src/lib/workflow-executor.ts` — the generic
  `execute_baseline_template` workflow node loads the template's method/endpoint/body
  and license requirement, evaluates the same precondition, and sets
  `nodeError`/`switchChosenHandle`/`output` to the refusal instead of executing.
- `artifacts/api-server/src/routes/msp-launch-control.ts` — `POST
  /msp/:mspId/launch-control/execute` already had the #3947 license gate (a
  different, older, still-correct mechanism); added the missing Security Defaults
  replacement rule via the same shared call, placed before
  `raiseChangeRequestForLaunchControlExecution` so a refused write never raises a
  Change Request.
- Extended `artifacts/api-server/src/lib/tenant-write-preconditions.live-verify.ts`
  with 3 new real, opt-in live-verify test cases (one per HTTP/workflow site) proving
  each refuses `quickstart-v1.disable-security-defaults` against the real testbed
  tenant with no audit-log row written.
