  ### How the issue's constraints are actually met

  - **Grouped by workload and resource type** — both documents group their rows by
    `config_snapshot_resource_types.workload`, joined in from the resource key (no FK, matching
    the store's own convention).
  - **Completeness shown honestly.** The snapshot document lists every targeted resource type,
    including skipped/failed ones, each with its real `skip_reason`/`reason_detail`/HTTP
    evidence — nothing omitted. The diff document's resource-comparability report does the same
    for `not_comparable`/`partially_comparable` resources, copying both sides' real status.
  - **Design system followed verbatim**, not derived: dark canvas, Inter (already the admin-panel
    app font), the severity thresholds (`>=60` healthy / `>=50` attention / `<50` critical) used
    as an honest "how much of this document could be read/compared" measure — never as a
    judgement on the tenant's configuration. Deltas (objects added/removed, changes) render in
    teal, never a severity colour. A denominator of zero renders "unavailable", never a red zero.
  - **No fabricated data.** Every row comes from `tenant_config_snapshots` /
    `tenant_config_snapshot_resource_status` / `config_diffs` / `config_diff_resource_status` /
    `config_diff_changes`. No `*Data.ts` fixture module; an empty response renders an honest
    empty state (verified: the empty-state copy names the real table with zero rows).
  - **Does not restyle or duplicate the findings/pillar reporting** — this is a different
    document (what configuration IS), kept in its own `configReport/` folder, not touching the
    existing health/pillar surfaces.

  ### A real bug found and worked around, not fixed — filed as #2032

  `config_diffs` row 8 (the pair #1797's own bookend describes as its decisive full-tenant run:
  340 changes, 155 comparable, 1,203 not_comparable) held only 6 comparable resources / 213
  objects / **0 changes** when I queried it — a later resource-scoped "parity check" recompute
  (`useCache:false` + `resourceKeys`) had silently overwritten it, because `resourceKeys` is not
  part of the diff cache key `(base, head, mode, rulesetFingerprint)`. I restored the full
  evidence myself by re-running `verify-1797-differ.ts 8 10 --mode drift` with no `--resources`
  filter (landed as new row 9, since the active ruleset's fingerprint had since changed) — a
  workaround, not a fix. Filed as **#2032**, parented to **#1096**, board status "AI Batter Up".
  No tenant writes; this is a local diff-store recompute only.
