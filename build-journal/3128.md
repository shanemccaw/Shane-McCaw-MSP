# Git #3128 — Shopping page doesn't scroll (emulated + normal browser)

- **Status:** ✅ DONE 2026-09-07T00:45:00Z
- **Scope:** shanes-life (web/shanes-life)

## Log
- 2026-09-07T00:00:00Z — Session started. Investigating public/app.css + public/index.html Shopping room container overflow/height constraint.
- 2026-09-07T00:45:00Z — ✅ DONE — Root cause found by headless CDP repro (Edge, real WebSocket
  driven `Input.dispatchMouseEvent` wheel event, not JS `scrollTo`): `html, body { overflow-x:
  hidden; }` in `public/app.css` had `overflow-x: hidden` on BOTH the root `<html>` element and
  `<body>`. Setting it on `<html>` as well collapses Chromium's compositor scroll node for the
  WHOLE page (both axes) -- `window.scrollTo()` kept working because it sets the scroll offset
  directly, but real wheel/touch-driven scroll was dead, on every room using the shared shell
  (Today/Shopping/Inbox/Things/Settings all share this rule), matching Shane's real report in
  both desktop and emulated-mobile rendering. Fix: moved `overflow-x: hidden` to `body` alone,
  leaving `html` unconstrained so the real scroll node stays intact; the horizontal watermark-
  bleed clipping (Git #3119) this rule exists for still works since body alone clips it.
  Verified with two headless repros: a minimal fixture using the real app.css/DOM shell, and the
  real `public/app.js` Shopping room (mocked `/api/me`, `/api/shopping`, `/api/stores`) with 60
  items -- both went from `scrollY` stuck at 0 after a real wheel event (bug reproduced) to
  `scrollY` advancing normally after the fix (bug fixed). No DB/backend changes needed; this was
  a pure CSS defect affecting all rooms, not Shopping-specific.
  Commit: 017a1e3f8 (`web/shanes-life/public/app.css`), merged to origin/main at f85cc8ca1.
  Scratch test scripts (`_scroll_test.mjs`, `_scroll_test2.mjs`, `public/_scroll_repro.html`,
  edge profile dirs) were created and deleted before the final commit -- none landed in the tree.
