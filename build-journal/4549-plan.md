# Plan — #4549: CA create templates keep "(report-only)" suffix after promotion/immediate-enforce

**Posted:** 2026-09-17T22:20:00Z

## Problem Description

Five of the six Conditional Access baseline create templates hard-code a
`displayName` ending in the literal string `" (report-only)"` in
`baseline_action_templates.body_template`. Since #4522, the same templates
resolve `"state": "{{caPolicyState}}"`, so:

- A Config Pack run with `caEnforcementMode: "immediate"` creates the policy
  already `enabled`, but its name still says `(report-only)`.
- The #4522 promotion workflow (`action.set-ca-policy-state`, PATCH `{state}`
  only) flips an existing report-only policy to `enabled` and leaves the name
  unchanged.

Either path leaves a tenant-side policy whose real state (`enabled`) and
displayed name (`… (report-only)`) disagree.

## Root Cause Analysis

- `lib/db/migrations/manual/2026-09-17-ca-enforcement-mode-and-promotions-4522.sql`
  rewrote each create template's `state` field to `{{caPolicyState}}` but never
  touched `displayName`.
- `action.set-ca-policy-state`'s `body_template` is `{"state": "{{state}}"}`
  only (`lib/db/migrations/manual/2026-09-13-write-action-catalog-users-domain-batch-2494.sql`)
  — no `displayName` field to PATCH.
- `promoteCaPolicy` in
  `artifacts/api-server/src/lib/ca-policy-promotion.ts` builds
  `proposedPayload = { policyId, state: CA_STATE_ENABLED, customerId }` — it
  never reads or forwards the policy's current `displayName`.
- Separately, `lib/db/migrations/manual/2026-09-17-ca-policy-existence-lookup-4531.sql`
  gives each of the six create templates a resolve-then-skip lookup keyed on
  an EXACT (`ieq:`) match of the suffixed `displayName`. This is exactly why
  the issue says a rename is not a one-line fix: renaming a live policy (or
  the template body) without also updating this lookup makes the next pack
  run fail to recognize its own policy and create a duplicate.

## Proposed Changes

1. **Stop encoding transient state in the name at all.** The suffix's only
   job was to tell an admin "this one is report-only" — but `state` is
   already the real, authoritative source of truth everywhere else in the
   codebase (`listCaPoliciesForTenant`: `reportOnly: p.state === CA_STATE_REPORT_ONLY`,
   https://github.com/shanemccaw/Shane-McCaw-MSP/blob/2319db4a8b499b2cdcd3df0ab8908d108920e131/artifacts/api-server/src/lib/ca-policy-promotion.ts#L140).
   Strip `" (report-only)"` from the five affected templates'
   `body_template.displayName` so a freshly created policy's name is accurate
   under *either* enforcement mode, and a promoted policy's name never needs
   to lie in the first place going forward.
   Templates: `action.create-ca-legacy-auth-block-policy`,
   `action.create-ca-mfa-all-users-policy`, `action.create-ca-signin-risk-policy`,
   `action.create-ca-user-risk-policy`, `action.create-ca-guest-mfa-policy`.
   (`quickstart-v1.create-ca-baseline-policy` never had the suffix.)

2. **Rename path for policies that already exist** (the issue's explicit
   second requirement). Add `displayName` to `action.set-ca-policy-state`'s
   `body_template` (`{"state": "{{state}}", "displayName": "{{displayName}}"}`)
   and its `required_params`. `promoteCaPolicy`
   (https://github.com/shanemccaw/Shane-McCaw-MSP/blob/2319db4a8b499b2cdcd3df0ab8908d108920e131/artifacts/api-server/src/lib/ca-policy-promotion.ts#L445)
   now computes `newDisplayName` by stripping the suffix from the policy's
   *current* live `displayName` (new helper `stripCaReportOnlySuffix` in
   `ca-enforcement-mode.ts`) and always includes it in `proposedPayload` — a
   policy that was already renamed (no suffix) gets the exact same name
   written back, a no-op PATCH. This also covers already-existing testbed
   policies created before this fix.

3. **Existence-lookup naming scheme that matches both before and after.**
   `resolve-then-write.ts` already supports an `"in:a,b"` selectMatch
   convention (case-insensitive membership). Rewrite each of the five
   templates' skip-write `selectMatch.displayName` from
   `ieq:<suffixed name>` to `in:<clean name>,<suffixed name>` so a pack
   re-run recognizes its own policy under either name — the legacy suffixed
   name (not yet promoted/renamed) or the new clean name (freshly created, or
   renamed by step 2) — without ever creating a duplicate.

Migration file:
`lib/db/migrations/manual/2026-09-17-ca-report-only-suffix-rename-4549.sql`
— additive/data-only jsonb rewrites plus the promotion-audit-trail–adjacent
code changes above. No DDL.

## Verification Plan

- Run the new migration against local Postgres (`DATABASE_URL`), confirm via
  `psql.mjs` that the five `body_template.displayName` values and the
  `action.set-ca-policy-state` `body_template`/`required_params` rows read
  back as expected, and that each of the five templates' skip-write step now
  reads `in:<clean>,<suffixed>`.
- `pnpm --filter api-server vitest run` the existing CA suites
  (`ca-enforcement-precondition-4522.test.ts`,
  `ca-policy-existence-lookup-4531.test.ts`, `ca-policy-promotion` if present)
  plus a new/updated test asserting `promoteCaPolicy` sends a
  suffix-stripped `displayName` in `proposedPayload`.
- Grep confirms no other CA template body still contains the literal
  `(report-only)` in a `displayName`.
