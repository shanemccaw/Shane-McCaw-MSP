- 2026-08-31 ⏳ IN FLIGHT — Investigated: `EXPIRED` is already fully gone from the decision-state
  vocabulary. `POLICY_DECISION_STATES = ["proposed","live","due"]` (schema comment explicitly
  cites #1527) landed via `33f8b5a34` (#1507) and `d1d9b41b3` (#2024's own `policy_decisions`

  decision-state-relevant route or schema file.

  Real gap found: the issue's third bullet, "Overdue alerts to the MSP per #1513", is NOT fully
  satisfied. #1513's `risk_review_overdue` alert-engine evaluator only advances/reads
  `msp_risk_decisions.review_state` — it never touches the newer `policy_decisions` table
  (Git #2024), which post-dates #1513 in the commit graph and defines the exact same
  `reviewState`/`reviewDueAt` columns for the SAME operational lane but is never evaluated.
  Also: neither table's operational writer ever syncs `decisionState` off `reviewState`, so the
  issue's own design sentence — "overdue reviews surface as an operational flag on a decision
  that remains LIVE" — has no code making it true: `decisionState` is frozen at whatever it was
  set to at creation and never reflects `due`/collapses back to `live` on overdue.

  Building: (1) a `policy_review_overdue` alert condition mirroring `risk_review_overdue` for
  `policy_decisions`, wired into `alert-engine.ts` + a seeded `msp_alert_rules` row; (2) syncing
  `decisionState` from `reviewState` in both operational writers (on_track/overdue → `live`,
  due → `due`) so the "remains LIVE" design fact is real, not just documented.

  NOT building: a reviewCadence-to-reviewDueAt parser for `policy_decisions` (`reviewDueAt` stays
  null for every row today — nothing computes it from the free-text `reviewCadence` field, by the
  schema's own explicit design note). Inventing a cadence vocabulary to parse against is exactly
  what that same note forbids, and doing it well requires a real product decision (fixed cadence
  enum vs. free-text parsing) this session shouldn't make silently. Filing as a finding instead.
