# #4482 — Plan: `sendSmsOtp` logs plaintext OTP & reports success when Twilio unset (any env)

- **Author:** Claude Opus 4.8 (build 3183)
- **Posted:** 2026-09-17T23:22:14Z
- **Base commit:** dee94570cd2c64959c4087f0ca807ef962a3c37f

## Problem Description

`artifacts/api-server/src/routes/mfa.ts` `sendSmsOtp()` has a fallback branch that
fires whenever any of `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` / `TWILIO_FROM_NUMBER`
is unset:

```ts
if (!accountSid || !authToken || !from) {
  log.warn({ code }, "Twilio not configured — OTP code not sent (dev mode)");
  return;
}
```

The message claims "dev mode" but nothing checks the environment. In any deployment
missing those env vars, every SMS one-time code is written **in plaintext** to the log
stream, and the function returns normally so every caller reports the code as sent when
nothing was sent. A second-factor code in a log is a credential in a log — anyone with
log read access can complete an SMS challenge.

## Root Cause Analysis

The fallback conflates two separate concerns: (a) whether SMS delivery is configured,
and (b) whether we are on a developer's own machine where surfacing the code is an
acceptable local-dev convenience. It gates on (a) only and then does the (b) behaviour
(log the code) plus silently returns success — in every environment. `#1380` already
established the correct gate for verification-code exposure elsewhere in this codebase:
`process.env.NODE_ENV === "development"` — a strictly-`development` check, distinct from
the looser `isDev = NODE_ENV !== "production"` (which is also true in test/staging).
See `public-purchase-account.ts:126` (`isLocalDevCodeExposure`).

## User Review Required

None. This is a security fix with a well-defined correct behaviour and no product
decision (no money, entitlement, customer-facing promise, or conflict with a recorded
decision). All six call paths were audited and each already surfaces a graceful error
path for a throw (see below) — no caller crashes.

## Proposed Changes

Single-file change in `sendSmsOtp`
(`artifacts/api-server/src/routes/mfa.ts`, current blob:
https://github.com/shanemccaw/Shane-McCaw-MSP/blob/dee94570cd2c64959c4087f0ca807ef962a3c37f/artifacts/api-server/src/routes/mfa.ts#L1271-L1293):

- When Twilio is unconfigured:
  - **`NODE_ENV === "development"` only** → keep the log-the-code convenience (relabelled
    "local dev only"), return. Never anywhere else.
  - **Every other environment** (staging/production/test) → log an error **without the
    code** and `throw` so callers surface their existing "could not send" path instead
    of falsely reporting success.
