## Log
- 2026-09-02T15:52:00Z ⏳ IN FLIGHT — Confirmed root cause: `scripts/report-progress.mjs` computes
  `repoRoot = path.resolve(__dirname, "..")`, which resolves to whichever worktree the script's own
  copy lives in. When a build runs in an isolated worktree (the normal case per the mandatory
  worktree-isolation rule), the progress JSON lands at `<worktree>/.logs/dev-all/progress/<id>.json`.
  ShaneBuilder's reader (`MainWindow.xaml.cs` `ReadPaletteBuildProgress`, added in #2203) correctly
  reads from `_logService.MainRepoRoot/.logs/dev-all/progress/<id>.json` — the real shared main
  checkout, resolved via the git-commondir walk in `LogService.ResolveMainRepoRoot`. The two never
  meet for a worktree-run build, so the palette's Builds/Build IDs pane always falls back to the
  coarse "no step/% reported yet" message for any build that ran in a worktree. Fix: make
  report-progress.mjs resolve the same shared main-repo-root `scripts/dev-server/config.mjs`
  already computes (`loadConfig().devAllLogDir`, via `git rev-parse --git-common-dir`) instead of
  its own `__dirname`-relative path, so writer and reader agree regardless of which worktree ran
  the build.
