## Problem Description
`identity:ca-legacy-auth-block` and `identity:ca-mfa-coverage` gate-skip on Security Defaults tenants but do not stamp `securityDefaultsEnabled: true` the way `identity:ca-policy-count` does (#4576), so the SIGNALS cards read `gate_skipped` instead of `security_defaults_active`.

## Root Cause Analysis
[`monitor-executor.ts` gate-skipped block](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/701e378eeb3489a8eb50fa061ccb3849f82192ce/artifacts/api-server/src/lib/monitor-executor.ts#L3985-L3993) only stamps extras for `identity:ca-policy-count`. Local `monitor_checks`: ca-legacy-auth-block and ca-mfa-coverage share the Security Defaults gate (`{{isEnabled}} != true`); **`identity:ca-device-compliance` has no gate_endpoint/gate_expression at all**, so it has no gate-skipped path and a stamp there would be dead code.

## Proposed Changes
In [`monitor-executor.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/701e378eeb3489a8eb50fa061ccb3849f82192ce/artifacts/api-server/src/lib/monitor-executor.ts#L3990-L3993), stamp `securityDefaultsEnabled: true` for ca-legacy-auth-block and ca-mfa-coverage (ca-policy-count keeps its `caPolicyCount: 0`). Only the flag is stamped; no invented enforced-count scalars. ca-device-compliance is left alone and filed as a finding.
