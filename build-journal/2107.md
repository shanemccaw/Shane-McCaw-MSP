## Log
- 2026-09-06T15:14:54Z ⏳ IN FLIGHT — confirmed root cause per issue body:
  `BuildQueuePanel._openIssues` is only populated via `ApplyOpenIssueSet()`, fed
  exclusively by `LeftSidebar.GitBoardOpenIssuesRefreshed`, which only fires on
  Issues-tab-open or manual Git Board refresh (2026-08-14 manual-only conversion).
  Going with option 3 from the issue (event-triggered refresh, not periodic polling
  — preserves the manual-only decision) combined with the existing lightweight
  one-shot `gh` call BuildWatchWindow.CheckIssueClosuresAsync already uses for its
  "Recheck closures" button (`GitHubIssuesService.GetOpenIssueNumbersAsync`):
  BuildQueuePanel.RefreshAsync (its own local-DB poll, not GitHub) now detects when
  a queue item transitions into Verifying/terminal state and, on that real
  transition, fires one lightweight `gh issue list` call to refresh `_openIssues`
  — the exact moment option 3 names as "a blocker is most likely to have just
  closed." Also adding a last-refreshed-at cue to the BLOCKED badge/tooltip
  (option 1) so staleness is visible even between transitions.
