# #4579 plan — combined expired-credential total

## Problem Description
`appgov:cert-secret-expiration` emits `expiredKeyCredentialCount` and `expiredPasswordCredentialCount` separately; no field sums them, so the pillar tile (#4560) can only show secrets.

## Root Cause Analysis
The check's stored `monitor_checks.mapping` (see `lib/db/migrations/manual/2026-08-07-cert-secret-expiration-mapping-severity-541.sql`) is four `countWhere` rules, each over one array. `applyMapping` (`artifacts/api-server/src/lib/monitor-executor.ts`) has no transform that combines two already-computed target fields, and `countWhere` cannot span two source arrays.

## User Review Required
Naming/semantics: the two existing fields measure *already expired* (`olderThanDays 0`), and the forward-looking window was explicitly deferred in #541. The new field is therefore `expiredCredentialCount` (expired-only) — not "expiring" — so it stays truthful. A within-N-days field needs a forward-bound operator and a window decision from Shane; not done here.

## Proposed Changes
1. `monitor-executor.ts`: new mapping transform `sumOf('fieldA','fieldB',...)` that sums previously computed numeric target fields of the same run (rules run in order); added to `KNOWN_TRANSFORMS` and the doc comment. Non-numeric/missing operands count as 0 with a warning.
2. New manual migration `lib/db/migrations/manual/2026-09-19-cert-secret-expiration-combined-total-4579.sql` appending `{"sourceField":"*","targetField":"expiredCredentialCount","transform":"sumOf('expiredPasswordCredentialCount','expiredKeyCredentialCount')"}` to the mapping; the two existing fields are kept. Run against local DB.
3. Extend `cert-secret-expiration-541.test.ts` with the combined field.
