## Answer to the question the issue actually asked

**No regression in `portal-checkout.ts`.** Production checkout code is untouched by this build. The
`expected 500 to be 200` assertion failures are a *consequence* of the timeouts, not an independent
application error.

Root cause: `makeApp()` ran `await import("./portal-checkout")` inside every test body, so the route
module's cold Vite transform was billed against the first test's 5000ms budget. `portal-checkout.ts`
imports `./portal-checkout-direct`, which drags in `mailer.ts` → `graph.ts`, `tenant-signals.ts`
(1,864 lines) → `sla-engine.ts`, and `crm-pipeline.ts` → `zoho-lead-sync`/`zoho-client` — the whole
outbound-email + Microsoft Graph + Zoho stack transformed for a unit test that mocks Stripe and the
database. On a loaded box that transform took 15–40s, so the first several tests all timed out on the
same in-flight import; the first test to run *after* it resolved then returned 500, because the
timed-out tests' handlers resumed and consumed the `mockReturnValueOnce()` chains that test had just
queued in `beforeEach`. Every observed 500 landed on exactly that test — the signature of the cascade,
not of a logic defect.

Fix, in the test file only: stub `./portal-checkout-direct` (neither export is reachable from these
ten tests), mock `../lib/captcha` (it makes a real HTTPS call to Cloudflare when
`TURNSTILE_SECRET_KEY` is set — see #2882), hoist the import into a `beforeAll` so no test body ever
pays for it, and a file-scoped `vi.setConfig({ testTimeout: 20_000, hookTimeout: 120_000 })` backstop
(same precedent as #2865).
