# #4548 — Plan: real AAD_PREMIUM_P2 service-plan detection in `useCaBaselineLive`

**Posted:** 2026-09-18T02:14:00Z

## Problem Description

`useCaBaselineLive.ts` derives `hasEntraP2` by testing the raw `subscribedSkus`
row's `skuPartNumber` field against a hardcoded allowlist
(`P2_SKU_PART_NUMBERS`) instead of reading whether the tenant's SKUs actually
*provision* the `AAD_PREMIUM_P2` service plan. Any real E5-family/EDU/GOV
`skuPartNumber` not on that list (e.g. `SPE_E5_NOPSTNCONF`,
`Microsoft_365_E5_(no_Teams)`, `M365EDU_A5_FACULTY`, `EMSPREMIUM_GOV`) reads
as "no P2" even when the tenant genuinely holds the plan; conversely a listed
SKU counts even if its P2 plan isn't actually provisioned on that tenant.

`hasEntraP2` currently has no consumer in `artifacts/` (confirmed:
`grep -rn hasEntraP2 artifacts/` matches only the three internal
declarations/returns inside this hook), so nothing is misreporting on screen
yet — but it will as soon as the first P2 badge wires to it.

## Root Cause Analysis

Same defect class already fixed twice tonight on the server side:

- #4512 / [`1f18ef450`](https://github.com/shanemccaw/Shane-McCaw-MSP/commit/1f18ef450caabe3758cd6fdff6aee0c35ce5bc68) — CA checks read the tenant's live service plans instead of trusting a SKU allowlist for the P1 license prerequisite.
- #4534 / [`a75fc98ad`](https://github.com/shanemccaw/Shane-McCaw-MSP/commit/a75fc98ad) — same pattern applied to device-compliance checks.
- #4535 / [`c387decc8`](https://github.com/shanemccaw/Shane-McCaw-MSP/commit/c387decc88e1901c494538d2fa467dfb45dc752f) — Launch Control / Config Pack / tenant-write preconditions moved off `skuPartNumber` entirely onto `getProvisionedServicePlanNamesForTenant` (`artifacts/api-server/src/lib/license-gate.ts`), which reads `/subscribedSkus?$select=capabilityStatus,servicePlans` and treats a plan as held only when its parent SKU's `capabilityStatus` is `Enabled`/`Warning` **and** the plan's own `provisioningStatus === "Success"`.

`useCaBaselineLive.ts` was never touched by any of those three fixes — it's a
portal-side (client) hook, not an api-server module, so it kept its original
`skuPartNumber`-list heuristic (predates #4512/#4534/#4535 by a wide margin;
see the file's own header referencing #1232/#339/#776).

**Verified the fix is actually applicable here, not just structurally
similar:** queried the live local dev database directly —

```sql
select jsonb_pretty(items->0) from tenant_check_item_details
where check_key = 'license:sku-utilization' order by collected_at desc limit 1;
```

— and confirmed a real persisted row for `license:sku-utilization` already
carries the full `servicePlans[]` array (`servicePlanName`,
`provisioningStatus`, etc.) per SKU, alongside `capabilityStatus` is present
on each Graph-fetched row's top level. This is because that check's DB row
(`monitor_checks.select_params` for `key = 'license:sku-utilization'`) has no
`$select` filter, so `monitor-executor.ts`'s standard Graph path
(`graphFetchPaginated` → raw `items` persisted verbatim, unfiltered by
`properties`) keeps every Graph-default field of the `subscribedSku` resource,
`servicePlans` included. The item-detail collector does not need to be
extended — the issue's own "check first" caveat resolves to: no extension
needed.

## Proposed Changes

Rewrite the `hasEntraP2` derivation in
[`artifacts/portal/src/components/useCaBaselineLive.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/67e7edbee280c7558289853e5df523125e5847e0/artifacts/portal/src/components/useCaBaselineLive.ts#L44-L103)
to mirror `getProvisionedServicePlanNamesForTenant`'s real rule instead of the
`P2_SKU_PART_NUMBERS` allowlist:

1. Delete `P2_SKU_PART_NUMBERS`.
2. For each raw `license:sku-utilization` row: only consider it if
   `capabilityStatus` is `"Enabled"` or `"Warning"` (mirrors
   `USABLE_SKU_CAPABILITY_STATUSES` in `license-gate.ts`).
3. Within a usable row's `servicePlans` array, `hasEntraP2` is true iff any
   entry has `servicePlanName === "AAD_PREMIUM_P2"` **and**
   `provisioningStatus === "Success"`.
4. Keep the existing null-until-loaded / best-effort-empty-state contract
   (Git #1439) — no other shape of `CaBaselineLiveState` changes.

No backend, schema, or route change is needed — the real field already flows
through `GET /api/portal/tenant-check-items` unfiltered.
