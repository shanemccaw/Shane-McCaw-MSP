  Root cause: `PollAsync`'s single queue fetch (`_db.GetQueueAsync()`/`_api.GetQueueAsync()`) gates EVERY non-interactively-owned ("read-only") slot's refresh that tick — `TailSlotLog`/`UpdateThinkingText` for those slots only run after it returns. A build genuinely launched by THIS app instance keeps rendering regardless via `DrainInteractiveOutput`'s own render pump (fed from the in-memory watcher buffer, independent of this fetch) — exactly the asymmetry reported: 5 read-only panes stuck, the 1 owned interactive pane (#4588) still moving. The old `catch { return; }` around that fetch also logged nothing, so a real stall there was invisible in ActivityLog.
  Fix (`desktop/BuildConsole/BuildWatchWindow.xaml.cs`): wrapped the fetch with a real 10s timeout (`Task.WhenAny`) so a slow/stuck fetch degrades to "skip this tick, retry in 3s" instead of being able to wedge every read-only slot's refresh indefinitely, and logs the real failure (timeout or exception) via ActivityLog either way, closing the silent-swallow gap.
