  (Steps 1+2 of `GetNextAsync`: `WHERE status='queued' ORDER BY created_at ASC`, minus
  `PausedBuildIds`, filtered to rows whose every blocker GitHub reports closed, fail-closed)
  into a shared, strictly read-only `SelectClaimCandidatesAsync`. Both `GetNextAsync` (which

## Decisions

- **Per Shane's correction comment:** NO usage footer in the dropdown. `UsageTrackingService`
  and all its call sites left completely untouched (#1864 owns the title-bar readout — already
  landed on main as `8ecf8ecd7`). The dropdown is the four counts + the next five, nothing else.
- **`QueueWatcherService.GetActiveUsageSummary()` kept** — the unchanged "(N active)" running
  readout still consumes its `ActiveBuildCount`. It has no other caller, but it is still called,
  so it stays.
- **Cold start (`_openIssues == null`, before first Git Board refresh):** blocked-ness is
  UNKNOWN. Fails toward the old declared-blocker heuristic (any declared blocker ⇒ blocked) and
  renders the Blocked figure **provisionally** — muted colour, trailing `*`, tooltip explaining
  it's waiting for the first refresh. The dropdown, likewise, says "Waiting for the first Git
  Board refresh…" rather than showing an order computed without blocker knowledge.
- **Reconciliation / bucket precedence:** among `queued` rows the four buckets PARTITION with
  manually-paused taking precedence (paused rows are set aside exactly as `GetNextAsync` filters
  them before the blocker check). So Blocked = non-paused queued with an open blocker; Up next =
  non-paused queued, all blockers closed (= `GetNextAsync`'s own candidate set). This makes
  `Blocked + Up next + manually-paused + limit-paused == In queue` true by construction, matching
  the issue's own reconciliation equation (which lists manually-paused as a separate addend from
  Blocked). `parked`/`external` excluded from all four.
