# #4485 — env stubs for public-free-scan-results.test.ts

## Problem Description
`artifacts/api-server/src/routes/public-free-scan-results.test.ts` fails to load because it
transitively imports `consent.ts` → `workflow-executor` → the Anthropic AI integration client,
which throws at module-load time when `JWT_SECRET`, `AI_INTEGRATIONS_ANTHROPIC_BASE_URL`, and
`AI_INTEGRATIONS_ANTHROPIC_API_KEY` are unset. Its sibling
`public-free-scan-remediate.live-db.test.ts` already carries the `??=` stub fix for this
(https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/artifacts/api-server/src/routes/public-free-scan-remediate.live-db.test.ts#L27-L30).

## Root Cause Analysis
Same root cause as the sibling live-db test: env vars required at module load time by a
transitively-imported AI client are not set in the test process, causing a load-time throw
instead of a clean test run/skip.

## Proposed Changes
Add the same `??=` stubs to the top of `public-free-scan-results.test.ts`, before its imports:
- `process.env.JWT_SECRET ??= "..."`
- `process.env.AI_INTEGRATIONS_ANTHROPIC_BASE_URL ??= "https://anthropic.test"`
- `process.env.AI_INTEGRATIONS_ANTHROPIC_API_KEY ??= "test-anthropic-key"`

Also check whether this suite needs `DATABASE_URL` skip handling matching the sibling's pattern
(it already creates real DB rows via `@workspace/db`, so likely needs a `describe.skipIf` or
similar guard if `DATABASE_URL` is unset — matching whatever pattern is already used elsewhere
in this file/sibling).

## Verification Plan
Run from `artifacts/api-server`:
```
DATABASE_URL=<local> npx vitest run src/routes/public-free-scan-results.test.ts
```
Confirm all tests pass (not "no tests found" / module-load failure).
