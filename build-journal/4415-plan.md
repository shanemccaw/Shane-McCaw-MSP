# #4415 — Command Center: "Reset dev database" quick action — plan

(Honest note: this was written after investigation, before the work commit; the plan below is the
one the implementation followed.)

## Real current state (read before wiring)
- `scripts/db/reset-dev-database.mjs` (#4393): `--dry-run` = BEGIN...ROLLBACK, prints the plan, no
  backup; no flag = real reset behind an interactive `Type "yes"` prompt; `--yes` = real reset,
  no prompt. A real run always re-runs its own dry run first, takes a `pg_dump -Fc` backup into
  `C:\Source\ShaneMcCawConsulting\db-backups\` (verified with `pg_restore --list`), then commits.
  Exception sets (26 PRESERVE_TABLES, 9 ORPHAN_FULL_WIPE_TABLES) and the #4399
  UNCONSTRAINED_FK_SHAPED_EDGES workaround live in the script — nothing to re-derive in C#.
- Script header comment claimed "both modes take a backup" — the code only backs up on a real run.
- Palette: `CommandPaletteWindow` + `MainWindow.CommandPalette.cs`. Commands with `RunWithResult`
  keep the palette open and render real output in the right pane (#3826). Enter on a selected row
  re-runs that row's action. SQL (#3828) and Dispatch (#3829) are text-/caller-driven modes.
- Existing destructive-confirm pattern in the app: `MessageBox.Show(..., YesNo, Warning)`
  (BuildQueuePanel "Remove Entire Set", DispatchPanel force re-dispatch). Unusable here: Yes is
  the default button (a stray Enter confirms), and opening it deactivates the palette, which
  closes itself on `Deactivated` — the result could never render in-pane.
- `SubprocessRunner` retries children that exit with crash-class NTSTATUS codes — wrong for a
  destructive run.

## Plan
1. `Services/DevDatabaseResetGate.cs` — one instance per palette window.
   - `PreviewAsync()` → `node reset-dev-database.mjs --dry-run`; on exit 0 + the script's own
     target-MSP and dry-run-success lines, arm `ConfirmPhrase = "reset msp #<live id>"`.
   - `ExecuteAsync(typed)` → re-checks the phrase itself, consumes the confirmation, runs `--yes`
     once (no retry, stdin closed, long timeout), leads the result with the real `Backup:` path.
2. Command row "Reset dev database" (`RunWithResult = gate.PreviewAsync`) — the only thing the
   main list / tile / Enter can reach.
3. Palette "reset confirm mode" auto-detected from input shaped `reset msp #N` (like SQL mode).
   Enter/button run the real reset only when armed; otherwise a locked explanation. Up/Down/Tab
   inert in that mode. Toast backstop on completion (palette may close on focus loss).
4. Script: dry run reports where a real run's backup would go; fix the stale header comment.
   README: document the Command Center gate.
5. Verify: `dotnet build`; headless probe (separate exe, never launches BuildConsole.exe, never
   shows a window) driving the real window's `Window_PreviewKeyDown` + real gate against the local
   dev DB — phrase-before-preview, single Enter preview, accidental second Enter, wrong phrase,
   exact phrase real reset (backup on disk, staff logins preserved), Enter after consumption.
