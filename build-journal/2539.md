- 2026-09-03T14:40:00Z ✅ DONE — **Real root cause (evidenced, NOT the issue's guess):** the
  Windows Application event log shows `gh.exe` (2.96.0) never faulted and NO `0xc0000142` event
  exists anywhere in 14 days. The real, repeated crasher is `git.exe` **2.20.1.windows.1 (Dec
  2018)** aborting with **`0x40000015`** (STATUS_FATAL_APP_EXIT) ~28× across 14 days, always at
  fault offset `0x1fe258`/`0x1ee3ce`, clustered in short concurrent bursts (e.g. 2026-09-01
  11:29:26 — two in the same second) — a transient contention crash of an ancient binary. The
  "gh.exe 0xc0000142" dialog text in the issue was a misattribution.
  **Fix shipped (commit `b78bb1929`):** new `desktop/BuildConsole/Services/SubprocessRunner.cs` —
  one place all git/gh children spawn, with (1) honest stdout+stderr+exit capture (same surface
  #2535/#2536 built), (2) retry-with-backoff keyed to crash-class NTSTATUS codes
  (`IsCrashExitCode`: `0x40000015`, or any error-severity `0xC0000000`+ incl. `0xC0000142`/`0005`/
  `013A`) — a legit git/gh exit (1,128,…) is NOT retried, (3) a bounded `SemaphoreSlim` (max 4) so
  BuildConsole's own startup spawn burst is staggered, and (4) kill+report (never retry) on a hung
  child's timeout. Refactored 12 ad-hoc spawn sites onto it: StartupConnectivityService git probe
  (fixed a real false-success bug — a crashed git reported "main (clean)"), VersionInfo (×3),
  LocalDeployStatusService (×1), DoneBookendVerifier (×1, shells 2-3 git/blocked-item on startup),
  GitHubIssuesService (×6 gh). LeftSidebar's 4 git sites were already fixed by #2535/#2536 and are
  user-clicked (not part of the startup burst) — left as-is.
  **Verification:** `dotnet build … -c Release` clean (0 warnings, 0 errors). `IsCrashExitCode`
  math verified against the real observed `0x40000015` and `0xC0000142`/`0005`/`013A` (all
  detected) vs git exit 0/1/128/129 (none retried). Did NOT launch/kill Shane's live
  BuildConsole.exe (build-only verification, per the dispatch). Branch verified merged into
