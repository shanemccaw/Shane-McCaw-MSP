### What shipped

**Backend.** `artifacts/api-server/src/lib/free-scan-sow.ts` computes the whole SOW for one
Prospect: fixed structure off the six real `category = 'project'` catalog rows
(`identity-access-hardening` … `drift-baseline-handover` — name, customer-facing
description, fixed fee, `durationWeeks`, `deliverables`, `requiresChangeWindow` all read
from `services`), tenant-specific data off `buildPillarSummary(customerId)` — the same real
computation `/api/portal/pillars` and #1358's results screen read. **No fixture module and
no price written into any `.tsx`.**

The "41 → N" projection is `health-display.ts`'s own formula
(`100 − rawRiskScore/theoreticalMax × 100`) with the cleared findings' real `rankWeight`
subtracted from the raw term — not a second scoring model. A pillar whose evaluation is not
`"scored"` (#517) projects to `null` rather than acquiring a number through arithmetic.

`free-scan-engagement.ts` + `routes/public-free-scan-sow.ts` carry the lifecycle:
read / scope write / sign / payment-intent / payment-confirmed. Identity resolves through the
same two doors #1358 and #1359 already serve (checkout sessionId, or the emailed `fsr_`
return token) — never a caller-supplied customerId, never a JWT (#656). No amount field on
any request body; every cent is re-resolved server-side. Real Stripe PaymentIntent for both
plans, with the same metadata-bound confirm handshake `public-purchase-payment.ts` uses.

**Schema.** New `free_scan_engagements` table, keyed on `customerId` so both doors are one
engagement, with a CHECK that a signed row can never carry a partial signature block.
Deliberately not a row in `assessment_sow_agreements` — `workflow-executor`'s
`create_phased_invoices` resolves that table by `checkout_session_id` and would pick a Free
Scan engagement up as an Assessment phased plan.

**Frontend.** `/scan/review` (`FreeScanReview.tsx`), recreated from the design's `{{ open }}`
block: eight numbered sections, the delivery-timeline Gantt, six phase-breakdown cards, and
the right rail's scope selector, payment-plan choice and e-signature capture (real canvas,
drawn or typed, stored as a PNG data URL). A scope toggle round-trips to the server and
re-renders the whole document. The flow strip moved out of `FreeScan.tsx` into
`FreeScanFlowStrip.tsx` so Results and Review render the same strip; Review is step 4 of 5.

**Reuse correction mid-build.** The add-on section originally hand-rolled monitoring
seat-band and retainer tier resolution. `sow-monitoring-addon.ts` already does exactly that
and already carries the fixes #609, #632 and #4074 made to this same resolution — now
delegated to it, with the stored selection moved to the `{ addonId, tierId }` vocabulary
`checkout_sessions.sowAddonSelections` already uses.
