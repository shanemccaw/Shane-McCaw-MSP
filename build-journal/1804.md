## Log
- 2026-08-30 ⏳ IN FLIGHT — `QueueWatcherService.LaunchItem` redirects claude.exe stdout/stderr into a BuildConsole-owned in-process pipe (`RedirectStandardOutput`/`Error` + `OutputDataReceived`). When the app exits the pipe's read end dies with it; claude/node hits EPIPE on its next write and crashes the whole build. Replacing the pipe with an OS-level durable file redirect (child owns the file handle → survives app close), then tailing that file to keep Build Watch live-streaming when the app stays open. Verification: launch a real build, close the app while running, confirm the process survives; confirm live streaming still works app-open; `dotnet build … -c Release` clean.
