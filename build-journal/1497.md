### What shipped
- **Schema + migration:** `msp_change_requests.executor_run_id` (nullable int + index), added to Drizzle (`lib/db/src/schema/msp.ts`) and `lib/db/migrations/manual/2026-08-29-cr-authorization-gate-1497.sql`. **Run against local Postgres in-session** (column + index confirmed present). Appended to the #1630 release-gate checklist for Replit/staging.
- **The gate (`artifacts/api-server/src/lib/change-control-write-gate.ts`):** a PURE, unit-tested `evaluateChangeRequestAuthorization` (fail-closed: only an approved, unconsumed, non-terminal CR authorizes) plus `claimChangeRequestForWrite` (loads the CR scoped to (mspId, tenantId), folds its #1496 approval ledger, then ATOMICALLY claims it pending_approval/scheduled → in_progress), `bindChangeRequestToRun`, `releaseChangeRequestClaim`, and the reconciliation sweep `settleAuthorizedChangeRequests`.
- **Gate inside the write path (`config-pack-orchestrator.ts`):** `runConfigPackForCustomer` gained `changeRequestAuthorization`. An approved CR now authorizes a write even to a live (non-testbed) tenant; the claim happens BEFORE anything fires and the run is bound to the CR after firing, with a release on any pre-bind failure. Testbed + purchase-authorization paths are unchanged (no lockout — rule 6).
- **Reference writeback:** on completion the authorizing run's CR is closed to `completed` (executed_at from the run's finished_at) by the 60s reconciliation sweep wired in `index.ts`; a failed run releases the CR for retry. Closing the CR is what makes `CR-<id>` available to `monitor-executor`'s drift attribution (it queries `status='completed'`), fixing the "every legitimate change reads as unauthorized drift" bug by construction.
- **execute_write_pack is fail-closed:** the MCP tool now REQUIRES `changeRequestId` for a real execution (planOnly exempt); the admin route accepts it optionally (testbed admin validation preserved) and echoes `authorizingChangeRequestId`. New `ConfigPackError` code `change_request_not_authorized` → 403.
- **Wire contract:** `RunConfigPackResult.authorizingChangeRequestId`, the route 202 body, the MCP `PackRunResponse`, and `WireChangeRequest.executorRunId` (the register now carries the execution link). No UI wired (SCOPE STOP honored — artifacts/portal is a scaffold).
