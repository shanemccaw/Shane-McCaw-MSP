## Changes Made

Commit `9594f7607` — `artifacts/portal/src/components/useCaBaselineLive.ts`:
- Removed `P2_SKU_PART_NUMBERS` (the hardcoded skuPartNumber allowlist).
- Added `ENTRA_P2_SERVICE_PLAN_NAME` (`"AAD_PREMIUM_P2"`) and
  `USABLE_SKU_CAPABILITY_STATUSES` (`Enabled`/`Warning`), mirroring
  `license-gate.ts`'s `getProvisionedServicePlanNamesForTenant`.
- Added `skuProvisionsEntraP2(row)`: true iff the row's `capabilityStatus` is
  usable AND its `servicePlans[]` contains an entry with
  `servicePlanName === "AAD_PREMIUM_P2"` and `provisioningStatus === "Success"`.
- `hasEntraP2` is now `rawSkus.some(skuProvisionsEntraP2)` instead of a
  skuPartNumber membership test.

No backend, schema, or route change was needed — confirmed via a live DB
query (see Verification Results) that the persisted
`license:sku-utilization` item rows already carry the full `servicePlans[]`
array per SKU, because that check's `monitor_checks.select_params` has no
`$select` filter, so `monitor-executor.ts`'s standard Graph path persists the
raw, unfiltered Graph rows.
