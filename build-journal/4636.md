## Changes Made
- `desktop/BuildConsole/Services/QueueWatcherService.cs`
  - New `LiveQueueIdsForSessionThreadSafe(exceptQueueId, sessionId)` — a `_gate`-locked twin of the UI-thread-only `LiveQueueIdsForSession`, because `LaunchItemCore` runs on a thread-pool thread (SafeLaunch's `Task.Run`) where reading `_running` unlocked would tear against the reap/output threads.
  - New `TryDeferDuplicateResumeAsync(item)` — the load-bearing backstop. For a row carrying `resume_session_id` whose session is already live under another row, it releases the row to `queued` (preserving the resume id) via `RequeueForLiveSessionAsync` so the next 30s tick resumes it cleanly once the live process exits; logs once per deferral episode (throttled via `_deferredDuplicateResumeLogged`). Never stops the live process (would kill possibly-active work with no prompt — #4553's rule) and never supersedes the row (would drop a queued Reply message). HTTP-fallback mode (no `_db`) fails the launch instead — still strictly better than spawning a duplicate.
  - `LaunchItemCore` calls it at TWO sites: an early cheap check before worktree provisioning (avoids provisioning a worktree we'd abandon in the common queued-row case), and the authoritative last-moment check immediately before `RedirectedProcessLauncher.Launch` (the only check that can never be stale — it catches a session that went live DURING the 90s+ provisioning window). The late path disposes the pre-built `entry.TailCts` before returning.
- `desktop/BuildConsole/Services/BuildQueuePostgresClient.cs`
  - New `RequeueForLiveSessionAsync(id)` — `UPDATE ... SET status='queued', claimed_at=NULL, build_pid=NULL, build_pid_started_at=NULL WHERE id=@id AND status='running'`, preserving `resume_session_id`. Mirrors `RequeueLimitPausedAsync`'s shape; clears the pid fingerprint so no adoption/phantom-running logic mistakes the released claim for a live process.

Note on logging: BuildConsole (C#/WPF) uses the `ActivityLog.Log("watcher", …)` channel spine, not the TS platform's `logger.child({channel})` taxonomy (which governs `artifacts/*` + `lib/*` only). New log lines use the existing `watcher` channel, consistent with every surrounding line in this file.
