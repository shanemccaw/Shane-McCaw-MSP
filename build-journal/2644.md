# #2644 — Git panel: controls render at ~1/4 the panel's actual width

- **Status:** ✅ DONE 2026-09-03T16:27:48Z
- **Scope:** buildconsole

## Log
- 2026-09-03T16:18:56Z — Session started. Investigating full parent chain from MainWindow.xaml's host of LeftSidebar down through Controls/LeftSidebar.xaml's GitView tab, comparing against the Search tab which does not exhibit the bug.
- 2026-09-03T16:27:48Z — ✅ DONE — Root cause found and fixed. `MainWindow.xaml` hosts `LeftSidebar` in `Grid.Column="1"` of a plain `ColumnDefinition` (no issue there — LeftSidebar itself gets Grid.Stretch and the column's real allotted width). The bug lives entirely inside `Controls/LeftSidebar.xaml`'s own outer `DockPanel` (`LastChildFill="True"`), which hosts `ChatsView`/`ExplorerView`/`SearchView`/`GitView`/`IssuesView`/`SettingsView`/`AutomationView`/`GraphApiView` as sibling `Grid`s toggled via `Visibility` in `LeftSidebar.xaml.cs SwitchView()`. Only `ChatsView` carried an explicit `DockPanel.Dock="Top"`; every other view relied on the attached property's default, which is `Dock.Left`. In a `DockPanel`, a `Left`/`Right`-docked child is measured/arranged at its own desired (auto) width only — it is never stretched to the panel's available width — unless it happens to be the literal *last* child in the `DockPanel.Children` collection, which alone gets `LastChildFill` treatment (and that applies purely by collection position, regardless of `Visibility` — a `Collapsed` last child still occupies the slot and blocks the fill for everyone else). `GraphApiView` is that last XAML child, so it silently absorbed the fill; every other view — including `GitView` — was left auto-width-only, rendering its controls at only their intrinsic content width, i.e. the reported ~1/4-panel-width bug. `SearchView` visually looked closer to full width in Shane's screenshot only because its inner TextBoxes' `MinWidth="140"` plus surrounding chrome happen to sum near the sidebar's default ~260px width at the default (unwidened) split position — it has the identical structural defect, not a genuinely different rendering path.
  - **Fix:** added `DockPanel.Dock="Top"` to `ExplorerView`, `SearchView`, `GitView`, `IssuesView`, `SettingsView`, `AutomationView`, `GraphApiView` in `desktop/BuildConsole/Controls/LeftSidebar.xaml`, matching `ChatsView`'s existing (correct) declaration. Every view now genuinely fills the sidebar's real available width regardless of DockPanel child order or which view is currently visible.
