# #4368 — pre-work plan

## Problem Description

On BuildConsole's Build Queue panel "BUILD SETS" rollup, each build-set summary card
renders the chain title + up-next/running/verifying counts, a `⚠ N needs attention`
badge, an optional send/dispatch button, and an expand chevron all on **one row**. When
the title + counts text is long (e.g. `TenantReset — 0 up next, 0 running, 1 verifying
(#4273)`), the fixed-width auto columns holding the badge/button/chevron get pushed
toward — and past — the card's right edge, making the dispatch icon unreachable/unclickable.

## Root Cause Analysis

`BuildRollupRow` in
[`desktop/BuildConsole/Controls/BuildQueuePanel.xaml.cs`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/desktop/BuildConsole/Controls/BuildQueuePanel.xaml.cs#L4517)
builds `headerGrid` as a single-row `Grid` with 4 columns: `Star` (the title/counts
`summaryRow`), then three `Auto` columns for `sendButton`, the `needsAttentionPill`, and
`chevron` (lines 4542–4546, elements placed at lines 4583–4656). Because all four sit in
the same Grid row, a long `summaryText` (line 4567, `TextWrapping.Wrap`) only has the
Star column's width to wrap into once the three Auto columns have claimed their own
space — and at real-world widths (long build-set / chain names) that squeezes the
right-hand controls to the edge or past it. There is no second row for the
badge/button/chevron to fall to.

## Proposed Changes

Restructure `headerGrid` in `BuildRollupRow`
([BuildQueuePanel.xaml.cs:4542](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/desktop/BuildConsole/Controls/BuildQueuePanel.xaml.cs#L4542))
from one row to two:

- **Row 0** — `summaryRow` (accent dot + title/counts `TextBlock`), spanning the full
  card width so it wraps/ellipses freely with nothing competing for horizontal space.
- **Row 1** — a right-aligned horizontal strip holding, in order, `sendButton`, the
  `needsAttentionPill`, and `chevron` — its own row underneath, never sharing horizontal
  space with the title line, so the dispatch icon is always reachable regardless of
  title length.

This is a layout-only change inside `BuildRollupRow`; no data model, event wiring
(`MouseLeftButtonDown`, `chevron.Click`, `sendButton.Click`, context menu), or expand/
collapse behavior changes — those handlers reference the same element instances, just
repositioned.

## Verification Plan

- `dotnet build` the `desktop/BuildConsole` project to confirm it compiles clean.
- Visual/manual check is the real verification target here (a WPF layout fix); per
  CLAUDE.md, BuildConsole/WPF UI is out of scope for test manifests. Confirm via a
  code-level review of the new Grid row/column assignments that: (1) the title row

  right-aligned, (3) existing click handlers (row body, chevron, send button, context
  menu) still target the correct elements post-refactor.
