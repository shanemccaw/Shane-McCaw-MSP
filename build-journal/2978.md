- 2026-09-07T15:09:02Z ✅ DONE — commit 8aa987a9f (pushed to main, merged-ancestor
  check passed). Added a bounded downward pass to build-resource-model.mjs's
  reachability closure: a reverse BaseType index (resolved qualifiedName -> derived
  qualifiedNames, built once per Graph version over the full declared type universe)
  seeded ONLY from the entityType actually declared on a real addressable config path
  — never from an ancestor reached via the existing upward walk, and never from a
  type reached sideways through a structural property. That restriction is the real
  design decision this issue asked for: the issue's own literal draft algorithm
  ("enqueue every type whose resolved BaseType is a type already in reachable") would
  have walked microsoft.graph.entity — already reachable as the universal ancestor of
  virtually the whole object model — back down through most of the ~11.6k-type
  universe. Restricting downward-eligible roots to genuine collection roots (plus
  their own discovered subtypes, re-seeded so multi-level hierarchies reach a fixed
  point) avoids that. Added a 1000-type sanity-cap circuit breaker as a defensive
  backstop, unused in the real run.

  Live-verified against real fetched Graph v1.0 (3906 declared types) + beta (7745
  declared types) metadata, run against the local DB:
  - v1.0: 2041 -> 2387 reachable types (208 newly via downward closure)
  - beta: 3733 -> 4736 reachable types (536 newly via downward closure)
  - no sanity-cap warnings triggered on either version
  - microsoft.graph.iosWiFiConfiguration is now a real row (base_type =
    microsoft.graph.deviceConfiguration, 11 own declared properties incl. ssid,
    preSharedKey, wiFiSecurityType) — was 0 rows before, per the issue's own evidence
  - 87 beta / 24 v1.0 types now derive from deviceConfiguration, 22/13 from
    mobileApp, 8/4 from deviceEnrollmentConfiguration
  - direct children of microsoft.graph.entity (622 v1.0 / 1128 beta) were ALL already
    reachable via the pre-existing upward walk — none newly pulled in via downward,
    confirming entity itself was never treated as a downward root
