- 2026-09-15T23:13:12Z ✅ DONE — Root cause: `OpenPortalTabAsync` (MainWindow.xaml.cs) only registered the dark-mode invert CSS via `AddScriptToExecuteOnDocumentCreatedAsync`, which fires before a page's own scripts run. A site that re-renders `<head>` during SPA hydration (e.g. the Microsoft sign-in flow inside M365 Admin) could wipe that early-injected style before paint, so dark mode looked off until the manual toggle's `ExecuteScriptAsync` (run against the already-loaded page) reasserted it. Fix: reassert the same injection in the tab's `NavigationCompleted` handler on every completed navigation when `tab.IsDarkMode` is true, matching what the toggle already did correctly. `dotnet build` (Debug + Release) clean, 0 warnings/errors. Live-verified: launched the real built exe with the saved dark-mode preference file set to `true` (the actual default), no toggle interaction — the auto-opened M365 Admin tab's real Microsoft sign-in page rendered with the dark-invert filter applied on the very first paint (screenshot captured, confirmed dark background + light text on what is normally a white/light Microsoft login page, then deleted as scratch). No genuine new findings surfaced — root cause and fix are self-contained to this one method.
