Confirmed vicious cycle. FIX: serve mirror on `HasUsableDataAsync()` alone (drop the closed-backfill gate) + never fire the live ALL walk while `GitHubRateLimitCircuit.IsOpen`.
  - **Part 2 reconciled — largely already fixed by #3359 + literal change is UNSOUND**: `MaybeBackfillClosedIssuesAsync` is already gated to once/24h (`ClosedBackfillInterval`) AND circuit-gated, so it is NOT firing "at the end of every 30-min full sync." The full/incremental sync walks the OPEN set only (mark-closed just flips `state`), so deriving/recording the backfill timestamp "from data already captured" would make `HasClosedBackfillAsync()` report complete over a badly-truncated closed set → permanently wrong burndowns. Part 1 already severs the circular dependency (GetAllIssuesAsync no longer depends on the backfill). DECISION: keep the backfill's once/24h circuit-gated ALL walk as-is (it's the only correct source of historical closed rows); do NOT make the unsound change. Documented.
  - **Part 3 confirmed**: both `BatterUpQueueService.RefreshAsync` and `AiBatterUpQueueService.RefreshAsync` hard-throw on open circuit (#3494). Board read is already mirror-backed; only BUILD-comment resolution needs live GitHub. FIX: remove the throw + add a per-issue in-memory BUILD-comment cache in `ResolveBuildCommentsAsync` (shared by both panels) so a cooldown serves last-known resolutions instead of flapping every item to needs-dispatch.
  - **Part 4 confirmed**: `BatterUpPanel.OnMirrorSyncCompleted` takes the count-only path when `!IsVisible`, so Free Flow never auto-queues overnight while the tab is closed. FIX: when Free Flow is ON, run the real `RefreshAsync` (auto-queue) even when `!IsVisible`; keep count-only when OFF. (AI Batter Up has no auto-queue, so no Part 4 change there.)
  - **Part 5 confirmed**: `RefreshCoreAsync` blanks `_allRows`/`RowsList` on a non-circuit failure even when prior/mirror rows exist. FIX: broaden the "keep last-known rows" preserve to any failure when prior rows exist; apply the same to AiBatterUpPanel for consistency (Part 3 removes its throw too).
  - Supporting: `DoneBookendVerifier.GetSatisfiedAsync` uses local git only (no GitHub API) — safe under an open circuit.
