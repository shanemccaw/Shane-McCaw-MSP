  **Schema** — `lib/db/src/schema/rbac.ts` + `lib/db/migrations/manual/2026-09-09-rbac-foundation-2455.sql`
  (run against the local Postgres 18 `shanemccawmsp` in-session; additive, idempotent,
  nothing altered or dropped). Seven tables: `rbac_capabilities` (shared catalog,
  PRIMARY KEY on the `(system, key)` PAIR), `msp_roles`/`msp_user_roles`/`msp_feature_role_mapping`
  and `customer_roles`/`customer_user_roles`/`customer_feature_role_mapping`. Roles carry
  uuid pks; `msp_id`/`tenant_id` NULL = platform scope, non-null = that org's own — the
  "platform default + customer-customizable" shape Shane described 2026-09-09.

  **Integrity a jsonb column cannot have** (#1696 requirement 2) — three trigger pairs:
  every role id written must exist and be in a scope the row may cite; deleting a role
  strips its id from every mapping in the same transaction; a user may only hold a role
  from their own org's scope or the platform scope. Plus a real composite FK from each
  mapping table onto `rbac_capabilities (system, key)`, so an uncatalogued key cannot be
  stored at all.

  **Evaluation** — `lib/db/src/rbac/evaluate.ts`, pure and shared by both systems.
  DENY WINS, stated explicitly and computed as a set intersection so the answer cannot
  depend on role order, array order or row order. Deny wins across scopes too (an org
  override may grant what the platform left unset, never un-deny a platform deny).
  Default deny; an uncatalogued capability fails closed. `load.ts` is the DB-backed
  context loader, `capabilities.ts` the enumerable catalog, `sync.ts` keeps the table
  equal to it.
