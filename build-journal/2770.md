- 2026-09-03T23:38:32Z — ✅ DONE — Root cause confirmed by code reading, not the issue's literal "call fires before Load() has the PAT" framing (Load() reads synchronously). The real race: `BuildConsoleSettings.Save()` wrote `settings.json` non-atomically (`File.WriteAllText` = truncate-then-write) while `Load()` reads it fresh on every call from many concurrent threads/timers (every `GitHubApiClient` is built from `Load().GitHubPat`; startup fires a burst of board/queue polls, and the first `Load()` itself triggers a Save() for the WebTools/UserAccounts backfill). A `Load()` landing in the write window hit a sharing violation / torn read; its blanket `catch` silently returned a fresh settings object with a blank `GitHubPat` → `GitHubApiClient` built with an empty Bearer token → GitHub 401. A later manual refresh reads the now-stable file → real token → success. Matches "occasional, at startup, clears on manual refresh" exactly.
  - **Fix** (`desktop/BuildConsole/Services/BuildConsoleSettings.cs`): `Save()` now atomic (write sibling `.tmp` + `File.Move(overwrite:true)` — same-volume atomic replace, readers only ever see a complete old/new file). `Load()` now retries a transient IO/parse failure (4 attempts, 25/50/75ms) before giving up, and if the file genuinely exists but still can't be read, logs LOUDLY (`settings.load` channel) instead of silently degrading to blank credentials. A genuinely-absent file (fresh install) is still the legitimate empty-settings case, unlogged.
  - **Diagnostics** (`desktop/BuildConsole/Services/GitHubApiClient.cs`, per issue steps 1 & 4): logs a loud warning at construction when a client is built with an empty PAT (the direct race signature), and a central `LogIfUnauthorized` attributes any 401 to its request path + the token's empty-vs-present-by-length state (never the token value) at the REST GET + both GraphQL POST choke points — so the next 401, if any, is fully diagnosable and distinguishes the empty-token race from a genuinely revoked/invalid PAT.
