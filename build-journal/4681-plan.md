# #4681 — Plan: make the bookend read multi-repo aware

Written before any code change (standing requirement #4307). Permalinks are pinned to
`e8c18d9d2205e315ee5701519c1e465f89c01f27` (origin/main when this plan was written).

## Problem Description

`DoneBookendVerifier` reads every bookend as `git show origin/main:build-journal/{N}.md` from the
MAIN repo checkout only. For a build whose tracking issue is on `shanemccaw/Shane-McCaw-MSP` but whose
code and bookend live in `shanemccaw/M365Architect`, that read always fails, so:

1. **Airplane-icon UI (✈ / ❓ rollup buttons)** — `RefreshVerifyingBookendSatisfactionAsync` and both
   send-time re-checks report "no verified DONE bookend yet — needs attention" for a Verifying M365Architect
   row whose bookend really is DONE and really is on M365Architect `origin/main`.
2. **FalseDoneReconciler Shape A** can never see an M365Architect 🛑 BLOCKED bookend.
3. **(Found while reading, not in the issue body)** the same blind spot corrupts Shape B: a `done` row with
   an open issue and no *visible* DONE bookend is treated as "work never landed" and reset to `canceled`
   (re-dispatchable) — for an M365Architect row whose work genuinely landed, that is a wrongful re-run.
4. **(Also)** the #2225 dispatch gate: `#4651 --blocked-by 4650` can never be released by #4650's DONE
   bookend (it lives in M365Architect), so the chain waits for a human to close #4650.

## User Review Required

**Design decision taken without waiting (not a money/entitlement/customer question, reversible, no schema
change): "tracking repo first, then discover the bookend's home."** Flagging it because it departs from the
issue's literal fix direction:

- The verifier takes an optional *tracking-repo hint* (the row's own `repo_owner/repo_name` — the #3579
  dimension, exactly the #3582 pattern). The bookend is read from that repo's own local checkout first.
- If that repo has no `build-journal/{N}.md`, the other configured repos (Settings > Repos registry, #3581)
  are probed. Exactly one hit → that repo's bookend is used, and the commit-ancestry verification runs in
  *that* repo. More than one hit → ambiguous → fail closed. No hit → "no bookend", as today.
- A local checkout for a registry repo is found by **its `origin` remote actually equalling that
  owner/repo** (never by directory name alone): `<secondary-root>\<owner>__<repo>` (the #3584
  `repo-clone.mjs` convention), then `<sibling of the main checkout>\<repo>-clone`, `\<repo>`, then any
  sibling real clone. No checkout found → that repo is skipped with a log line (fail closed); nothing is
  ever cloned or downloaded by the verifier.

**Alternative Shane may prefer:** persist a `bookend_repo` column on `bt_build_queue`, populated at dispatch
from a new `--repo owner/repo` BUILD-header flag. Cleaner as data, but it needs a dispatch-convention change
and does nothing for the 3,000+ existing rows, so it was not chosen here. It composes with this change
(the hint parameter is the seam it would feed).

**Residual risk (documented, not silent):** the fallback keys on the bare issue number. A false *satisfied*
requires (a) the MSP issue `N` to have no MSP bookend AND (b) a *different* configured repo to hold a DONE
bookend named `N` whose commit is a real ancestor of its main. M365Architect's bookends today are all
`4562+` (MSP tracking numbers), so there is no collision now. Secondary-tracked items keep the #3582
`itemIsPrimaryRepo` gate for exactly this reason — their blockers are never checked number-only.

## Proposed Changes

1. **New** `desktop/BuildConsole/Services/BookendSourceResolver.cs` — maps an `owner/repo` to a
   verified local checkout + base ref (origin-remote-validated, cached, no network), and lists the
   configured repos to probe. Logs on the existing `watcher` channel.
2. [`DoneBookendVerifier.cs`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/e8c18d9d2205e315ee5701519c1e465f89c01f27/desktop/BuildConsole/Services/DoneBookendVerifier.cs)
   — `GetSatisfiedAsync` / `IsSatisfiedAsync` / `GetBlockedAsync` gain an optional `ownerRepo` hint (existing
   call sites compile unchanged and default to the primary repo). A shared `LocateBookendAsync` does the
   tracking-first-then-discover read; `VerifyAsync` runs `cat-file` / `merge-base --is-ancestor` in the
   *bookend's own* repo against *its* base ref. Caches re-keyed `(repo, number)`. Secondary repos get a
   5-minute `origin` refresh cooldown, only when a probe is actually needed (the primary's 45s is unchanged).
3. [`BuildQueuePostgresClient.GetDoneOrVerifyingGithubRowsAsync`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/e8c18d9d2205e315ee5701519c1e465f89c01f27/desktop/BuildConsole/Services/BuildQueuePostgresClient.cs#L1755)
   — also returns the row's `repo_owner/repo_name`.
4. [`FalseDoneReconciler.cs`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/e8c18d9d2205e315ee5701519c1e465f89c01f27/desktop/BuildConsole/Services/FalseDoneReconciler.cs#L92-L132)
   — Shape A (and the Shape B DONE verification, same blind spot) call the verifier per row-repo group with
   that repo as the hint and match results back by row id, so two repos' same-numbered issues can never be
   confused with each other.
5. Correct the now-stale "only ever checks THIS instance's own clone" comments at the #3582 sites
   (`BuildQueuePostgresClient.cs:607-612`, `BatterUpQueueService.cs:618-623`) — behavior there is unchanged
   (the `itemIsPrimaryRepo` gate stays), only the comment is made accurate.
6. Bookend `build-journal/4681.md` DONE with `## Changes Made` / `## Verification Results`.

Out of scope, deliberately unchanged: the claim-path `itemIsPrimaryRepo` gate, the #4679 `blocked`-label
workaround (still correct and cheaper), and any schema.
