## Log
- 2026-08-31 ⏳ IN FLIGHT — Investigated. The domain math (`retainer-hours.ts`
  `computeMonthBucket`) and wire mapper (`admin-retainer.ts` `bucketToWire`, shared by
  `routes/portal-retainer.ts`) already exist and are correct/tested for the rollover
  arithmetic (Git #1285/#1293) — `retainerModel.ts`/`useRetainerLive.ts` (#1588/#1590's
  targets) are moot, deleted wholesale in the portal-v2 retirement. The real gap: there
  is no explicit, honest "over-month" wire signal. The live AdminV2 consumer
  (`RetainerBody.tsx`) infers it as `remainingHours <= 0`, which wrongly flags a
  customer who used EXACTLY their allotment (a normal, non-remarkable state) as
  "over" — conflating "ran out exactly" with "delivered more than retained," the
  opposite of what this issue asks for ("over-month is a normal state, not an error
  state," shown honestly rather than inferred/capped). Adding an explicit
  `overMinutes`/`overHours`/`isOverMonth` field to the domain model + wire contract so
  both the admin console and the eventual customer page can render "10h retained ·
  12h delivered" without recomputing/misinferring the state client-side. No schema
  change — pure computation + wire extension. DB confirmed still 0/0/0 rows
  (`retainer_settings`/`retainer_work_log`/`status_reports`) via direct psql, so no
  live data is affected. This is the last blocker `#1581` (contract pack) is waiting
  on for this module's read surface.
