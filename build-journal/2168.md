- 2026-09-01T22:05:00Z ✅ DONE — Audit + fix shipped. **Audit finding:** the "17:37:57 then silent for hours" premise is a red herring. Line 16336 of today's `activity-2026-09-01.log` is exactly `[17:37:57.153] [system.health] Postgres service check` — but the file continues seamlessly (17:38:09, 17:38:12, … through 19:38) with the ~15s health-check cadence unbroken. Max intra-day gap today is 82s; prior days' larger gaps (500s/893s) are overnight idle, not mid-session death. At the instant the investigator looked, 17:37:57 was simply the last-flushed line of an actively-growing, multi-process-shared per-day file (files are keyed by date only, so every concurrent BuildConsole appends to the same file). **The real defect** is that you cannot tell "ActivityLog died" from "you caught the file mid-flush / one process died while others kept the shared file growing" — the diagnostic system left no trace of its own liveness or health. Code-level failure modes that CAN cause a true silent death and are now fixed: (1) `AppendToFile` swallowed every write exception with zero trace; (2) a single global `_fileGate` wrapped up to 5 synchronous file opens with no stall detection — a wedged op held the lock forever, deadlocking all Log() callers invisibly; (3) the event-dispatch half of `Log()` was unguarded, so a throwing UI subscriber on the synchronous UI-thread path could propagate back and kill the timer that called it; (4) one failing sink skipped all remaining sinks; (5) `activity-latest.log` was 424MB unbounded. Fix: guarded both halves of Log(), per-sink independent writes with bounded retry on sharing violations, `SelfReport()` via fallback channels (temp sentinel + Trace + event) on break/recover, a watchdog Timer that detects a wedged `_fileGate` via `Monitor.TryEnter(timeout)` and emits a low-cadence liveness heartbeat (its absence = logger/process died), bounded `activity-latest.log` with O(1) rotation, and `GetHealth()`/`ActivityLogHealth` for a surface. **Verification:** `dotnet build BuildConsole.csproj -c Debug` succeeded, 0 warnings, 0 errors. Build-only verification per the never-launch-BuildConsole.exe rule. Branch verified ancestor of origin/main (verify-branch-merged.mjs exit 0). Working tree clean.
