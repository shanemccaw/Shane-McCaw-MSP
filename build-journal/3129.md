# #3129 — Critter peekers render distorted/tiny instead of correct shape

## Log
- 2026-09-07T00:00:00Z — Session started. Pulled issue body. Confirmed `web/shanes-life/public/critters.js` is the real file (issue said `public/critters.js`). Investigating `svgEl()` square-box-vs-wide-viewBox hypothesis before fixing.
- 2026-09-07T00:00:00Z — **Confirmed live** (real DOM, Playwright/chromium against a static-served copy of `public/`, not just code inspection): the issue's hypothesis was exactly right. `svgEl()` set the SVG's `width`/`height` **attributes** to the same square `size` (52×52) regardless of `viewBox`. An `<svg>`'s intrinsic aspect ratio is derived from its `width`/`height` attributes independent of `viewBox`, so the browser locked the peeker's intrinsic ratio to 1:1 even though CSS later said `height:52px; width:auto` — `auto` then computed from the wrong (square) intrinsic ratio, squeezing the real 260×64 (~4:1) peeker content into a near-square box. Screenshotted the pre-fix render (tiny distorted smudges, matching Shane's report) then the post-fix render for contrast.
- **Fix** (`web/shanes-life/public/critters.js`, commit `877da4813`): `svgEl()` now accepts separate `width`/`height` params; whichever one a caller omits is derived from the *other* using the real viewBox aspect ratio, so the attribute-derived intrinsic ratio always matches the viewBox it's framing. `attachPeeker()` now passes `height: 52` (not `size: 52`) so `svgEl` derives `width ≈ 211.25` from the real 260:64 viewBox. `critterIcon` (square viewBox, `size` only) and `attachRoomWatermark` (`size: 260`, square viewBox) are unchanged in behavior — `aspect` resolves to `1` for both, so `w`/`h` both equal `size` exactly as before.
- **Live verification**: served `web/shanes-life/public/` statically, built a throwaway harness page (`__verify-3129.html`, deleted before finishing — not committed) importing the real `critters.js`/`critters-sprite.svg` unmodified, rendered all 6 real peekers (`pkw-cat`, `pkw-fox`, `pkw-rac`, `pkw-frog`, `pkw-bear`, `pkw-owl`) via the real `attachPeeker()`, plus `critterIcon` at 36/40/44/104px and `attachRoomWatermark`. Post-fix: all 6 peekers render as recognizable creatures with real ears/paws/faces, matching the design's own reference (`Design/design_handoff_shanes_life/screenshots/02-today-tray.png`) fox-peeker rendering. Confirmed via `getBoundingClientRect()`: rendered box `211.25×52`, exactly matching the real `260:64` viewBox ratio (was `52×52` pre-fix). Icons (36/40/44/104px) and the room watermark render correctly, unaffected by the fix, confirming the scope-item-3 audit — no other `svgEl` caller has this bug pattern (both other callers use the default square viewBox).
