## Engineering decision — own per-customer credit ledger, not `coupons`

Per #3436's instruction and Shane's 2026-09-14 pointer, I read `admin-coupons.ts` and `Coupons.tsx` in full before deciding. The coupon shape does not fit a next-month credit:

- A coupon is a **global code** (`coupons.code` UNIQUE) with no customer binding. A per-customer reward issued as a code could be redeemed by anyone holding it.
- Redemption is keyed on a **checkout session** (`coupon_redemptions.checkout_session_id` NOT NULL UNIQUE). A monthly service invoice comes from a Stripe subscription, not a checkout, so there is nothing to key on.
- **No code path redeems a coupon against any bill.** Nothing writes `coupon_redemptions`, increments `uses_count`, or sets `invoices.coupon_code` (filed as #4059). A coupon row would record the reward but never reach an invoice.

What is reused: the coupon **discount shape and validation** (fixed dollars or percentage 0–100, same rules as admin-coupons.ts), and the **Stripe `duration: "once"` coupon** primitive `copilot-assessment-checkout.ts:135` already uses for a one-time credit.

Built:

- `customer_testimonials.status` / `reviewed_at` / `reviewed_by_user_id`: the approval decision (who, when).
- `customer_billing_credits`: one row per approval, unique per testimonial. Delivered as a `duration: "once"`, `max_redemptions: 1` Stripe coupon attached to the tenant's active `tenant_subscriptions` Stripe subscription. Existing discounts are preserved. Stripe applies it to exactly the next invoice.
- `POST /api/admin/testimonials/:id/approve` (`{discountType, discountValue}`), `POST /api/admin/testimonials/:id/reject`, `POST /api/admin/testimonial-credits/:id/retry`, and `GET /api/admin/testimonials/all` extended with status, reviewer and credit.
- Approval only for `kind='testimonial'` with `permission_to_publish`. Review and credit rows commit together, and Stripe runs after commit. With no active subscription the credit is `awaiting_subscription`; on a Stripe error it is `failed`. Both are retryable.
- `invoice.paid` (msp-billing-webhook.ts) marks the credit `applied` with the real discount amount.
- Admin Panel `crm/Testimonials.tsx`: approve (amount + type) / reject / retry, plus approval and credit status on portal rows.
