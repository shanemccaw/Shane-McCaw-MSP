- **✅ DONE 2026-09-03T14:40:00Z** — Real cause found and fixed.

  **Real cause (evidenced against the live DB, not guessed):** queried `bt_chats` directly via `DATABASE_URL` and found real rows titled literally `1202 Build Console` (conversation ids `e165938a-…` and `577e01d0-…`) — a bare leading issue number, no `#`, no brackets. Every current title-generating code path emits `[#N]` format (`OpenChatTab`, `StartNewEpicChat`, `AssociateChatWithIssueAsync`, auto-name, milestone/issue link). The ONE path that can produce free-form text is the **manual Rename Chat dialog** (`LeftSidebar.xaml.cs:3998`, `newTitle = txtInput.Text?.Trim()`) — so `1202 Build Console` is a hand-typed title. There is no forward code path to "fix" — a user rename can always sidestep the convention — so the correct fix is parser resilience (Shane's option b), which he explicitly called for regardless of source.

  **Fix (`MainWindow.xaml.cs`):**
  1. Extended the anchored `TabTitleIssueNumberRegex` with a third alternative `(\d+)(?=\s|$)` so a bare leading number (`1202 Build Console`) resolves — still anchored to start, still requires a word boundary after the digits, so `v1.1 launch` / `10x ideas` / bare `Build Console` still correctly yield nothing. This also fixes the #1802/#1905 Working-epic board highlight for the same tabs, which couldn't resolve them before either.
  2. Added `ExtractAnyTitleIssueNumber` (regex `(?<![\w.])#?(\d+)(?=\s|$|\])`) as a genuine last-resort wired into `TriggerHandoffAsync` AFTER the anchored parse — catches a real number anywhere in a renamed title (`Handoff for #1202`, `Build Console 1202`). Kept separate from the shared extractor so the loose whole-title scan can't silently loosen the board-highlight resolvers. So "no associated epic" can never fire on a tab that visibly shows an issue number.
