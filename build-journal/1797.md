  ### How each of the issue's constraints is actually met

  - **Absence ≠ unreadability ≠ deletion.** `resolveComparability` gives three states:
    `comparable` (both sides `collected`/`empty` — an absence IS a deletion), `partially_comparable`
    (a side is `partial` — paired objects still diff, unpaired ones are `object_indeterminate`),
    `not_comparable` (a side is `skipped`/`failed`/never targeted — **no change rows at all**).
    Backed by a database CHECK so a non-`comparable` resource can never store a non-zero
    `objects_added`/`objects_removed` even if this file regresses.
  - **Property-level.** Every property row names one path and carries both values.
  - **Stable and ordered.** Total sort over (resource, identity, path, kind, both canonical
    values) → `sequence`. Checked by running the same pair twice, not asserted.
  - **Noise control driven by data.** `config_diff_property_rules`; the engine contains no
    property names. `deriveVolatilityRules` MEASURES volatility from a real same-tenant diff and
    writes rules carrying that measurement. Ignored changes are stored with the rule that
    ignored them, never dropped.
  - **Four entry points, one engine.** `diffDrift` / `diffAgainstBaseline` / `diffTenants` /
    `diffPromotion`. There is no `if (mode === …)` in the comparison; the mode labels the pair
    and is validated (a `drift` across two tenants is rejected).
  - **No apply path.** Nothing in this build writes to a tenant. The differ reads the snapshot
    store and writes the diff store — it cannot reach a tenant at all.

  ### Two real bugs the live run found and this session fixed

  1. **Array members were paired by a fixed name list**, which missed
     `/applications passwordCredentials[].keyId`. Two credentials that had merely swapped
     positions were reported as **8 false property changes**. Member keying is now derived from
     two signals that must agree — the data (present, scalar, unique on BOTH sides) and the name
     shape. Real changes on the pair fell **444 → 340**. A test pins the exact case.
  2. **`useCache: false` violated the unique cache key outright**, so a forced recompute was
     impossible. It now recomputes AND replaces.
