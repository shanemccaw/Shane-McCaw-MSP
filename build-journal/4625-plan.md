# Plan: #4625 — Backend: replace public-chat.ts's AI call with a deterministic form endpoint

**Posted:** 2026-09-18T05:03:14Z

## Problem Description

`POST /api/public-chat` (`artifacts/api-server/src/routes/public-chat.ts`) is the
marketing site's "talk to a human" front door. Every turn makes a real
`anthropic.messages.create()` call (`artifacts/api-server/src/routes/public-chat.ts#L163-168`),
which per #4624 (Feature: Decommission ShaneBot Public's AI chat) is a real, ongoing
AI cost Shane has decided to eliminate for the marketing/public surface entirely —
zero AI cost, no exceptions.

## Root Cause Analysis

Not a bug — a deliberate decommission. The route was built as an open-ended AI chat
(conversation array, guardrail regex backstop for personal-topic questions, persona
system prompt, structured-block content parsing) because it had to defend an
open-ended surface. A flat lead-capture form has no open-ended surface to defend:
there is no free-text channel a visitor could use to ask an off-limits personal
question, so the entire guardrail/persona/parsing apparatus this route depends on
becomes unnecessary for this route specifically (it stays alive for
`support-chat.ts` / ShaneBot Paid, out of scope, untouched).

`publicChatConversationsTable` (`lib/db/src/schema/index.ts#L4906-4940`) already
carries every column a flat form needs (`contactName`, `contactEmail`,
`contactCompany`, `serviceInterest`, `requestSummary`, `needsReview`, `userAgent`) —
today populated by parsing the model's JSON-shaped reply
(`lib/public-chat-guardrail.ts`'s `parseStructuredRequest`); a real form populates
them directly. No schema change needed.

`enqueueEscalationTicket` (`artifacts/api-server/src/lib/zoho-desk.ts#L831-836`) is
transport-agnostic — it takes `contactEmail`/`contactName`/`subject`/`description`/
`notifyEmails`/`pushNotify` and queues a Zoho Desk ticket job regardless of what
produced those fields, so it's reused as-is.

## Proposed Changes

Rewrite `artifacts/api-server/src/routes/public-chat.ts` in place (same route path,
cleanest diff per the issue's own guidance) to:

1. Replace `bodySchema` with a flat form schema: `name` (required, min 1), `email`
   (required, valid email), `company` (optional), `serviceInterest` (optional
   string), `message` (required, min 1). Drop `sessionId`-as-conversation-continuation
   and the `messages[]` array entirely — one submission is one row.
2. Drop the rate limiter's AI-abuse framing (each submission is one write, not an
   AI turn) — keep a lighter form-submission rate limit to guard against spam POSTs,
   still `express-rate-limit`.
3. Remove imports: `@workspace/integrations-anthropic-ai`, `../lib/shanebot-engine.ts`,
   `../lib/chat-content-blocks.ts`, `../lib/public-chat-guardrail.ts`,
   `../lib/shanebot-persona.ts`, `randomUUID` (no client-generated session id),
   `BotConversationMessage` type.
4. On a valid submission: insert directly into `publicChatConversationsTable` with
   `contactName`, `contactEmail`, `contactCompany`, `serviceInterest`,
   `requestSummary` (the message), `needsReview: true` (always), `userAgent`. A
   generated `sessionId` (still `randomUUID()`-backed, since the column is
   `notNull().unique()`) is kept purely as the row's own stable key — not a
   conversation-continuation token accepted from the client.
5. Always call `enqueueEscalationTicket` on a successful submission — `notifyEmails: []`,
   `pushNotify: true`, preserved exactly (never emails a visitor's submission).
6. Respond with a simple `{ success: true }` shape (no `reply`/`content`/
   `suggestedReplies`/model output — there is no model).
7. Rewrite `artifacts/api-server/src/routes/public-chat.test.ts` to cover the new
   contract: valid submission writes the right row + calls `enqueueEscalationTicket`
   with the preserved `notifyEmails: []`/`pushNotify: true` shape; validation
   rejects missing name/email/message; zero references to `anthropic`/guardrail/
   persona in the test's own mocks (proof by omission, same technique the current
   test file already uses for "no mailer/notification imported").

Out of scope, left untouched per #4624's own structured index (separate issues):
`admin-public-chat.ts`/`ChatQueue.tsx` (#TBD3), the marketing-site widget
`PublicChatWidget.tsx`/`PersistentChatBubble.tsx` (#TBD2 — will need to switch to
posting the new flat shape once built), and dead-code removal of
`public-chat-guardrail.ts`/`shanebot-persona.ts`'s public mode/`chat-content-blocks.ts`
(#TBD4, since other consumers may still need them — not verified in this build).
