- 2026-08-29 ✅ DONE — Shipped in `aa2bb3768` (merged into `origin/main`; branch confirmed an ancestor via `verify-branch-merged.mjs`, exit 0).

### What shipped
- **Schema:** `lib/db/src/schema/index.ts:736` → `integer("amount")` (cents). lib/db declarations rebuilt so consumers see `amount: number`.
- **Migration:** `lib/db/migrations/manual/2026-08-29-invoices-amount-to-cents-1610.sql` — adds `amount_cents`, backfills `ROUND(amount*100)`, a `DO` guard raises/rolls back on any row mismatch **before** cutover, then renames old `amount`→`amount_old_numeric` (retained, nullable) and `amount_cents`→`amount`. The old column is **not** dropped here (a later migration drops it).
- **Pay path (highest risk):** `portal-billing.ts` `unit_amount` now passes integer cents straight through (removed the `*100`, which would have charged 100×).
- **Portal display:** `billingWire.ts` converts cents→dollars at render (`Math.round(cents)/100`, matching `receiptWire.ts`); `billing-types.ts` `amount: number`; `BillingSummaryCards`/`InvoiceHistory` divide by 100.
- **Internal revenue math** (admin-finance, admin-overview, msp-financial-aggregator, analytics-forecast, ai-next-best-actions, admin-fulfillment, shanebot-engine, dashboard-resolvers comment) divides cents by 100.
- **Writes** (admin create, seed-portal, portal-checkout-free) store integer cents.
- **admin-panel** is out of the sweep scope (issue confined it to api-server + msp-portal); its wire contract is preserved by converting cents→dollar-string at the api-server boundary (admin-invoices GET/POST + audit metadata, admin-purchases GET x2). GDPR export (portal-privacy) keeps a human dollar string.

- **Typecheck:** all 21 changed files clean on both api-server and msp-portal; remaining errors are pre-existing and unrelated (present in a baseline run, none reference `invoicesTable`).
