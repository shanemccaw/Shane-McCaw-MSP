  **But the text-formatting line itself has a real, independent, currently-latent bug:**
  the old code was
  ```csharp
  var pctLabel = new TextBlock { Text = $"{Math.Round(frac * 100)}%", ... };
  ```
  `Math.Round(double)` rounds to the nearest integer (banker's rounding on exact .5 ties,
  irrelevant here). For ANY `frac` in `[0.995, 1.0)` — e.g. 373/374 = 99.73%, or 199/200 =
  99.5% — `Math.Round(frac * 100)` evaluates to **100**, so the text reads "100%", while the
  fill brush conditional (`frac >= 1.0 ? Rainbow : ...`) correctly stays **Green**, because
  `frac` is genuinely `< 1.0`. That is exactly the class of bug #4410 asked to rule out ("never
  let a rounding/formatting bug jump a real value up to a literal '100%'") — it just isn't
  triggered by #1096's CURRENT real numbers (recomputed below), only by any epic that happens
  to land in that half-percent band.
