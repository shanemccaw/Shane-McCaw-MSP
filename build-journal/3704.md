## Root cause

Not a lookback window. `GitHubIssueMirror.MaybeBackfillClosedIssuesAsync` was a **no-op**: #3359's
one-burst `ListBoardIssuesAsync(All)` walk tripped GitHub's secondary rate limit, so the walk was
removed and the method reduced to calling `RecordClosedBackfillAsync()` — it recorded that a backfill
had happened and fetched nothing. `HasClosedBackfillAsync()` was a hardcoded `Task.FromResult(true)`
on top of that, so the mirror reported itself backfilled while holding almost no closed history.

Real state before the fix (read from BUILD_DATABASE_URL):

| | mirrored | real |
|---|---|---|
| total rows | 1,121 | 3,693 |
| closed rows | 608 (191 with a real `closed_at`) | 3,180 |
| milestone #5 | 674 | 2,080 |
| milestones 4/6/11/12/13/14/16/18 | 0 | 164 |

## What shipped

- `GitHubApiClient.ListClosedIssuesPageAsync(after)` — ONE page of real CLOSED issues plus the cursor
  to resume from. `GetIssueStateCountAsync(state)` — a 1-point `totalCount` probe.
- `MaybeBackfillClosedIssuesAsync` rewritten as a chunked, resumable walk: 8 pages per chunk, 4s
  between pages, cursor persisted after **every** page, so a rate-limit stop / error / restart resumes
  instead of restarting. Also advances on the incremental pass, not just the 30-min full walk.
  Fail-closed: nothing marks complete unless the walk genuinely reached the end.
- Steady state is cheap: once complete, the once/24h re-check is the 1-point count probe vs the
  mirror's own closed row count; the 32-page walk is skipped entirely unless they disagree.
- `ReconcileClosedGraphAsync` — the parent/milestone reconciliation the board fetch does in memory,
  done in SQL across the whole open+closed table. Needed because a closed sub-issue's parent is
  usually an OPEN epic from a different walk, and its effective milestone is its nearest ancestor's
  (#2543). Without it every closed sub-issue lands milestone NULL and never counts toward #5.
- `HasClosedBackfillAsync` now reports the real persisted flag instead of a hardcoded `true`.
- Migration `lib/db/migrations/manual/2026-09-11-bt-issue-mirror-resumable-closed-backfill-3704.sql`
  (six additive columns on `bt_issue_mirror_sync_state`) — run in-session against BUILD_DATABASE_URL;
  recorded on #1630.
