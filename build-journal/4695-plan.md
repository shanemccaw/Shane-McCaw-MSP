# #4695 — Plan + Walkthrough (standing requirement, #4307)

## Investigation findings (real, read from code + local `BuildConsole` DB)
- The only current "get this row out of my view" action is the card context-menu item
  **"✓ Mark Complete (Hide)"** (`BuildQueuePanel.xaml.cs` ~7230). It adds the id to an in-memory
  `_manuallyHiddenQueueIds` set (lost on restart) and calls `MarkCompleteAsync(id, 0)`, which for a row with a
  `github_number` lands it on `verifying` (and the watcher path mirrors board state to GitHub). It is not a real
  local dismiss. Removing that item is #4694's scope, not this issue's.
- **Stop already exists as a distinct action** (`⏹ Stop`, running rows only, ~7336). Its reap path
  (`QueueWatcherService` ~2267-2270) mirrors the resulting Verifying/Crashed state onto the GitHub board — that is
  Stop's existing behaviour and is NOT part of this action.
- `bt_build_queue` already has `archived boolean NOT NULL DEFAULT false` + `archived_at` (Git #3607/#3611, used by
  `FalseDoneReconciler` for canceled rows) and an existing **"Archive"** filter (`i.Archived`). No new status value
  and no schema change are needed: real local statuses today are canceled/done/external/failed/parked/queued/
  running/superseded/verifying.

## Decision
Reuse the existing soft-archive (`archived = TRUE, archived_at = NOW()`); never DELETE (history, `build_dispatch_log`
FK, `superseded_by_id` links stay intact).

New `BuildQueuePostgresClient.DismissFromQueueAsync(id)` — pure local SQL, one UPDATE:
- `running` → refused (0 rows). Shane uses the existing ⏹ Stop first, then dismisses the stopped row. Keeps the
  dismiss path free of any watcher/board side effects.
- `queued` / `parked` / `limit-paused` / `capped` / `external` (would otherwise still launch or sit "active") →
  `status = 'canceled'`, `exit_code = COALESCE(exit_code, -1)`, `completed_at = COALESCE(completed_at, NOW())`, plus
  `archived = TRUE`. (exit -1 = the same "user canceled" sentinel Stop uses, NOT 0, so it is not read as the
  ⏳ WAITING self-block shape.)
- terminal / verifying rows (`done`, `failed`, `verifying`, `canceled`, `superseded`) → status untouched, only
  `archived = TRUE, archived_at = NOW()`.

UI (`BuildQueuePanel`): new card context-menu item **"🗑 Remove from Queue (local only)"** (disabled with a
"Stop it first" header on running rows), requires `_db` (no HTTP fallback — nothing to call there), writes an
ActivityLog line, calls `RefreshAsync()`. Zero GitHub calls: no label/comment/close/board move.

Making "archived" actually mean "out of view" (today only the Canceled filter honours it):
- `ApplyFilter` — every filter except "Archive" excludes `i.Archived`.
- `IsCrashed` — excludes archived (so a dismissed crashed row clears the recovery banner/Queued bucket).
- `ComputeQueueStatusCounts`, `RenderBuildSetRollup`, `ResolveBuildSetEpicsAsync` — skip archived.
- Search still reaches archived rows (explicit query, same as today for #3607 archived canceled rows); they remain
  browsable under the "Archive" filter, so nothing is lost.

Not doing: a "Restore" action (row stays fully intact under the Archive filter; can be a follow-up), touching Mark
Complete (#4694), any GitHub call.
