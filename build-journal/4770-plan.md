# #4770 — Plan: restore page-container padding on five Portal pages

Posted: 2026-09-18T20:05:00Z

## Problem Description

My Architect, Status Reports, Offers, Microsoft Changes and Change Control render flush against the
top and left edges of the portal content area, and (measured live, see below) My Architect and its
siblings are also content-width-shrunk instead of filling the slot. Overview has correct padding.

Live audit against the running portal (localhost:5175, Playwright/msedge, 1440x900, auth + API stubbed
client-side only to reach the shell; measuring the computed padding of the first child of the shell's
content slot):

| Page | padding L / T / R |
|---|---|
| Overview | 26px / 20px / 26px |
| My Architect | 0 / 0 / 0 |
| Status Reports | 0 / 0 / 0 |
| Offers | 0 / 0 / 0 |
| Microsoft Changes | 0 / 8px / 0 (centred by a max-width wrapper, so left is only "flush" once the viewport narrows) |
| Change Control | 0 / 0 / 0 |

## Root Cause Analysis

**There is no shared padding wrapper.** Overview does not get its padding from a component: the shell's
content slot ([PortalShell.tsx:170](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/3066cc9321eb5250472179ca5a8214fd8ca90e1c/artifacts/portal/src/components/shell/PortalShell.tsx#L170)) is a bare, unpadded flex
row (`relative flex min-h-0 flex-1 overflow-y-auto`), and Overview ([index.tsx:194](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/3066cc9321eb5250472179ca5a8214fd8ca90e1c/artifacts/portal/src/pages/index.tsx#L194))
hand-writes `flex min-w-0 flex-1 flex-col gap-4 px-[26px] py-5` on its own root. Thirteen pages repeat that
same literal string (account-security, billing, config-state, customer-diagnostics, customer-team,
data-rights-and-privacy, email-auth-setup, index, invoice-detail, offboarding, pillar, settings, ...).

The five broken pages were written for the *previous* frame, which padded for them
(`<main className="mx-auto w-full max-w-6xl px-6 py-8">`, `components/layout.tsx` before commit 6e7dee651,
"Portal Shell: navigation"). When the real shell replaced that frame the padding moved to "each page owns it"
and these pages kept the old root (`flex flex-col gap-4 pb-14`), so they lost the padding *and* the
`min-w-0 flex-1` that makes a page fill the slot's flex row.

**Why not fix it in the shell:** adding padding to the slot would double-pad Overview and the twelve other pages
that already own theirs. Extracting a shared `PageContainer` and migrating 13+ pages is a much larger change than
this bug and is not what the issue asks for. The dispatch's own fallback applies: the audit shows no shared
wrapper, so each of the five gets the same real values Overview uses.

## Proposed Changes

Replace each page's root className with Overview's values (`min-w-0 flex-1 px-[26px] py-5`), keeping each page's
own testids and structure:

- [my-architect.tsx:95](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/3066cc9321eb5250472179ca5a8214fd8ca90e1c/artifacts/portal/src/pages/my-architect.tsx#L95): `flex flex-col gap-4 pb-14` -> `flex min-w-0 flex-1 flex-col gap-4 px-[26px] py-5`
- [status-reports.tsx:108](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/3066cc9321eb5250472179ca5a8214fd8ca90e1c/artifacts/portal/src/pages/status-reports.tsx#L108): same
- [customer-offers.tsx:112](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/3066cc9321eb5250472179ca5a8214fd8ca90e1c/artifacts/portal/src/pages/customer-offers.tsx#L112): same
- [change-control.tsx:85](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/3066cc9321eb5250472179ca5a8214fd8ca90e1c/artifacts/portal/src/pages/change-control.tsx#L85): same (keeps `data-testid="change-control-page"`)
- [microsoft-changes.tsx:278](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/3066cc9321eb5250472179ca5a8214fd8ca90e1c/artifacts/portal/src/pages/microsoft-changes.tsx#L278): `mx-auto flex max-w-[1080px] flex-col gap-4 py-2` -> `mx-auto flex min-w-0 flex-1 max-w-[1080px] flex-col gap-4 px-[26px] py-5` (keeps its 1080px centred column, which is a design choice)

`pb-14` is dropped: it only compensated for the old frame's bottom inset and would otherwise override Overview's
`py-5` bottom value.

Out of scope, filed separately as a finding (same defect, not named in the issue): Testimonials, Azure Credential,
Risk Register, POA&Ms, Policy Decisions, Ownership, Security Plan, Documents, Remediation Tracking, Scope and SLA
also measure 0px padding.
