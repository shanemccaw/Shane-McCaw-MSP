- 2026-08-30 ✅ DONE — Shipped the resource model as queryable data, not prose.

  **Sources (3 downloads, zero probing).** Graph CSDL `$metadata` v1.0 (3,864 types) and beta
  (7,738 types); Microsoft's own published permissions reference (Kibali schema, 818 permissions
  → 2,502 distinct app-only GET paths) — found mid-build and it is what closed the availability
  gap, since `$metadata` carries no permission information at all; and the Microsoft365DSC
  resource map at commit `f79f2971` (536 resources, MIT, attributed).

  **Model.** 7 tables + 1 view (`lib/db/src/schema/config-state.ts`). **1,539 config resources**,
  **22,565 property definitions** (17,548 excluding DSC connection parameters). Origin: 1,004
  Graph-metadata-only, 481 M365DSC-only, 54 linked with the evidence recorded in `link_basis`.
  Transport: graph 1,277 · powershell 211 · sharepoint-admin 23 · azure-rm 22 · power-platform 6.
  Availability against the testbed's 30 real granted scopes: available_now 594 ·
  needs_additional_scope 505 · unknown 414 · unavailable 22 · needs_license 4.

  Two separate permission columns on purpose: `required_app_permissions` is Microsoft365DSC's
  ALL-OF set, `graph_read_permission_options` is Microsoft's ANY-OF set. Merging them would
  misreport availability both ways. `needs_license` is live-evidence-only — no published source
  states license requirements, so only the sampler may set it.

  **Coverage measurement (the point of item 4).** All 157 `monitor_checks` mapped:
  126 graph-path-exact, 15 ps-cmdlet, 7 graph-root, 5 graph-path-prefix, 1 sp-operation, 1 dns,
  **2 unmatched**. Result: **62 of 1,539 resources (4.0%) covered; 1,477 entirely uncovered**.
  The actionable slice — available_now AND uncovered — is 508, led by device-management 191,
  reporting 143, exchange 93. Four surfaces have literally zero coverage (collaboration 58,
  integration 14, azure 12, power-platform 7).

  **Live verification — read-only, tenant 1 (`mccawsoft2.onmicrosoft.com`, is_testbed).**
  29 resources across 11 surfaces, **21 returned 200, 8 failed**, each recorded with its real
  Graph error code. Safety is structural: GET is the only method the file can emit; bound OData
  Functions only (never Actions); no templated paths; `$top=1`; serialised; refuses a
  non-testbed tenant; stores SHAPE ONLY (property names + JSON types, never values).
  Of the 12 resources that returned a body, observed properties matched the derived model
  exactly for 10 — strong evidence the derivation is correct. 1,119 rows remain honestly
  `derived_not_verified`, 391 `not_attempted` with the reason recorded.

  **Surface + API.** `GET /api/admin/config-resources` (+ `/summary`, `/:id`), all `requireAdmin`,
  all read-only; admin page at Delivery → Monitoring → Config Resource Model
  (`/delivery/config-resources`). No fixture module, no fallback array — empty response renders
  an empty state saying the extraction has not been run.
