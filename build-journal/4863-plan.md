# #4863 plan — Financial Ledger (financial_events + log_financial_event / list_financial_events)

## Problem Description
Money has current-state MCP tools (`get_gate_status`, `list_debts`/`set_debt`) but nothing that records events over time (payments, transfers, notices). Those land as free-text `capture()` blobs. MCP-tools-only; no UI.

## Root Cause Analysis
No table or tool exists for dated financial events. Reference patterns: [set_debt/list_debts in tools.mjs](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/fc96bc114fe4d80e26f79567f2c38841e0b56dc9/web/shanes-life/src/mcp/tools.mjs#L1507-L1560), name-resolution in [log_car_maintenance](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/fc96bc114fe4d80e26f79567f2c38841e0b56dc9/web/shanes-life/src/mcp/tools.mjs#L1858-L1908), debts data layer in [money.mjs](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/fc96bc114fe4d80e26f79567f2c38841e0b56dc9/web/shanes-life/src/core/money.mjs#L1810-L1826).

## User Review Required
- `debts` has no `user_id` (single-user table), so debt resolution is by creditor name against all debts; `financial_events` itself is user-scoped.
- The pre-existing local `shanessurvival` / `shanes_life` databases are stale (no `medication_usage_log`, no `debts.debt_type`), so live verification runs against a disposable scratch database built with the real migration and real core module. Replit/staging migration is a #1630 line, not applied here.
- The app has no `logger`; it audits via `core/audit.mjs` `record()`, which I follow.

## Proposed Changes
1. `web/shanes-life/migrations/075_financial_events.sql` — new table `financial_events` (id uuid, user_id, event_type text, amount_cents integer null, from_account, to_account, source, debt_id uuid null FK debts ON DELETE SET NULL, occurred_on date default today, note text, created_at) + indexes; self-marks nothing extra (this app's runner records the ledger).
2. `web/shanes-life/src/core/financial-events.mjs` (new) — `resolveDebt` (id or name: exact/prefix/substring tiers; ambiguous or unmatched throws asking), `logEvent`, `listEvents` (filters debtId/source/eventType/from/to).
3. `web/shanes-life/src/mcp/tools.mjs` — add `log_financial_event` and `list_financial_events` next to the debt tools.
4. `web/shanes-life/bin/selftest-financial-events.mjs` (new) — real run against a scratch DB.

Non-goal: no backfill of existing captures.

## Verification Plan
Scratch DB with users + debts + the real migration; log payment (linked by name), transfer (unlinked), notice; ambiguous and unmatched debt names error; list filtered by debtId, source, eventType, date range.
