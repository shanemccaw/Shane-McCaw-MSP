  **Real, load-bearing gap found:** `active_directory_ous` (the #1547 attachment
  point) carries no object-membership model at all — confirmed by three independent,
  explicit prior notes across sessions ("no object-to-OU membership model", "policy
  semantics explicitly undefined per Shane, reserved for a future version") and by
  grep (zero references anywhere). Comparing a policy's `targetState` against a real
  tenant requires knowing which real Graph objects the policy's OU refers to.

  Decision taken **in this session, disclosed rather than silently assumed**: resolve
  OU membership by matching the OU's `name` against each candidate tenant's real Graph
  `department` attribute on `/users` (`$filter=department eq '<ouName>'`) — a real,
  documented Entra field, not an invented one. This lets a single standing policy
  (scoped by `mspId`, not `customerId` — #1547 shipped it that way on purpose) apply
  across every customer of that MSP that happens to have a matching department, which
  reads consistently with the design's own "New exec hired, VIP -> policy" framing.
  Flagging this as its own finding for Shane's review since it is a real architectural
  choice, not a forced one — see the finding filed below.

  Building now: `findingSource`/`standingPolicyId` provenance columns on
  `msp_diagnostic_findings` (the literal "not Microsoft's baseline, it's yours" ask),
  pure comparison logic for `mailbox_attribute` (the issue's own worked example — "policy
  says 150MB, mailbox is 500MB"), a real Graph reader (`/users` department filter +
  `/reports/getMailboxUsageDetail` CSV, reusing the existing `parseCsvReport`/
  `graphFetchForTenant` machinery already proven elsewhere in this codebase), and an
  on-demand evaluate route that writes real findings. `group_membership` and
  `service_policy` target kinds get an honest `not_evaluable` verdict (no fabricated
  compliant/non-compliant call) rather than a built-but-fake reader — deferred as their
  own finding, the same honesty pattern #1549 already established for its own gap.
