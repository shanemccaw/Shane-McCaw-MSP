- 2026-08-31 ✅ DONE — Shipped in `566d78b0d` (verified ancestor of `origin/main`). New `UsageAutomationService` (singleton) fed by `ClaudeUsageMeterService.StatusChanged`:
  - **Auto-conservation with hysteresis** — engages `ConservationModeEnabled` when the best-headroom (min-usage) account still crosses `AutoConservationThresholdPercent` (default 85); releases only on a genuine reset — usage ≤ `AutoConservationReleasePercent` (default 50) or the tracked weekly reset moment passing. Engage(85)/release(50) gap + monotonic weekly usage means it cannot flap across a poll boundary.
  - **Headroom-aware routing** — `QueueWatcherService.LaunchItem` (before the account-injection block) calls `ResolveAccountForLaunch`, which re-routes only HEAVY builds (`AccountCapPolicy.ExceedsSonnetHigh`, the single reused predicate) to the more-headroom account, requiring a ≥10pt margin, and respecting an explicit non-default per-build account choice.
  - **Fail closed** — a reading is only actable when State==Ok, has a real percent, and was polled within `StaleAfter` (30m = 3 missed 10m polls). Otherwise: no engage, no route, hold last manual state; the title-bar `Auto` status text states the concrete reason (unavailable/errored/stale/not configured). Routing needs BOTH accounts fresh; conservation needs primary fresh.
  - **Manual wins** — a manual Conservation toggle or Drain arms a 2h `ManualHoldWindow` during which automation won't touch the cap; per-item "Run at Full Model"/Run Now still bypass via existing `isForced`; master `Auto` toggle (default OFF) is the full-manual escape hatch.
  - New settings: `UsageAutomationEnabled` (default false), `AutoConservationThresholdPercent` (85), `AutoConservationReleasePercent` (50). New title-bar `Auto` toggle + status text (green when acting).
