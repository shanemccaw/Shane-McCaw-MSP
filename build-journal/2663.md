- 2026-09-03T16:40:00Z ✅ DONE — Fix shipped in `868010ace` (on `main`; `verify-branch-merged.mjs` confirms ancestor; `git status --porcelain` clean). `dotnet build -c Debug BuildConsole.csproj` succeeds, 0 warnings, 0 errors.

  **Fix #1 — ONE shared resolution path (all four entry points).** Added to `MainWindow.xaml.cs` (right after `TryGetChatUrlForTab`):
  - `ResolveChatIdentity(TabItem? tab, string? cachedConversationId, string? cachedClaudeUrl)` → `(conversationId, claudeUrl)`. Reads the chat's REAL current identity live off its open tab's WebView2 URL (`TryGetChatUrlForTab` + `ClaudeChatUrlRegex`), never a cached `BoardChat.ClaudeUrl`/`PersistedInProgressChat.ClaudeUrl` that went stale after the tab navigated. **Two intents, one path:** when the caller hands the tab directly ("mark what THIS tab really shows"), the live URL wins even if it moved past the cached id (fixes "marks the new chat, opens the old one"); when the tab is only *found* via the cached conversation id (sidebar card / immersive chip act on an already-known persisted chat), the authoritative persisted id is kept and only the URL is refreshed — so an unmark still matches the exact row it removes. Falls back to cached values when no live URL resolves (chat not open, or brand-new chat with no `/chat/<uuid>` URL yet).
  - `FindOpenChatTabByConversationId` (helper), `ToggleChatInProgressResolved` (resolve+toggle wrapper for the simple sites), `GetActiveChatTab` (selected chat tab across all four panes) also added.

  Per call site:
  - **Site 1 — `MainWindow.xaml.cs` `OpenChatTab` tab-header ⚡ bolt** (was `~3288`): now calls `ToggleChatInProgressResolved(boltTab, chat.ConversationId, chat.Title, chat.ClaudeUrl)`. `boltTab` is a captured mutable assigned to the real `TabItem` once it's built below (the closure only runs on click), so the bolt marks the live conversation the tab actually shows. This is the site that most directly caused "marks the new #1202 chat, opens the old one" — it previously stored `chat.ClaudeUrl` from the cached snapshot.

Now resolves live-first through the same `ResolveChatIdentity(tabItem, chat?.ConversationId, chat?.ClaudeUrl)`; its extra gh-label / toast / tab-decoration work is unchanged.
  - **Site 3 — `Controls/LeftSidebar.xaml.cs` chat-card right-click** (was `~3719`): now routes through `(Application.Current.MainWindow as MainWindow).ToggleChatInProgressResolved(null, chat.ConversationId, chat.Title, chat.ClaudeUrl)` (direct-toggle fallback if the main window somehow isn't a `MainWindow`).
