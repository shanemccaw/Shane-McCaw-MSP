- 2026-09-13T00:15:00Z — ✅ DONE — Root cause: otplib's `verifySync` throws (rather than
  returning `{ valid: false }`) on a malformed/undersized secret or non-6-digit token.
  `verify-setup`'s `secret` param is caller-round-tripped from `/totp/setup`, so an
  invalid-format secret + wrong code fell through the unguarded call to an unhandled
  500 instead of the intended 400. Fixed by wrapping `verifySync` in try/catch and
  treating any throw as an invalid code. Commit `6c9b7b8f3`
  (artifacts/api-server/src/routes/mfa.ts). Verified: reproduced the exact throw with
  the manifest's own secret/code pair (`JBSWY3DPEHPK3PXP`/`000000`) via a direct
  otplib call, confirmed the fix resolves it to `{ valid: false }`, and
  `tsc --noEmit` passed clean. Branch confirmed merged into `origin/main` via
  `verify-branch-merged.mjs`; working tree clean.
