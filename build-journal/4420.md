## Findings

**None — both #4416 and #4417 correctly handle the missing-tenant-consent case.**

### #4416 (standalone "Reset RBAC test accounts")
`RbacTestAccountsResetGate.cs` runs the pre-existing `scripts/db/reset-rbac-test-accounts.mjs`
(#4396), which itself already resolves the live mccawsoft2 tenant row by its stable Entra tenant
GUID (`MCCAWSOFT2_ENTRA_TENANT_ID`) and, when none exists, skips every rung whose
`users_role_scope_check` requires `tenant_id NOT NULL` (Free, Customer, RetainerConsented,
MonitoringConsented, PackConsented, customer-admin, billing, cap.team.manage,
cap.changes.approve) with a clear, per-account reason: `"no live mccawsoft2 tenant row right now
(#4318) — not faking one"` (`scripts/db/reset-rbac-test-accounts.mjs:236-238`). It never fabricates
a tenant_id and never hangs.
The gate surfaces this plainly to Shane in both paths:
- Preview (`DescribeSettingsPlan`, `RbacTestAccountsResetGate.cs:283-284`): `skip <email> —
  <reason>` line per skipped account.
- Execute (`ExecuteAsync`, lines 215-220): a "Left untouched in settings.json — their accounts were
  deleted and not recreated this run" section listing every skip + reason.
This is not silent, not a hang, and not fabricated data — it tells Shane exactly which accounts
didn't get created and why, in the same result pane as everything else. No stronger banner is
needed for the standalone command since it operates on individual accounts, not a whole-tenant
gate.

### #4417 ("Clean Dev Database" chain)
`CleanDevDatabaseChainGate.cs` goes further, as its own scope requires (it just wiped the tenant
that step 3 needs): before ever running step 3 for real, it re-runs step 3's own dry run against
the just-reset database and reads `RbacTestAccountsResetGate.PreviewedTenantRowPresent`
(itself parsed from the script's own `[resolve] mccawsoft2 -> …` / `[resolve] mccawsoft2 -> NO
live tenants row right now` lines). If no live tenant row exists post-reset, the chain **stops
before step 3** with an explicit header (`"■ CHAIN STOPPED BEFORE STEP 3 — tenant admin consent
needed. The database WAS reset (step 2 completed)."`, `CleanDevDatabaseChainGate.cs:325`) and a
footer telling Shane to grant consent manually and then run "Reset RBAC test accounts" on its own
— explicitly warning not to re-run the chain (which would delete the freshly-consented tenant row
again). The preview path also states the tenant-consent situation up front via `ConsentNote()`
(lines 176-194), covering all three cases (tenant present under this MSP and about to be deleted
by step 2, tenant present under a different MSP, or no tenant at all).
This exact "stop before step 3, database reset, no accounts recreated" behavior is real, verified
evidence in #4417's own DONE bookend (`build-journal/4417.md`, "Real chain phase" — the mccawsoft2
tenants row genuinely didn't exist post-reset in that session's real run, and the chain genuinely
stopped there rather than proceeding).
