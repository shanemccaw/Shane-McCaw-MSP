## Log
- 2026-09-10T18:15:00Z ⏳ IN FLIGHT — Building the real cross-cutting auth/session gap #3501 documents: no MyArchitect service attaches an Authorization header, holds a token, or has any concept of mspId, so every auth-gated api-server call (LaunchControlActionsService #3460, TelemetryService #3476) 401/403s silently. Investigating the real web Portal/Admin MSP-staff login contract to reuse it.
- 2026-09-10T18:40:00Z ✅ DONE — Shipped a real login/session mechanism reusing the api-server's existing MSP-staff contract (no parallel flow, no browser redirect — confirmed staff login is plain email+password→JWT).

### What shipped (commit bb3c74f34)
- **AuthService / IAuthService** — `POST /api/auth/login` (email+password), headless MFA code step via `POST /api/auth/mfa/verify`, sliding refresh via body-based `POST /api/auth/refresh` (the "native client" path), proactive 3-min refresh timer + `EnsureValidTokenAsync`, silent restore, `SignOutAsync`. Access token (15m) memory-only.
- **SessionStore** — DPAPI-wrapped persistence of the **refresh token only** (never the access token, never plaintext), same discipline as #3461 Credential Vault. `%AppData%/MyArchitect/session.dat`.
- **LoginWindow** — native FluentWindow email/password + MFA UI, shown at startup when silent restore fails, plus a status-bar "Signed in: <email> · Sign out" control.
- **Token fan-out** — on `SessionChanged`, the access token is pushed into every auth-attaching service: LaunchControlActions (#3460), ChangeControl, Telemetry, Assessment, EvidencePost. `AuthToken` added to those interfaces (ILaunchControlActionsService, IChangeControlService, ITelemetryService, IAssessmentService, IEvidencePostClient).
- **Silent-401 fix (#3476)** — TelemetryService **and** AssessmentService (same masking pattern, found in audit) now attach the Bearer token and surface a real 401/403 as "Authentication required — sign in" instead of the generic "Backend Standby / Offline" that hid the auth gap.
- **mspId wiring** — `MainWindow.TryResolveLaunchControlScope` now resolves `mspId` from the real session.

### Verification (real, against the running local api-server)

- Created a synthetic MSPOperator test user (`zz-test-3501@…`, reserved prefix, msp_id=1), then **deleted it + its tokens** — DB left pristine.
