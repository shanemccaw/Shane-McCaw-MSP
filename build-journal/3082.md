**No paywall regression. The redaction logic is intact.** The 500s were a stale test
mock, not a defect in the boundary.

Root cause: commit `749b26513` (#3049, 2026-09-06 17:16) added an **unconditional**
`raciPendingAcceptance` count over `portalOwnershipAssignmentsTable` to
`GET /api/portal/dashboard` and did not extend either test's hand-rolled
`@workspace/db` mock. The handler threw
`[vitest] No "portalOwnershipAssignmentsTable" export is defined on the "@workspace/db" mock`,
its own catch converted that to a 500, and every `expect(res.status).toBe(200)` failed.

Evidence the boundary itself holds — two independent checks:
1. **Not one `expect()` was changed.** The diff deletes exactly two lines, both the
   logger stub. All 15 tests pass on their original assertions, including the
   unpaid-customer redaction proofs for pillar findings/recommendations (#164) and
   for priorityItems (#2500).
2. **Read the code directly.** `portal-customer-engines.ts:510-512` gives an unpaid
   caller only `findingsCount`/`recommendationsCount`, never the text;
   `:566-570` sets `title`/`description` to `null` unless `isPaidTier`. Both key on a
   real `assessmentSowAgreementsTable` query for status in `("paid","free_activated")`.
