## Decision — mechanism
Chose an **explicit `surface: "console" | "portal"` request-body field**, defaulting to
portal when absent/unrecognised.
- **Rejected `req.hostname`/`Referer`:** unreliable behind the Replit proxy; Referer can be
  stripped/spoofed. Not deterministic.
- **Rejected keying off the resolved user's `mspRole`:** the issue itself flags the risk —
  one `users` row can hold an MSP role while still being portal-reachable, so forcing every
  MSP-role user onto the console link regardless of which form they used would be wrong. It
  also couples URL choice to identity rather than origin.
- **Explicit field:** deterministic, respects where the request actually originated, doesn't
  leak account existence (caller-provided, not derived), and is fully backward compatible —
  the customer portal sends nothing and gets the exact pre-#3910 link.

  reuses ONE page for request+reset, keyed on `?token=` — see `ForgotPasswordPage.tsx`);
  everything else → the **byte-identical** existing portal branch

  `getMspPortalBaseUrl()`) because production `PORTAL_BASE_URL` isn't knowable from the worktree
  and the helper's `/crm`-strip + `/portal`-append could alter the suffix — a regression the
  issue explicitly warns against.
