### Remaining runtime behavior (not a code defect — reported honestly)
Later in the evening both accounts began returning **401 Unauthorized** then **429**. The 401 is genuine token expiry: BuildConsole only *reads* the OAuth token and cannot refresh it, so once Claude Code's token expires with nothing re-running `claude` on that account, the poll correctly reports "session expired / sign in." The 429 was the meter re-polling every 10 min into a `Retry-After: 01:00:00` throttle because the prior code logged Retry-After but never honored it — **that is what this session's commit fixes**: per-account back-off now defers the next poll until the Retry-After window, keeping the last good reading on screen.
