# #4771 plan — remove ConsentLedger from customer-facing render

## Problem Description
The card "What these pages deliberately do not do" (internal engineering rationale with §-citations) renders on customer-facing consent pages.

## Root Cause Analysis
`ConsentLedger` in `artifacts/portal/src/components/consent/ConsentOnboardingShell.tsx` was built from the design export's maintainer ledger and is rendered by all five pages sharing the shell: consent-success (3 render paths), consent-declined, consent-tenant-conflict, onboarding-link (2 paths), portal-identity-interstitial. So the leak is not limited to one of the three outcome pages.

## Proposed Changes
- Delete the `ConsentLedger` component and its JSX usages from all five pages, and remove the now-unused `useState` import.
- Preserve the rationale as a code comment (`CONSENT_LEDGER_RATIONALE`) in the shell file, not as markup or a runtime constant.
- Files: `artifacts/portal/src/components/consent/ConsentOnboardingShell.tsx`, and the five pages under `artifacts/portal/src/pages/`.

## Verification Plan
- Typecheck the portal; grep confirms no `ConsentLedger` or card title in `artifacts/portal/src`.
- Render each outcome page in the real app and confirm the card is absent.
