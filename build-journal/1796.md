  **The constraints the issue set, and how each is actually met**
  - *Reuse the execution layer, no second transport* — there is no transport in the collector.
    Graph goes through `graphFetchPaginated` → `graphFetchForTenant`; PowerShell through
    `callPsExecution`. Reaching `beta` was done by **widening** `graphFetchForTenant` to accept
    an absolute Graph URL (host-gated, so a tenant token can never be sent off-origin), not by
    writing a parallel client. That also fixed a latent bug: `graphFetchPaginated` already
    passed `endpoint.startsWith("http")` values through, which were being concatenated onto
    the v1.0 base — no caller had supplied one yet (0 of 157 `monitor_checks` rows).
  - *Registry-driven, never a hardcoded list* — every target is
    `config_snapshot_resource_types WHERE is_collectable`, ordered by `collection_order`. The
    one code-owned table is `PS_CATALOG_BY_CMDLET`, and it exists because #209's security
    boundary requires it; the un-mapped entries are listed with the reason each is excluded.
  - *Partial success is recordable, never an abort* — `runOne` cannot throw; a failure becomes
    a `failed` row and the run continues. The live run proves it: **1,359 status rows for
    1,359 targeted resources**, one per resource, including all 778 failures.
  - *Throttling handled* — `graphFetchPaginated`'s opt-in throttle retry is switched ON
    (6 retries, `Retry-After` honoured, resumes at the same page). **No 429 was observed in
    the live run**, so the backoff is written and wired but is not claimed as live-proven.
  - *Read-only* — every Graph call is a GET; every PowerShell call resolves to a `Get-*`
    catalog entry with no `IsWrite`. Nothing was written to the tenant, and no `monitor_checks`
    row was read, modified or retired.

  **A real bug the live run found and this session fixed.** The first run reported the
  `/deviceManagement` failures as `permission_denied` and `transport_error` — the exact
  "not configured vs not licensed" conflation #1847 exists to prevent. Cause:
  `serviceKeyForGraphPath()` matched on a bare `startsWith("/deviceManagement")`, so the
  absolute beta URLs the collector uses fell straight through and **none** of #1847's Intune
  signatures could match. Fixed in `8ad52c824` by normalising any Graph endpoint form to its
  version-less path. After the fix the same resources resolve to the real verdict, with the
  real entitlement evidence: *"the only Intune-family entitlement is INTUNE_O365
  (ENTERPRISEPACK, PendingActivation) … does not include Intune."*
