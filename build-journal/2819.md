  **Findings filed**
  - **#3089** — "Conditional Access policy creation/deletion is one opaque whole-array drift event with no policy identity" (`bug`, `security`, sub-issue of #1850, milestone v1.1, board status AI Batter Up). Proved live against the real `detectDrift`: `[A,B] → [A,B,C]` and `[A,B] → [B]` both produce exactly `[{op:"replace",path:"/policies"}]`. A created or deleted CA policy therefore has no object identity, so it is the one case this build's per-setting attribution can only match at resource level. Not fixed here because re-keying `buildCaPolicyDriftConfig` by policy id invalidates every existing `ca-policy` baseline and needs its own re-capture step — the exception `drift-check-specs.ts` documents deliberately.
