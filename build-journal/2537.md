## Log
- 2026-09-06T15:14:00Z ⏳ IN FLIGHT — Auditing the worktree sweep's liveness check (scripts/dev-server/worktree-lifecycle.mjs `sweepWorktrees` / cleanup-worktree.mjs --sweep) against the BuildConsole `LaunchItem` provisioning path. Confirmed: the periodic auto-sweep runs `force:false` every 5 min (QueueWatcherService.MaybeSweepWorktrees), and every retention check in `sweepWorktrees` (Check 1 pidAlive, Check 2 grace, Check 3 keepForDebug) requires a tracking `rec`. An `agent/*` worktree with no record — or one whose single stored `creatorPid` is dead while the real session lives under another pid (the stamped `launched.Process.Id` = claude.exe launcher can outlive-differ from the CLAUDE_PID worker) — falls through all three to removal. That is the violated guarantee. Planned fix: make removal require positive evidence of abandonment (filesystem-activity liveness fallback + missing-record protection), gated to non-force so the explicit Clean/force path is unchanged.
- 2026-09-06T15:38:00Z ✅ DONE — Fix shipped in `ec13b9c2d`. Root cause (audit): the sweep's retention of an `agent/*` worktree depended ENTIRELY on a tracking record existing with a live stored `creatorPid`. Two realistic ways that single signal fails while a session is genuinely live: (1) the stamped owner pid is `launched.Process.Id` (claude.exe), which can be a short-lived launcher distinct from the real CLAUDE_PID worker — dead stored pid, live session; (2) the record can be lost/mismatched, after which a recordless `agent/*` worktree falls through Checks 1/2/3 (all `rec`-gated) straight to the removal candidate list — exactly #2537. **Fix:** added `worktreeLastActivityMs()` (best-effort, shallow: working-tree root + immediate entries + the per-worktree git dir's HEAD/index/logs/HEAD/ORIG_HEAD/COMMIT_EDITMSG/FETCH_HEAD) and folded it into the sweep's grace check, dropping the `rec &&` requirement. A live session continuously writes to its worktree, so recent on-disk mtimes retain it regardless of record/pid; a completed/abandoned worktree stops being written to and still ages past the grace and is reclaimed as before. Gated to non-force, so the explicit Clean/force path is unchanged. **Verification:** new `scripts/dev-server/worktree-sweep.selftest.mjs` (6 assertions, all pass) — proves a recordless freshly-active agent/* worktree is RETAINED by the non-force sweep and that an inactive one still expires (no permanent leak). Ran against a throwaway temp repo, dry-run.
