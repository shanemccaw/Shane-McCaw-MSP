# #3388 — Real sort-order bug in msp-diagnostics.ts findings queries

- **Status:** ⏳ IN FLIGHT 2026-09-11T04:05:00Z
- **Scope:** platform

## Log

- 2026-09-11T04:05:00Z — Confirmed the bug per the issue body: `mspDiagnosticFindingsTable.severity`
  is a plain `text` column with no DB enum/CHECK constraint, so
  `.orderBy(mspDiagnosticFindingsTable.severity)` sorted alphabetically (critical, info, ok,
  warning) at all 5 call sites named in the issue. Added a shared `findingSeverityRank` SQL
  `CASE` expression (critical=0, warning=1, info=2, ok=3, else=4) and replaced
  `.orderBy(mspDiagnosticFindingsTable.severity)` with `.orderBy(findingSeverityRank)` at all 5
  sites in `artifacts/api-server/src/routes/msp-diagnostics.ts` (now lines 593, 772, 957, 1161,
  1231 after the helper insertion shifted line numbers from the issue body's original 528/706/
  891/1086/1156).
