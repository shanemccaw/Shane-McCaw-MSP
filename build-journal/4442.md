  - **A11y persistence:** new `visual_test_tracker_a11y_audits` table, same shape as `visual_test_tracker_dom_mutations` (page_id, base_url, page_path, total_violations, violation_summary jsonb holding the full violation list, last_audited_at, created/updated, UNIQUE(base_url,page_path), trailing `simulator_migration_runs` insert). Store: `GetA11yAuditAsync`/`SaveA11yAuditAsync`, mirroring the DOM baseline methods. Also added `...OrThrowAsync` variants, because the existing methods swallow DB errors and return null, and the auto-check can't let a dropped connection look like "never visited" (that would overwrite a real baseline). DOM baselines now also save a structural snapshot into the existing, previously unused `dom_snapshot` column.
  - **Real diff (`Services/DomBaselineDiff.cs`):** drift = live mutations whose signature (type, action, tag, selector with nth-of-type normalized, attribute) isn't already in the baseline, plus stable structural keys (data-testid / non-generated ids) added or removed. Values and timestamps aren't part of the signature, so a ticking clock isn't drift. `DomDriftDiffWindow` now shows exactly this (it used to count every live mutation, and counted childList removals as "Added"). Accept now merges into the baseline instead of replacing it. The composer's Verify button used `DiffDomSnapshotAsync`, which compares against an in-memory snapshot Test Mode never takes, so it always came back empty. It now uses the auto-check's observation for the page, so the window shows the same drift the banner reported.
  - **Orchestration (`Services/PageAutoCheckService.cs`, called from `UpdateTestModeActiveTab()` for watched pages only):** waits for readyState=complete plus a 1.5s settle, then claims the page once per document in the page itself. One load fires several navigation events and only one gets through; a reload or SPA route change runs a fresh check. It observes silently for 3s with its own observer (the existing observer draws outlines and floods the diagnostics UI), confirming the URL at claim and again at collect. If there's no DOM baseline it records one; if there's no a11y audit it runs `RunAccessibilityAuditAsync` and saves it. When a baseline exists it diffs against it, and a non-empty diff re-runs the a11y audit and reports NEW violations since the last audit (per the addendum). An empty diff with both records present is silent: nothing re-runs, no banner. A failed a11y run (no scanner timestamp) is never saved as "0 violations". If the a11y table doesn't exist yet or the DB is unreachable, the banner says so once per app session, naming the migration file; pages aren't treated as unvisited.
  - **Banner (`Controls/PageAutoCheckBanner`):** a new lightweight control in its own row directly under each browser tab's toolbar (the #3984 toolbar), dismissible, with "View drift" to open `DomDriftDiffWindow`. ToastEngine wasn't reused because it's one app-wide host window with no tab scope, and a WPF overlay can't draw over WebView2 (airspace). A stale banner hides when the tab moves to another page or a new check claims the document.
