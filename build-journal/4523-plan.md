# Build plan — #4523

Posted: 2026-09-17T22:10:00Z

## Problem Description

`artifacts/admin-panel/src/components/simulatorConfigPack.ts`'s `templateNodeId`
mirrors the backend's node-id scheme (`config-pack-graph.ts`) so the Simulator UI
can look up a step's live run status in `run.nodeResultMap` by node id. The
admin-panel copy does not sanitize dots in the template id before building the
node id, but the real backend does (Git #1316, added in #4510). For any dotted
`templateId` (90 of 92 real `config_pack_templates` rows locally), the admin-panel
computes `tpl-quickstart-v1.create-break-glass-account` while the run's actual
node id is `tpl-quickstart-v1-create-break-glass-account` — the lookup never
matches, so `deriveStepStatuses` renders every such step `pending` while running
and `not_run` once the run reaches a terminal state, regardless of what the
executor actually did.

## Root Cause Analysis

Two independent copies of the same node-id-construction logic exist because
`artifacts/admin-panel` and `artifacts/api-server` are separate Vite/Node apps
with no shared-component mechanism between them other than `lib/*` workspace
packages (this repo's monorepo convention — CLAUDE.md "Workspace / monorepo").
The backend's real, authoritative version —
[`artifacts/api-server/src/lib/config-pack-graph.ts:139-141`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/artifacts/api-server/src/lib/config-pack-graph.ts#L139-L141):

```ts
export const nodeIdSafe = (raw: string): string => raw.replace(/\./g, "-");
export const templateNodeId = (templateId: string): string => `tpl-${nodeIdSafe(templateId)}`;
```

was updated to sanitize dots when checkKey-only steps were added (Git #1316 /
#4510). The admin-panel mirror at
[`artifacts/admin-panel/src/components/simulatorConfigPack.ts:23`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/artifacts/admin-panel/src/components/simulatorConfigPack.ts#L23)
was never updated to match:

```ts
export const templateNodeId = (templateId: string): string => `tpl-${templateId}`;
```

A third copy already exists and already got this right — the marketing-site
mirror at
[`artifacts/shane-mccaw-consulting/src/hooks/useBuyPackLive.ts:168`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/artifacts/shane-mccaw-consulting/src/hooks/useBuyPackLive.ts#L168):

```ts
const templateNodeId = (templateId: string): string => `tpl-${templateId.replace(/\./g, "-")}`;
```

This confirms the correct normalization (`.replace(/\./g, "-")`, i.e. the same
transform as the backend's `nodeIdSafe`) and that the established pattern for
this cross-app duplication is an inline sanitizing mirror, not a shared import
(these are separate Vite apps; the backend module is server-only and not
reachable from either front-end build).

## User Review Required

None — this is a pure bug fix reusing an existing, already-proven normalization
rule. No product decision, no schema change, no money/entitlement question.

## Proposed Changes

- [`artifacts/admin-panel/src/components/simulatorConfigPack.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/artifacts/admin-panel/src/components/simulatorConfigPack.ts#L21-L23) —
  sanitize dots in `templateNodeId`, matching `nodeIdSafe` from
  `config-pack-graph.ts` and the already-correct `useBuyPackLive.ts` mirror:

  ```ts
  export const templateNodeId = (templateId: string): string =>
    `tpl-${templateId.replace(/\./g, "-")}`;
  ```

- [`artifacts/admin-panel/src/components/simulatorConfigPack.test.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/artifacts/admin-panel/src/components/simulatorConfigPack.test.ts) —
  add a dotted-id test case to `deriveStepStatuses`'s describe block, asserting
  a dotted `templateId` (e.g. `"quickstart-v1.create-break-glass-account"`)
  correctly matches its run node's `ok` result to `"success"` — the exact
  failure mode described in #4523 (dotted id renders `not_run`/`pending`
  without the fix, `success` with it).

No schema, endpoint, or wire-interface change — this is a pure client-side
normalization fix; the field the admin-panel already reads
(`run.nodeResultMap`) already carries sanitized keys from the backend.

## Verification Plan

1. `pnpm --filter admin-panel test simulatorConfigPack` (or the app's real
   vitest invocation) — new dotted-id test passes, existing tests unaffected.
2. Confirm via local Postgres that the fix addresses real data: re-run the
   issue's own query (`select count(*), count(distinct pack_id) from
   config_pack_templates where template_id like '%.%'`) to confirm the blast
   radius is still accurate against current local DB state.
3. Manual trace: for one dotted template id from local data, hand-compute
   `templateNodeId` before/after the fix and confirm it now equals the
   backend's `nodeIdSafe`-derived node id for the same template id.
