## Changes Made

- `lib/db/migrations/manual/2026-09-17-ca-report-only-suffix-rename-4549.sql` —
  data-only migration, run against local Postgres myself (idempotent, verified
  by a second no-op run):
  1. Strips `" (report-only)"` from the 5 suffixed CA create templates'
     `body_template.displayName` (`action.create-ca-legacy-auth-block-policy`,
     `action.create-ca-mfa-all-users-policy`, `action.create-ca-signin-risk-policy`,
     `action.create-ca-user-risk-policy`, `action.create-ca-guest-mfa-policy`).
     State (already the real source of truth) tells an admin whether a policy
     is enforcing; the name no longer encodes it, so it can never disagree
     with the real state again.
  2. `action.set-ca-policy-state`'s `body_template` now PATCHes `displayName`
     alongside `state`; `required_variables` gained `"displayName"`.
  3. Widened each of the 5 templates' #4531 skip-write `selectMatch.displayName`
     from an exact `ieq:` match to an `in:<clean>,<suffixed>` match, so a pack
     re-run still recognizes its own already-created policy under either name.
- `artifacts/api-server/src/lib/ca-enforcement-mode.ts` — new
  `stripCaReportOnlySuffix()` helper.
- `artifacts/api-server/src/lib/ca-policy-promotion.ts` — `promoteCaPolicy`
  now computes `newDisplayName` (suffix stripped from the policy's current
  live `displayName`) and always includes it in `proposedPayload`, so
  promoting an already-existing suffixed policy renames it as part of the
  same write. A name with no suffix comes back unchanged (a harmless no-op
  rename).
- `artifacts/api-server/src/lib/ca-report-only-suffix-rename-4549.test.ts` —
  new test file: `stripCaReportOnlySuffix` unit coverage + migration-content
  assertions read from the real SQL file.
