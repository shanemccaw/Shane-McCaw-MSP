Confirmed live via screenshot of the running BuildConsole.exe (bin\ShanesBuild) that the regression is a light rectangle filling the entire `GlobalQueueStatusText` StatusBarItem cell, not a Foreground color issue (queue-count text itself reads fine in dark). Root cause: `#3864` put the bare `TextBlock` (with `Cursor="Hand"`) directly as the sole child of `StatusBarItem` Grid.Column="2", unlike every other clickable segment (`UsageStatusText`, `ClaudeOnlineStatusText`, `DeployStatusText`) which wrap their content in a `StackPanel`. The bare-child pattern lets the native `StatusBarItem` chrome fill/highlight the whole allotted column instead of sizing to content.
  - Fix: wrapped `GlobalQueueStatusText` in a `StackPanel Orientation="Horizontal" VerticalAlignment="Center"` inside its `StatusBarItem`, matching the exact convention already used successfully by `UsageStatusText`/`ClaudeOnlineStatusText`. No change to the runtime Foreground logic in `MainWindow.xaml.cs` (confirmed those brushes — `TextBrush`/`Subtext0Brush` — are legitimate dark-theme text colors, not the cause).
