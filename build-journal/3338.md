  Fix: merged the two separate protected regions into one `try { ... } catch (Exception ex) { ActivityLog.Log(...); ToastEngine.Error(...); } finally { ... }` wrapping the entire method body (overlay construction through bitmap disposal), so any future exception anywhere in `Capture()` — including the previously-unprotected overlay-construction path — degrades to the same ActivityLog line + friendly toast as the rest of the method's established error-handling discipline, instead of an unhandled crash dialog.
