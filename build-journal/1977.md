The 439-issue dataset is NOT lost: `_milestones` holds all 439 (the blocked-by sweep counts them off it). The bug is in the FOCUS FILTER at render time. Focus Mode was active in-memory on milestone #11 ("A. Core Assessment Product"), which had just reached 100% (33/33 closed) and therefore dropped off the OPEN-only board entirely. The failing refresh logged `[focus-mode] filter applied — Git Board 0/11 milestone(s) shown (11 hidden)` and `RenderIssuesTree ... 0ms wall ... across 1 burst(s)` (empty render) for "439 issue(s)". `IsMilestoneInFocus(11)` matched none of the 11 board milestones → `shownMilestones` empty → blank tree + all four summary counts (Active Milestones/Epics/Pending/Done) zero. **Fix (LeftSidebar.xaml.cs, right after BuildBoardFromGitHub):** when Focus is active (and not immersive) and the just-built tree milestone set contains NO milestone matching focus, auto-release Focus (`Deactivate()`) so the board falls back to showing everything. Guarded on a non-empty `_milestones` so a cold/failed fetch never spuriously clears focus.
