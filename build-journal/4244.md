Found: `ProvisionWorktreeAsync` already re-stamps `creatorPid`/`lastActiveAt` on reuse (Git #1371), but `StampOwnerAsync` (the hand-off from BuildConsole's own pid to the real long-lived build process pid) is fired fire-and-forget (`_ = ...`) right after process spawn — no guarantee it lands before a BuildConsole restart/exit or a concurrent sweep. Implementing: (1) await that hand-off so it's durable before launch is considered complete, and (2) sweep-side defense-in-depth using BuildConsole's own authoritative in-process list of live build worktree paths (`_running`), passed to the sweep as `--protect`, so a live build is retained regardless of registry/pid state.
