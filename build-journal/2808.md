## What was found (REAL live evidence, not static tracing)

1. **`%APPDATA%/BuildConsole/context-meter-highwater.json` does NOT exist on this machine.**
   `ChatContextMeterStore.Merge()` calls `Save()` (which writes that file) on every call, so
   its absence proves **Merge has never persisted a real conversationId**. The
   `ChatDocumentContainer` reader (Band 1) reads ONLY that store, so it can only ever show the
   40k `FixedOverhead` floor + `Messages: —`. **This is why #2781 (register ClaudeWebView) and
   #2802 (drive RefreshContext from the timer) were both real fixes yet both left the symptom
   live — the store they depend on is empty.**
2. All 849 chat URLs the app has stored (`queue-chat-urls.json`) are `https://claude.ai/chat/<uuid>`
   — the JS regex's exact expected shape — yet the live meter reached **174,091 tokens** and a
   real handoff fired on 2026-09-03 (`activity-2026-09-03.log`). Live meter works + store never
   persisted ⇒ **`Merge` is being skipped on an EMPTY conversationId** is the leading hypothesis.
   This genuinely cannot be pinned down further by static tracing — exactly the issue's point.
