## The one real correction to the issue's own instructions

#3107 said to point `DATABASE_URL` at `Database=shanessurvival`, citing
`desktop/ShanesSurvival/README.md`. **That name is wrong, and following it would have defeated
the issue's own verification requirement.** The README's `shanessurvival` is an example line, not
the real configuration. The WPF app's real connection string lives in
`%AppData%\ShanesSurvival\settings.json` and reads `Host=localhost;...;Database=finances`.

Queried live before deciding:

| database | tables | `schema_migrations` | accounts | transactions |
|---|---|---|---|---|
| `finances` | 12 | 13 rows, 001–012 all applied | 25 | 1,251 |
| `shanessurvival` | 5 | **table does not exist** | 0 | 0 |

The issue's stated intent — "the same real local database ShanesSurvival's WPF app already
uses", with "same real data, same real schema for its own 12 tables" — is unambiguous, and only
`finances` satisfies it. Built against `finances`, and filed the stale doc as #3114.

## What shipped

**1. Shared database, migrations 013+.** `DATABASE_URL` → the real database the WPF app uses.
`migrations/001_foundation.sql` → `013_shanes_life_foundation.sql`, and `src/migrate.mjs` now
creates `schema_migrations(filename, applied_at)` — the same shape `MigrationRunner.cs` creates —
so both runners share one ledger while each executes only its own directory. It also fails
closed, naming the database it actually found, if ShanesSurvival's tables are absent, so #3087's
mistake cannot repeat quietly.

**2. Migrations 014–018**, the handoff's *Data model additions* tables:
`dates`/`date_asks`/`date_visits`/`date_photos`/`federal_holidays`,
`pets`/`pet_vaccines`/`pet_care`/`pet_records`, `lists`/`list_items`/`things`/`contacts`,
`wins`/`smoke_log`/`catches`/`vault`/`vault_reveals`/`vehicles`, `nudges`/`nudge_events`/`hooks`.
Real, empty, unwired — each room is its own Feature. `vehicles.loan_bill_id` is a real FK into
ShanesSurvival's `accounts` (`ON DELETE SET NULL`; checked first that nothing in
`desktop/ShanesSurvival/` issues a DELETE, TRUNCATE or DROP against it).

**3. Passkeys replace scrypt.** Deleted `src/auth/passwords.mjs`, the password columns,
`POST /api/auth/login` and both DOM inputs. Added real WebAuthn — `src/auth/webauthn.mjs` +
a hand-written CBOR decoder (`src/auth/cbor.mjs`) and COSE→JWK key import, no new dependency
(bandwidth, Git #1987). Discoverable credentials (`residentKey: "required"`) so sign-in needs no
email field; `userVerification: "required"`; challenges single-use in Postgres. Enrolment is
out-of-band via a single-use 30-minute link with the token in the URL **fragment**. The last
passkey on an account cannot be removed. `sessions.last_verified_at` backs the vault's
fresh-assertion-per-reveal rule. Sign-in screen rebuilt to screen 1's exact copy.

**4. Audit for empty-database assumptions.** Real ones found and fixed: the README's "a real
database of its own, `shanes_life`" section, `.env.example`, `src/migrate.mjs` (now guards), and
`bin/check.mjs` (now re-counts every ShanesSurvival table to prove it moved nothing). No seed or
bootstrap logic existed beyond `ensureCategory`, which is the open-registry mechanism, not
empty-DB seeding. No fixture modules anywhere.

## Real verification

- **Migrations 013–018 applied cleanly** on top of the real 001–012, against `finances`.
- **ShanesSurvival's 12 tables: schema diff empty**, every row count unchanged

  Short by $5,239.69; total shortfall $7,933.70; both GATE-tier bills unchanged. Re-run a second
  time after the full E2E suite: still identical. Tool committed as
  `desktop/ShanesSurvival/scripts/mcp-call.mjs` so the next migration can repeat it.
- **The WPF app cannot be disturbed by 013+**: `MigrationRunner.cs` enumerates only its own
  `migrations` directory — simulated its next run, all 13 of its files report AlreadyApplied and
  none of 013+ is reachable by it. `DatabaseConnectionTester` checks a fixed 5-table allow-list
  (`plaid_items`, `accounts`, `transactions`, `debts`, `survival_snapshots`), so extra tables
  cannot turn it orange. `dotnet build ShanesSurvival.sln -c Release` clean.
- **`npm run check`: 50/50 PASS** against the real shared database, with a real software
  authenticator (real P-256 keys, real ECDSA signatures, real CBOR). Asserts the refusals too —
  replayed challenge, tampered signature, spent enrolment token, removing the only passkey — and
  ends by proving not one ShanesSurvival row moved.

**Honest gap:** the browser half of WebAuthn is not covered — that `app.js` calls
`navigator.credentials` with the right options, and that Face ID genuinely fires. That needs
Shane on a real device. `bin/check.mjs` says so in its own output rather than implying coverage
it does not have. The critter art on the sign-in screen is also not ported (#3117).

**Explicitly not done, per the issue:** no cloud database, no Replit deployment, no data
migration to a hosted instance.
