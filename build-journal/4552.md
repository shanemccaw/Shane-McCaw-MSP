## Changes Made

- `artifacts/api-server/src/lib/ca-policy-impact.ts` — added `SignInCategory`
  (`interactiveUser`/`nonInteractiveUser`/`servicePrincipal`/`managedIdentity`),
  extended `GraphSignInForImpact` with an optional caller-tagged `category` plus
  `servicePrincipalId`/`servicePrincipalName`; `summarizeReportOnlyImpact` now keys
  affected identities by `userId ?? servicePrincipalId` (workload sign-ins carry no
  `userId`) and reports a new `byCategory` breakdown on `ReportOnlyImpactSummary`;
  `ImpactEvent` carries its `category`. All additive — existing tests untouched.
- `artifacts/api-server/src/lib/ca-policy-promotion.ts` — `evaluateCaPolicyImpact`
  now issues four sign-in reads instead of one: the existing v1.0 interactive read
  (unchanged path), plus three new absolute-URL beta reads
  (`https://graph.microsoft.com/beta/auditLogs/signIns?$filter=...signInEventTypes/any(t:t eq '<type>')`)
  for `nonInteractiveUser`, `servicePrincipal`, `managedIdentity` — each with its own
  `MAX_SIGN_IN_PAGES` budget via the new `readSignInsForCategory` helper. `complete`
  is now true only when all four categories finished; a new `readByCategory` field on
  `CaPolicyImpact` reports each category's own pages-read/complete state. Any one
  category's Graph error/consent-revocation/license-gap still fails the whole
  evaluation (no partial count is ever presented as complete). `COVERAGE_NOTE`
  updated to state all four event types are included.
- `artifacts/msp-console/src/api/ca-promotion-api.ts` — widened the frontend
  `CaPolicyImpact`/`ImpactEvent` types to match the new additive wire fields
  (`byCategory`, `readByCategory`, `category`). No UI rendering change needed —
  `LaunchControl.tsx` already renders `summary.wouldBlock`/`wouldInterrupt`/
  `affectedUserCount` directly, so it now reflects the real, undercounted-no-longer
  totals with zero further changes.
- New test: `artifacts/api-server/src/lib/ca-policy-promotion-signin-categories.test.ts`
  — mocks `graphFetchForTenant` and asserts all four category paths are actually
  called (1 relative v1.0 + 3 absolute beta URLs), that a service-principal sign-in
  with no `userId` still counts toward `wouldBlock`/`affectedUserCount`, and that a
  single category's Graph error fails the whole evaluation rather than reporting a
  partial count as complete.
