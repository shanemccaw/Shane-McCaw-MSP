# #4827 — Plan: one shared page container for the Portal, migrate every page to it

Posted: 2026-09-19T04:35:00Z

## Problem Description

Ten Portal pages render flush against the top/left edges of the shell content slot (computed padding 0/0/0, Testimonials 0/8/0), the same defect #4770 fixed on five other pages. Project Detail has the same root class and was never probed.

## Root Cause Analysis

No shared page wrapper exists. The shell content slot ([PortalShell.tsx:170](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/6b25489f3f2b9d2befcfa5b5ab719cebaa592b85/artifacts/portal/src/components/shell/PortalShell.tsx#L170)) is an unpadded flex row, so every page must own `flex min-w-0 flex-1 flex-col gap-4 px-[26px] py-5` (Overview, [index.tsx:194](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/6b25489f3f2b9d2befcfa5b5ab719cebaa592b85/artifacts/portal/src/pages/index.tsx#L194)). Pages that kept the pre-shell root `flex flex-col gap-4 pb-14` lost padding and the `min-w-0 flex-1` fill. #4770 fixed five by pasting the string inline; that is the copy-paste this build removes. Padding lives in the page, not the shell, because settings.tsx and others wrap sub-panels with their own padding and would double-pad.

## Proposed Changes

New `components/shell/PageContainer.tsx`: a `div` that owns `flex min-w-0 flex-1 flex-col gap-4 px-[26px] py-5`, merges caller `className` through `cn` (for `relative`, `mx-auto max-w-[...]`), and forwards all other div props (`data-testid`, `style`, `data-*`).
