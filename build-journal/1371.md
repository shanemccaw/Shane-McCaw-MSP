## Log
- 2026-08-26 ⏳ IN FLIGHT — Audited the existing dev-server worktree architecture
  (`scripts/dev-server/`) and the BuildConsole launch path. Finding: the full
  isolate → commit → coordinated-merge-back → restart → cleanup engine already
  exists and is selftest-verified, but is **opt-in** — no launcher provisions a
  worktree, and `registerWorktree` has zero callers (so the sweep can delete a
  live mid-build worktree). Implementing: (1) auto-provision a worktree per build
  in `QueueWatcherService.LaunchItem`, gated by a settings toggle default-ON;
  (2) merge-back + cleanup on completion in the reap loop; (3) fix the Node
  safety gaps; (4) make it a standing CLAUDE.md convention. Doing this work in an
  isolated worktree off origin/main (dogfooding the fix).
- 2026-08-26 ✅ DONE — Landed automatic, mandatory per-build worktree isolation.
  **Node (`05cba6a0e`):** `provision-worktree.mjs` now registers every worktree it
  creates (the critical gap — unregistered live worktrees could be swept mid-build),
  stamps the owner pid, supports `--json`/`--owner-pid`, is idempotent, and is importable;
  `sweepWorktrees` gained an ownership gate (only tracked or `agent/*` worktrees are ever
  removal candidates — harness/manual/other worktrees left strictly alone); `config.mjs`
  defines the previously-undefined `cleanupsLog`. **BuildConsole (`bbbc67705`):**
  `QueueWatcherService.LaunchItem` is now async and provisions a fresh worktree off
  origin/main (deps junctioned, #1372) for every build unless `--cwd` is set, gated by the
  new `EnforceWorktreeIsolation` setting (default ON), fail-loud on provisioning failure;
  the owner pid is re-stamped to the build process after start; the reaper merges the
  build's commit into the dev-server checkout on success and marks the worktree stale on
  failure; a throttled ownership-gated sweep (tick loop + startup) reclaims orphaned
  agent worktrees. New `WorktreeProvisionService`. **Merge-back (task 3):** confirmed the
  coordinator's merge-back is already fully built + selftest-verified; now auto-invoked
  from BuildConsole and documented as a standing CLAUDE.md convention (`e1c597bae`).
  **Verified:** provision→register→reuse live; `--link` = 29 junctions → shared
  node_modules; sweep ownership gate retains live/harness/detached worktrees and only
  flags orphaned `agent/*`; cleanup unlinks junctions before removal;
  `dotnet build BuildConsole.csproj -c Debug` = 0 errors. **Shane To-Do:** rebuild +
  relaunch BuildConsole for the C# to take effect (the running instance is the old
  binary). Orphan-cleanup task 4: automatic sweep handles dev-server worktrees going
  forward; a few pre-existing *harness* worktrees remain (removing them was gated as a
  destructive action) — clear with `git worktree remove` at will.
