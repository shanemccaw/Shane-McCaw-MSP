# #4417 — Command Center: "Clean Dev Database" chain — plan

(Written after investigation, before the work commit.)

## Real current state (read before wiring)
- Blockers landed on main: #4414 (`Find tenant-scoped tables` row, read-only), #4415 (`DevDatabaseResetGate`,
  typed phrase `reset msp #<id>`), #4416 (`IPaletteConfirmGate` + `PaletteScriptProcess` — the shared
  single-launch, never-retried, UTF-8 node runner — and `RbacTestAccountsResetGate`, phrase `reset rbac #<id>`,
  which also writes/re-reads the TEST_RBAC_* pairs in settings.json).
- The palette's confirm mode (`CommandPaletteWindow`) holds a list of gates, picks the one whose `ConfirmShape`
  matches the input, and only shows a result at the END of `ExecuteAsync` — no live progress today.
  `PaletteCommand.RunWithResult` likewise shows "Running…" then one final string.
- Consent constraint (Shane's comment on #4416/#4417): `reset-rbac-test-accounts.mjs` resolves the mccawsoft2
  `tenants` row live and, when none exists, prints `[resolve] mccawsoft2 -> NO live tenants row right now (see
  #4318)` and skips every tenant-scoped rung. Live DB: that row is `tenants.id=1`, `msp_id=1` = the direct MSP,
  so a real step 2 deletes it — right after a real reset, step 3 will find no consented tenant.
- `reset-dev-database.mjs` takes its backup with `pg_dump` from PATH before changing anything; a missing pg_dump
  fails step 2 with no data change, while step 3 does not need pg_dump — a real, non-faked fail-stop test.

## Plan
1. `Services/CleanDevDatabaseChainGate.cs` (new) implementing `IPaletteConfirmGate` (phrase
   `clean dev db #<live msp id>`). It composes its OWN private `DevDatabaseResetGate` and
   `RbacTestAccountsResetGate` instances (not the palette's standalone ones, so a chain preview never arms
   `reset msp #N` / `reset rbac #N`) and runs step 1 through `PaletteScriptProcess` — no second runner, no second
   confirm mechanism.
   - Preview (the row's Enter): step 1 real (never blocks), step 2 `--dry-run`, step 3 `--dry-run`, each streamed
     to the pane as it finishes. Arms only when both sub-gates armed for the same MSP id. Always states the
     consent assumption and what the chain does about it.
   - Execute: re-check + consume phrase; step 1 (never blocks) → step 2 real via the dev gate's own
     ExecuteAsync — FAIL-STOP on !Ok, step 3 marked "not run" → consent check: a fresh step-3 dry run against the
     now-reset DB; if the script reports no live mccawsoft2 tenants row, STOP before step 3 with the manual
     consent instruction (run "Reset RBAC test accounts" alone afterwards — NOT the chain, which would delete the
     consented tenant again) → otherwise step 3 real via the RBAC gate's own ExecuteAsync.
2. `RbacTestAccountsResetGate`: expose `PreviewedTenantRowPresent` (parsed from the script's own `[resolve]` line).
3. Live progress: `IPaletteProgressGate` (ExecuteAsync with `IProgress<string>`) + `PaletteCommand.RunWithProgress`;
   the window renders the streamed text while running. Existing gates/rows unchanged.
4. `MainWindow.CommandPalette.cs`: "Clean Dev Database" row + gate registered in the window's gate list.
5. `scripts/db/README.md`: document the chain.
6. Verify: `dotnet build`; headless probe (real window key handler + real gates, never launches BuildConsole.exe):
   preview (DB + settings unchanged, standalone gates not armed, progress streamed), wrong/locked phrase,
   fail-stop (pg_dump removed from the child PATH → step 2 fails, step 3 never runs: accounts fingerprint +
   settings unchanged), then the real chain end-to-end.
