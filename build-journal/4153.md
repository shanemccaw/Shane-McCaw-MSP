- 2026-09-15T02:20:00Z ✅ DONE — root cause confirmed: `maybeFireSetRestart` (coordinator.mjs) returned early whenever `set.restart.fired` was true, permanently latching a set closed the moment `expected` was first satisfied (e.g. by a lone agent's bookend-only commit under `expected=1`), even though `runSetMemberCycle` keeps merging every subsequent member event's commit into the server checkout regardless of set completion. Fixed by comparing the current server checkout HEAD to the HEAD recorded at the last fired restart: identical HEAD stays a genuine single-shot no-op (preserves the existing guarantee for a real re-completion with nothing new merged); an advanced HEAD (same-key re-report or a straggler landing a genuinely newer commit) now fires a FOLLOW-UP restart for the delta instead of silently orphaning the merge. `buildset.mjs`'s `markRestartFired` now preserves any prior restart in a new `restartHistory` array before overwriting `restart`.
