  seal/supersession chain, scope filtering (#1563) and the filter footprint (#1565).
  Re-reading #1564's own body: "Settled" says a signed version must record the scope it
  covers as a real, bounded statement ("our identity control posture as of this date"),
  never an unqualified blanket claim; "Consequence" says a scope change produces a new

  Gap found: `SecurityPlanScope.statement` is caller-supplied and optional, and nothing
  synthesizes one when absent — `security-plan-assembly.test.ts` never exercises it. A
  version can currently be sealed (and later signed) via `POST .../versions` with no
  `scope` body at all, landing a `footprint.scope.statement` of `undefined`: exactly the
  unqualified-claim shape #1564's "Settled" section forbids. Building: an always-non-empty
  synthesized statement (verbatim if the caller supplied one, else derived from the
  honest/scoped state and applied dimensions) baked into the footprint at assembly time,
  plus a top-level `scopeStatement` on the wire version so the bounded claim is legible
  without parsing `content`. No schema/migration change — `content` is already jsonb.
