## Regression vs distinct gap (the required determination)
**DISTINCT gap, NOT a regression of #3517/#3521.** #3517/#3521/#3661 all key off `status='canceled'
AND exit_code=0` (a *supervisory* cancel set by the false-done/board reconciler). A build that
self-halts via the agent's OWN blocked self-check (writes a 🛑 BLOCKED bookend + `blocked` label,
wires a `blocked_by` edge, exits 0) lands at **`verifying`** (Git #1469 real-Verifying gate, because
it has a real `github_number`) — it never reaches `canceled+exit0`, so none of #3517/#3521/#3661 can
fire. Their fix is intact; this is a different code path they never covered.

## Root cause (proven — code + live `bt_build_queue`)
1. `MarkCompleteAsync(exit 0, github_number present)` → `verifying`, exit_code 0 (Q1).
2. The claim loop `SelectClaimCandidatesAsync` scans **only** `status='queued'` (`QueuedCandidateSql`),
   so a `verifying` row is never reconsidered for launch (Q2).
3. All three paths that would turn `verifying` → the re-dispatchable `canceled+exit0` state miss a
   `--cwd`/cross-repo build (M365Architect) (Q3):
   - **#3628 immediate reap correction** is gated on a provisioned `worktreePath` — null for a `--cwd`
     build (`workDir = item.Cwd`), so it's skipped.
   - **FalseDoneReconciler Shape A** reads the BLOCKED bookend via `DoneBookendVerifier`, hardcoded to
     the MAIN repo's `origin/main:build-journal/{N}.md`. M365Architect bookends live in that repo
     (confirmed: `build-journal/4650/4651/4652/4641.md` all absent here). Also manual-refresh-only.
   - **#3661 `SweepAutoRequeueWaitingAsync`** only queries `status='canceled' AND exit_code=0`.
   Net: the row is stranded at `verifying`, invisible to every auto-recovery path.
4. Q4: the local `blocked_by_numbers` set can lag real GitHub edges, but #3623 already re-checks live
   edges at claim time and periodically re-syncs the column (for `verifying` + `canceled+exit0` rows);
   what was missing was the *requeue*. The fix adds it and relies on #3623's claim-time live-edge
   re-check as the pre-launch safety net.

## Changes Made
- **`desktop/BuildConsole/Services/BuildQueuePostgresClient.cs`**
  - `GetSelfHaltedBlockedVerifyingRowsAsync()` (new): rows at `status='verifying' AND exit_code=0 AND
    github_number>0 AND archived IS NOT TRUE` declaring at least one blocker.
  - `SweepAutoRequeueWaitingAsync(...)`: new pre-step + optional `blockedLabelIssuesFetcher` test seam.
    The pre-step (`ResetSelfHaltedVerifyingRowsToWaitingAsync`) live-fetches the open `blocked`-label
    set (`GitHubIssuesService.ListOpenByLabelAsync("blocked", 500)` — cross-repo-visible positive
    self-halt evidence), and for each candidate whose issue carries the label resets it to `canceled`
    (exit_code stays 0) via the existing `MarkFalseDoneReconciledAsync`. That funnels it into the exact
    `canceled+exit0` WAITING state the rest of the sweep already requeues once blockers clear (and the
    queue panel already renders as ⏳ WAITING, #3521). Fail-closed: acts only on a POSITIVE label match,
    so a failed/empty label fetch resets nothing. No board write (matches this sweep's status-only
    discipline). Same event-driven triggers (BuildFinished + manual refresh); **no new timer**
    (respects #3774/#3777).
- **`desktop/BuildConsole/Services/WaitingRowAutoRequeueService.cs`**: doc comment updated for the
  widened pre-step scope. No signature/trigger change.
- No migration — reuses existing columns/methods.
