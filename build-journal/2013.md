  Every part of the issue's ask is already built:
  - **Real FK, not a Tag heuristic:** `epic_id` is a genuine DB column/FK, not inferred
    from any in-memory "Tag" object at the persistence layer.
  - **New-chat-creation wiring:** every current "New Chat" entry point (NewChatEpicDialog,
    `MainWindow.xaml.cs` `MenuNewChat_Click`/successor-chat flow, `MainWindow.GitDetailTabs.cs`
    epic "New Chat", `LeftSidebar.xaml.cs` issue/milestone "New Chat" context menu) opens the
    chat via `OpenWebTab(..., associateIssueNumber, associateIssueType, associateDefaultTitle)`,
    which injects `EpicChatAssociationWatcherScript` (`MainWindow.xaml.cs:2150`) to catch the
    real `/chat/<uuid>` the instant claude.ai mints it, then calls
    `AssociateEpicChatAsync`/`AssociateChatWithIssueAsync` → `BuildTrackerApiClient.LinkChatToEpicAsync`
    → `POST /admin/build-tracker/chats/ingest` (`force:true`) →
    `artifacts/api-server/src/routes/admin-build-tracker.ts:569` sets `bt_chats.epic_id`
    server-side. This is real, already-shipped work from Git #828/#781/#922, not something
    this session needed to add.
  - **Panels read the real column, not a Tag heuristic:** the Chats tree
    (`LeftSidebar.GetEpicForChat`, `LeftSidebar.xaml.cs:3803`) and the Git Board's green
    "WORKING" epic badge were unified onto this same resolver by Git #1362/#1363
    (commit `0e6b5c500`, landed 2026-08-26) — `epic_id` is checked FIRST, with
    `IssueGithubNumber`/`AssociatedIssueNumbers` text-based matching used only as a fallback
    when `epic_id` is null. Focus Mode (`FocusModeService.cs:404`) and Universal Search
    (`MainWindow.UniversalSearch.cs:415`) likewise read `chat.EpicId` directly. "Home"
    (`HomeView.xaml.cs`) does not currently render any per-chat epic association at all —
    there's nothing there to migrate; that surface doesn't exist yet (tracked separately
    under #2017's Home Page work).
  - Live data check: `SELECT count(*) total, count(epic_id) has_epic FROM bt_chats` → 33
    total / 7 with `epic_id` set today. Per Shane's 2026-08-30 scope-narrowing comment on
    #2013, **no backfill of the other 26 is in scope** — new chats created going forward
