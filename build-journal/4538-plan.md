# Plan: #4538 — `sharepoint:inactive-sites` still missing `lastModifiedDateTime` after #4524

**Posted:** 2026-09-17T22:10:00Z

## Problem Description

`sharepoint:inactive-sites` fails closed (status `error`, `MissingRequiredFieldError`) even
after #4524 added `select_params = 'id,lastModifiedDateTime'` and `requireField: true` to the
row. Live re-run against tenant 2080 (`c4c814d4-3afe-441e-9145-62461d0a4fd3`,
`mccawsoft2.onmicrosoft.com`) via `run-checks-4481.ts` reproduced it exactly as filed:

```
GET /sites?$select=id,lastModifiedDateTime -> 200, 99 items
"sharepoint:inactive-sites: required field(s) \"lastModifiedDateTime\" absent from all 99
fetched item(s) — the endpoint is not returning them (missing $select?), so the check cannot
be evaluated. Failing closed rather than reporting 0."
```

## Root Cause Analysis (live Graph evidence)

Wrote a one-off scratch script (`graphFetchForTenant`, deleted before this commit — not part of
the deliverable) and fired three real requests against the same tenant to isolate exactly where
the field drops:

| Request | Status | Items | First item's fields |
|---|---|---|---|
| `GET /sites?$select=id,lastModifiedDateTime` | 200 | 99 | `id` only — **`$select` is silently ignored for any field beyond `id`** |
| `GET /sites` (no `$select` at all) | 200 | 99 | `createdDateTime, id, name, webUrl, displayName, isPersonalSite, siteCollection, root` — **`lastModifiedDateTime` is absent from the default projection too** |
| `GET /sites?search=*&$select=id,lastModifiedDateTime` | 200 | **143** | `id, lastModifiedDateTime` — present on **100% of 143 items** |
| `GET /sites/{id}?$select=id,lastModifiedDateTime` (single site) | 200 | 1 | `id, lastModifiedDateTime` — present |

This is not an API-version mismatch (`v1.0` is correct in both cases) and not a `$select`
syntax error (the identical query string works once `search=*` is added). Bare `GET /sites`
(no `$search`/`search=` query) is Graph/SharePoint's **enumeration-by-site-collection** listing
path — it has its own fixed, narrow default projection that does not include
`lastModifiedDateTime` at all, and does not honor `$select` for fields outside that fixed set
(it silently drops back to `id` alone rather than erroring). `GET /sites?search=` is backed by
SharePoint search instead, which is a different code path that both honors `$select` for
arbitrary site properties and finds more real sites in this tenant (143 vs 99 — bare `/sites`
appears to miss sites that the search index has). This matches the issue's own "suggested
direction" #1 exactly (`/sites?search=*` instead of bare `/sites`), confirmed live rather than
assumed.

Ruled out `isPersonalSite` pollution: all 143 `search=*` results have `isPersonalSite: false`
and 0 of 143 are missing `lastModifiedDateTime` — no OneDrive personal-site noise to filter.

No `ConsistencyLevel: eventual` header is needed for `/sites?search=*` (confirmed 200 without
it) — that header is Graph's AAD-advanced-query-on-`/users`/`/groups` mechanism, unrelated to
SharePoint site search.
