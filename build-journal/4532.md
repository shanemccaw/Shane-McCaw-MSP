## Changes Made

**The reused mechanism (answering the dispatch's first question).** A real pause / awaiting-input / resume pattern already exists: a node returns `pauseForApproval`, sets `wf_runs.status = "awaiting_approval"`, writes a dedicated `pending_*` row carrying a redacted payload snapshot, and an operator route records the answer and calls `resumeWorkflowRun`. Used three times before this (`approval_gate` + `/decide`, `generate_script` + `/complete`, the break-glass gate + `/acknowledge`). I followed the `generate_script` shape (a non-boolean answer that changes the resume payload) rather than `pending_approvals`, because that table's `context` would persist the plaintext password and its timeout sweeper auto-fails the run.

- **`lib/db/src/schema/msp.ts` + migration.** New table `break_glass_existing_account_decisions`; new pending-secret status `discarded_unapplied` (plain-text column, no CHECK, so no DDL).
- **`workflow-executor.ts` — the gate.** #4514's `credentialNotApplied` refusal is now a pause. The never-applied secret is parked with `credential_uncertain_at` set — the existing #4041 marker that already makes invite and reveal refuse a row whose credential the tenant may not accept, and that `performBreakGlassAdminOverride` already clears — so no new delivery guard was needed. A decision row carries the same redacted snapshot persisted onto the run; plaintext is in none of it. The reset target is the account id from the create step's own output, not the mapped payload key.
- **`lib/break-glass-existing-account-decision.ts`** (new). Record the decision; notify platform admins and the MSP's operators (best-effort, never fails the pause).
- **`break-glass-verification.ts` — `performExistingAccountDecision`.** Exactly the recorded path runs. *Reset and redeliver* delegates to `performBreakGlassAdminOverride` **unchanged**; the answer is recorded only after the replacement is recorded, so a refused or interrupted reset leaves the decision open. *Resume without delivering* discards the secret (ciphertext blanked, vault copy purged) and records the answer in one transaction, then `resumeWorkflowRun`. The pending-secret row's status is the mutex between the two, so two operators choosing differently cannot both act. Refuses without touching anything if the decision is another customer's, already answered, or the run is no longer `awaiting_approval`. The operator-facing invite refusal now says what the secret is actually waiting on instead of "an override ended without a definite answer".
- **`msp-break-glass.ts`.** `GET /msp/customers/:id/break-glass-decisions` and `POST .../:decisionId/decide`. The decide route requires the customer's answer **and** a reason (no default, no inference), rejects `emails` for the resume path, audits `break_glass.existing_account_decision` including the customer's answer. Separate path segment on purpose (see #4844).
- **MSP console.** "Decision needed" card on the customer's Break-glass page: existing account, both outcomes with their real consequences, required customer's answer and reason, optional invite emails (reset only), an explicit tenant-write warning on reset, and a "Recorded answers" list. Real endpoints only; renders nothing when there are no decisions; no fixture data. Its gating rules are a pure module with tests.

**Live, against the real testbed tenant** (`tenants.id 2080`, mccawsoft2), harness `break-glass-existing-account-decision-4532.live-verify.ts`. Real workflow executor, real Postgres, real Express routers, real Graph. 10/10 passed on two consecutive runs. Evidence from the run:

resume_without_delivery      -> 200 {"ok":true,"decision":"resume_without_delivery","runId":49996}
reset_and_redeliver          -> 200 {"ok":true,"decision":"reset_and_redeliver","newPendingSecretId":65,"reissued":1,"sent":1}
lastPasswordChangeDateTime   -> before 2026-09-19T04:37:53Z, after 2026-09-19T04:39:05Z

- **Pause:** the run reaches `awaiting_approval` instead of `failed`; a `pending` decision row and a marked secret exist; invite refused with the specific 409; the generated password is in none of `wf_runs.payload`, `wf_run_node_outputs`, `wf_run_node_logs`, `wf_node_output_samples`, the decision row, or `notifications`; notifications were created and no real e-mail was sent.
- **Resume without delivering:** **zero** Graph writes (counted); secret `discarded_unapplied` with empty ciphertext; vault copy purged; run went to `completed`; nothing delivered; the tenant account's `lastPasswordChangeDateTime` unchanged.
- **Reset and redeliver:** **exactly one** Graph write; old secret `superseded_by_reset`; new unmarked `pending_delivery` secret on the same gate node and the same account; the replacement is a different password from the run's, held by the store; the old copy purged; override audit row written; run still paused; the tenant's `lastPasswordChangeDateTime` moved forward (the tenant really changed); the replacement can then be invited.
- **Refusals change nothing:** missing/blank answer, missing reason, unknown decision value, `emails` on the resume path, another customer's id → 400/404; a second answer on a decided row → 409 with no second reset.

**Unit + type checks.** 13 new api-server unit tests (mocked DB: both paths, the race, refusals) and 6 new msp-console tests, all passing; 105 tests pass across 9 files in the touched and neighbouring break-glass / config-pack-graph / orchestrator / resolve-then-write / redaction suites. The 2 failing `msp-console` `nav.test.ts` tests are pre-existing (#4848). `tsc` clean for `lib/db` and `msp-console`; `api-server` reports nothing in files I touched.

**What was NOT verified, stated plainly:**
- **The tenant account was the synthetic identity, not a real break-glass account.** Path (a) performs a real password reset; CLAUDE.md restricts destructive per-user writes on this tenant to `zz-test-graphwrite-01@mccawsoft2.onmicrosoft.com`, and pointing it at a real `breakglass-admin` would destroy a real emergency credential. The harness ran twice, so that account's password was reset twice (held nowhere).
- **The vault was stubbed in-process.** The only vault reachable locally is production Key Vault (outside agent reach, #1913); the harness refuses to run if a store is configured. Vault purge is asserted against the stub, not a real Key Vault.
- **The run's create-step output was injected, not produced by a real `quickstart-v1` run.** The harness feeds the exact `skippedExisting` / `unappliedVariables` shape #4514 emits into a real executor run. #4514's own resolve step was verified separately by #4514; I did not re-run the full pack against a tenant that already has a `breakglass-admin` (that would make real, unrelated tenant writes).
- **The console panel has not been rendered in a browser.** It typechecks and its gating logic is unit-tested, and every route it calls is exercised live above, but no Playwright/Puppeteer exists in this repo and rendering needs an isolated API host plus an operator login; I did not attempt it. `msp-console` is also out of scope for test manifests per CLAUDE.md.
- **A crash between discarding the secret and the resume** (path b) would leave the run paused with the decision already recorded. This is the same window the existing acknowledge path has; not closed here.
