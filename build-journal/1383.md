- 2026-08-26 ✅ DONE — Root cause found: commit a001ae5e3's diff is genuine and matches its claim (button + handler both real, correct in source). The button "never appeared" because it set no Foreground/Background, so it inherited the app-wide implicit Button style's dark-theme light TextBrush (#CDD6F4) over the light PeachBrush (#FAB387) banner — ~1.3:1 contrast, text effectively invisible; only a faint thin dark border ghost was drawn. (Stale-binary per #1371 is a compounding factor but not the primary cause — the styling made it invisible even in a fresh build.) Fix: gave BtnCancelPendingUpdate explicit dark-chip styling (Background/BorderBrush=CrustBrush, Foreground=TextBrush) so light text on a dark chip reads clearly on peach. Verified: `dotnet build -c Debug` clean (0 errors); rendered the REAL banner markup + implicit Button template offscreen via RenderTargetBitmap — before shot: "Cancel" invisible; after shot: solid legible dark chip. Note: this is a WPF-render verification, not an in-app live click (BuildConsole's own WPF window isn't reachable via shaneapp://runTest, which drives the product WebView2, not the desktop shell).
