## Log
- 2026-08-31 ⏳ IN FLIGHT — Investigating real launch sites. Confirmed the registered
  `shaneapp://` protocol command (`BuildConsole.exe "%1"`, HKCU) is the single real
  choke point every build/agent-context launch flows through (report-progress.mjs's
  pipe-fallback, and every `shaneapp://executeSql|runTest|executeScan|executeCmdlet`
  trigger documented in AGENT_PROTOCOLS.md). It carries no --dev/--agent flag today.
  `--agent`/`--dev` (Git #1838) already exists and suppresses background services,
  but does NOT suppress the visible/maximized/activated window — and today agent
  mode actively DROPS a pending cold-start protocol URI instead of running it.
- 2026-08-31 ✅ DONE — Shipped in `2e833f91f`:
  1. `setup-shaneapp-protocol.ps1` now registers the shaneapp:// command with a
     trailing literal `--dev` — every future protocol-triggered launch carries it
     automatically, no per-caller changes needed.
  2. `App.OnStartup`: a `--dev` cold start couriering a real shaneapp:// payload
     (`protocolUri != null`) is parked off-screen with `ShowActivated=false`
     (TestRunnerWindow's Git #857 idiom) instead of WPF's default
     CenterScreen/Maximized/activated window. A bare `--agent`/`--dev` launch with
     NO payload is untouched — Git #1838's visible agent-shell stays visible (that
     path exists so an agent can screenshot the UI it's verifying).
  3. `MainWindow`: agent mode was unconditionally dropping a pending cold-start URI
     instead of running it — fixed so a quiet courier cold start actually handles
     its one URI (still never opening the ongoing pipe listener) and exits once done.
  - **Real root cause, live-reproduced**: even with the real primary instance (PID
    15832) genuinely open and idle, `ShaneAppProtocol.TryForwardToRunningInstance`'s
    2s pipe-connect raced and lost once during verification — the launch fell

    fix, that same cold start (my new build, `shaneapp://executeSql` + `--dev`)
    never showed/activated a window (`MainWindowTitle` empty throughout), wrote a
    real `{"ok":true, "statements":[{"Rows":[{"ok":1}]}]}` result envelope, and
    exited cleanly on its own — the primary's PID/window was never touched.
  - `dotnet build desktop/BuildConsole/BuildConsole.csproj -c Release`: clean, 0
