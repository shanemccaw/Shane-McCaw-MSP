## Problem Description

`quickstart-v1.create-break-glass-account` now skips its create when exactly one break-glass account already exists (#4514) and returns that account as the step result. The pack's `break_glass_verification_gate` runs right after it, and the run's generated password was never applied to the tenant. #4514 makes the gate **fail the run** (`credentialNotApplied`) rather than deliver a password that cannot sign in. So a re-run against an already-onboarded tenant stops dead and never finishes.

Shane's decision (comment on #4532): do not pick a path automatically. Pause with a real, visible decision point offering the two outcomes from the issue, let the operator record the customer's actual answer, and execute exactly that path:

- **(a) Reset and redeliver** — reset the existing account's password and deliver a working credential, using the same mechanism as `performBreakGlassAdminOverride` (#4015).
- **(b) Resume past the gate without delivering** — treat the existing credential as already held; the rest of the pack continues; nobody receives a credential from this run.

Not in scope: option 1 (halt) stays available only as "leave the run paused"; see User Review Required.

## Root Cause Analysis

The gate has exactly one response to "the secret was never applied": a hard node failure. There is no pause-for-a-decision branch, so the only two ways forward (a) and (b) are unreachable from inside the run.

## User Review Required

**No new execution-model scope is needed**, so I am proceeding. These are the judgment calls Shane should look at, none of which blocks the build:

1. **New table `break_glass_existing_account_decisions` and a new secret status `discarded_unapplied`.** Additive DDL (new table; `break_glass_pending_secrets.status` is plain text with no CHECK constraint — verified against the local DB — so the new value needs no DDL, only the Drizzle enum). Migration file will be run locally by me and appended to #1630 for release-time; it is **not** a `Shane To-Do`.
2. **The reset in (a) invalidates whatever credential the customer already stored**, silently from their side. The guard is procedural: the decide route refuses without a non-empty `customerAnswer` (the customer's actual answer, as recorded by the operator) and a `reason`, both audited. The UI states the consequence next to the button.
3. **No timeout on the decision.** `checkApprovalTimeouts` only touches `pending_approvals`, so a run paused here waits indefinitely, same as a run paused at the break-glass gate today. A customer may take days to answer; auto-failing would be wrong. There is also no "abandon the run" action: Shane specified two outcomes and `POST /admin/workflows/runs/:id/cancel` only cancels `pending`/`running` runs. Whether a paused run needs a third exit is a real gap; I will file it as a finding rather than widen scope.
4. **Live verification target.** CLAUDE.md restricts destructive per-user Graph writes on `mccawsoft2.onmicrosoft.com` to the reserved `zz-test-*` synthetic identity (Git #2840). Path (a) PATCHes a real password, so both paths are live-verified with a real executor run, real Postgres and real Graph, against `zz-test-graphwrite-01` standing in as "the existing break-glass account". I will not point it at a real `breakglass-admin` account: resetting it would destroy a real emergency credential. The generated-secret vault is the one stubbed piece (the only reachable vault locally is production Key Vault, outside agent reach per #1913), exactly as the existing #4029 harness does. I will say so in the verification results.
5. **Who the "customer" is.** The platform does not ask the customer anything. The operator (MSP operator/admin, or platform admin) relays the question and records the answer. That is what the dispatch specifies.

## Proposed Changes

### 1. Schema + migration
- `lib/db/src/schema/msp.ts`: add `breakGlassExistingAccountDecisionsTable` next to [`breakGlassPendingSecretsTable`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/0dee36dca0aba26715d69cf5b412d43c55fc8c4e/lib/db/src/schema/msp.ts#L4641-L4702). Columns: `id`, `runId` (FK `wf_runs`, cascade), `gateNodeId`, `customerId`, `pendingSecretId` (FK), `existingAccountId`, `existingAccountUpn`, `skippedNodeId`, `status` (`pending | reset_and_redeliver | resume_without_delivery`), `customerAnswer`, `reason`, `decidedByUserId`, `decidedAt`, `resultPendingSecretId`, `context` (redacted payload snapshot for resume), `createdAt`. Add `discarded_unapplied` to the pending-secret status enum.
- `lib/db/migrations/manual/4532-break-glass-existing-account-decisions.sql` — `CREATE TABLE IF NOT EXISTS`, ends with the `simulator_migration_runs` self-mark. Run against local `DATABASE_URL`; one line appended to #1630.

### 2. Gate: pause instead of refuse (`workflow-executor.ts` L8115-L8141)
When `findUnappliedSecretSource` hits, instead of `nodeError`:
- Insert the pending-secret row exactly as the normal path does, **but with `credentialUncertainAt = now()`**. That existing #4041 column is a semantically exact fit: invite and reveal already refuse while it is set ("the credential this row holds may not be accepted by the tenant"), so the never-applied password can never be delivered, and `performBreakGlassAdminOverride` already clears it when it records a replacement. No new delivery guard is needed.
- Insert a decision row (`pending`) carrying the redacted payload snapshot; set `wf_runs.status = "awaiting_approval"` with the redacted payload (same `redactForPersistence` treatment as the normal gate); notify MSP operators; log; return `pauseForApproval: true`. The plaintext never enters the decision row, node output or run payload.

### 3. Decision routes (`routes/msp-break-glass.ts`, next to the existing operator routes)
Paths use a separate `break-glass-decisions` segment (see finding note under Verification).
- `GET /msp/customers/:customerId/break-glass-decisions` — the decisions for one customer, real rows only.
- `POST /msp/customers/:customerId/break-glass-decisions/:decisionId/decide` — body `{ decision, customerAnswer, reason, emails? }`, `requireCapability("ladder.msp-operator")` + `assertCustomerAccess`, both "not found" and "not yours" a bare 404, audit log `break_glass.existing_account_decision`.
  - **(a) `reset_and_redeliver`:** call `performBreakGlassAdminOverride(ctx, pendingSecretId, actor, reason, emails)` unchanged. It claims the row, holds a replacement in the store, PATCHes the tenant account, records a new unmarked `pending_delivery` row on the same `gateNodeId`, purges the unapplied copy. The run stays paused at the gate and delivers through the existing verify-and-acknowledge flow. The decision row records `resultPendingSecretId`.
  - **(b) `resume_without_delivery`:** atomically move the pending secret `pending_delivery -> discarded_unapplied` with `encryptedValue = ""`, purge the vault copy (same helper the acknowledge path uses), record the decision, then `resumeWorkflowRun(runId, gateNodeId, snapshot, note)` via `setImmediate`. Nothing is delivered.
  - The pending-secret row's status is the mutex between the two paths (override's claim vs the conditional discard), so two operators choosing different paths cannot both act.

### 4. MSP console UI (`artifacts/msp-console/src/api/break-glass-api.ts`, `pages/break-glass/BreakGlassPage.tsx`)
A "Decision needed" panel at the top of the customer's Break-glass page for each `pending` decision: the existing account (UPN + object id, from the decision row), the two outcomes with their real consequences, required "Customer's answer" and "Reason" fields, optional invite emails for (a). Decided rows show the recorded answer, who, when. No fixture rows; empty state only when the query returns none. Existing status union gains `discarded_unapplied`.

### 5. Tests
Update the #4514 gate tests that assert the refusal; add unit tests for the pause, both decide paths, the mutex, and the plaintext-never-persisted invariant. A test manifest is **not** required: the change is in `api-server`/`msp-console`, outside the manifest scope in CLAUDE.md (`artifacts/portal/` and `artifacts/shane-mccaw-consulting/` only).
