## The distinction, confirmed before anything was wired

The issue's explicit warning was checked against the real resolver and the real table before a
line was written. `canonical_resource_id` asserts IDENTITY and legitimately shares coverage
credit through `effective_check_coverage_count`. Containment asserts membership in a polymorphic
collection, and sharing credit there would count 42 distinct Intune objects as one — #2821's own
bug inverted. So:

- `contained_in_resource_id` is a separate column with a separate resolver.
- Nothing in `resolve-containment-edges.mjs` reads or writes `effective_check_coverage_count`.
- `coverageStateFor()` does not take the edge as a parameter, and its doc now says why not.
- Proven in the DB after the real run: `82 contained rows, 0 of them with effective coverage > 0,
  0 rows carrying both a canonical and a containment edge`.
- Pinned by a test that asserts the edge object's key set contains no coverage field at all.

## What shipped

**Migration** `lib/db/migrations/manual/2026-09-06-config-resource-containment-edges-2940.sql`
— additive, run against the local `DATABASE_URL` in-session (`BEGIN … COMMIT`, all statements OK).
Adds `contained_in_resource_id` (self-FK, ON DELETE SET NULL), `containment_kind`,
`containment_basis`, `containment_matched_on`, `containment_gap_reason`, two indexes, column
comments, and the self-marking `simulator_migration_runs` insert.

**Resolver** `scripts/config-state/resolve-containment-edges.mjs` — imports #2821's own exported
path-tree/walk/name-gate primitives rather than reimplementing them, and keeps the parent
collection those rules resolve *before* the name gate rejects it. Three evidence tiers:

1. `dsc-literal-collection-uri` — the DSC module's `.psm1` GETs a modelled collection path
   literally, and #2821's name gate found surplus words. Direct evidence. **21 edges.**
2. `dsc-cmdlet-collection-walk` — the SDK-cmdlet path walk lands on a modelled collection.
   Inferential, so gated on the parent's Graph entity type being declared **`Abstract`** in
   `$metadata` — Microsoft's own statement that every member is a derived subtype. **61 edges.**
3. `graph-navigation-child` — a *kind* refinement, not a parent source: when the bare DSC name
   matches a navigation property (or its target type) on the parent's entity type, the row is
   `nested-child` rather than `collection-member`. **1 edge** (`AADCrossTenantIdentitySyncPolicy
   Partner` → `crossTenantAccessPolicyConfigurationPartner.identitySynchronization`) — exactly the
   containment-not-specialisation case the issue body called out.

The abstractness gate is what does the real work. `microsoft.graph.user` and `microsoft.graph.group`
are concrete, so the 28 resources invoking `Get-MgUser` and 184 invoking `Get-MgGroup` for
principal/assignment lookups get no edge — the false-link class #2821's own comments document.
`deviceConfiguration`, `mobileApp` and `deviceEnrollmentConfiguration` are abstract, so the real
members do. **122 residue rows are labelled with why no edge was asserted, not silently dropped.**

Also note the deliberate asymmetry with #2821: canonical resolution rejects a target claimed by
several rows (the shared-collection signature). Here that same signature is the *confirming*
evidence, so there is no uniqueness gate — copying one in would reject exactly the rows this
exists to serve. Pinned by a test.

**Pipeline** — `build-resource-model.mjs` runs the containment pass right after canonical
resolution, before check mapping.

**API** `artifacts/api-server/src/routes/admin-config-resources.ts` — `resourcesContained` and
`resourcesUncoveredUnderCoveredParent` (+ the member/child split) on the summary, counted
*alongside* the coverage buckets and never inside them; the five containment fields on every list
row; `containedIn` / `containedMembers` on the detail payload, each member carrying its OWN
coverage state (not rolled up, unlike `duplicates`); and a `?containment=` filter kept as a
separate query parameter so it composes with `?coverage=uncovered` instead of competing with it.

**Surface** `artifacts/admin-panel/src/pages/ConfigResourceModel.tsx` — an "Inside a collection"
stat tile (label deliberately lacks the word "excluded" that the Duplicates tile carries), a
Containment filter, a sky "in collection" / "nested child" badge rendered *after* the orange
"uncovered" badge, and a "Lives inside" detail section.

## Findings filed (all parented under #1128, labelled `bug`, board status "AI Batter Up")

- **#2977** — `graph_entity_types.base_type` stores the raw EDM alias (`graph.entity`) while
  `qualified_name` is resolved, so only 20 of 2,363 rows can join. The resolved value is computed
  ten lines earlier and thrown away.
- **#2978** — the entity-type closure walks up to `BaseType` and sideways through properties but
  never down to derived types, so no polymorphic collection's real subtypes are modelled at all.
  This is why #2940 had to gate on `is_abstract` rather than naming each row's exact `@odata.type`;
  once #2977 + #2978 land, an `odata-derived-type` tier can sit above the cmdlet-walk tier.
- **#2979** — no workspace package has its dependencies linked; `tsc` and `vitest` both cannot
  run. Second half of that finding: `store-doctor.mjs` reports CLEAN, because it validates the
  links it finds and never asserts that required links are present.
