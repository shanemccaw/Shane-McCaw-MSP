# #4546 — Plan

Posted: 2026-09-17T19:48:00Z

## Problem Description

`artifacts/api-server/src/lib/config-pack-dry-run.test.ts`'s test
`"#4513: on a P1 tenant, refuses quickstart-v1 because its CA replacement is
report-only (live seeded rows)"` fails on `main`:

```
AssertionError: expected 'license_required' to be 'security_defaults_replacement_not_enforcing'
```

The test's `vi.mock("./graph.ts", ...)` is meant to intercept every real Graph
call the dry-run pipeline makes, including the tenant's `/subscribedSkus` read
performed by `license-gate.ts`'s `getProvisionedServicePlanNamesForTenant`. For
this one test, that read reaches the REAL `graphFetchForTenant` → real
`getAccessTokenForTenant`, which fails with a real Microsoft Entra token error
(`AADSTS90002: Tenant '<guid>' not found` locally, or `MT_APP_CLIENT_ID /
MT_APP_CLIENT_SECRET not configured` per #4551 in an env with no MT app
credentials at all). The read then fails closed as `license_required`,
masking the `security_defaults_replacement_not_enforcing` refusal the test
means to exercise.

## Root Cause Analysis

`graph.ts` exports `graphFetchForTenant` (and `ConsentRevokedError` /
`LicenseGapError`), and it is imported by name, independently, from **three**
different modules inside this test's own call graph:

- [`config-pack-dry-run.ts:24`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/4e244549245eb8ffbeb818b2066a2050d1921dcd/artifacts/api-server/src/lib/config-pack-dry-run.ts#L24)
- [`config-pack-orchestrator.ts:33`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/4e244549245eb8ffbeb818b2066a2050d1921dcd/artifacts/api-server/src/lib/config-pack-orchestrator.ts#L33)
- [`license-gate.ts:34`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/4e244549245eb8ffbeb818b2066a2050d1921dcd/artifacts/api-server/src/lib/license-gate.ts#L34)

The test's original mock factory was **async**, spreading `importOriginal()`'s
awaited real exports before overriding `graphFetchForTenant`:

```ts
vi.mock("./graph.ts", async (importOriginal) => ({
  ...(await importOriginal<Record<string, unknown>>()),
  graphFetchForTenant: (...args: unknown[]) => mockGraphFetchForTenant(...args),
}));
```

Reproduced directly (see Verification Plan below, and the scratch harness used
to isolate it — not part of this diff): when the SAME named export
(`graphFetchForTenant`) is imported by **multiple separate modules** from a
module mocked via an **async** `vi.mock` factory, only some of those
importers' bindings resolve to the mocked function — at least one binds to
the module's REAL, un-mocked export instead, because that importer's static
`import` resolves before the awaited `importOriginal()` promise inside the
factory settles. In this suite specifically, `config-pack-dry-run.ts`'s own
`graphFetchForTenant` calls (used for the dry-run's `currentState` reads)
consistently bind to the mock, while `license-gate.ts`'s call — reached one
layer deeper, via `config-pack-orchestrator.ts` →
`tenant-write-preconditions.ts` → `license-gate.ts` — binds to the real
export.

This explains why the bug was invisible for 6 of the 7 tests in the file:
every OTHER test's expected refusal for a tenant that genuinely lacks the
required SKU is `license_required` — exactly the same code the real,
failing-closed SKU read also produces. Only #4513's case, which mocks a
tenant that DOES hold the license (so the real behavior should move past the
license check to the Security Defaults rule), exposes the divergence.

#4551 is confirmed to be the same defect, hit independently in an env with no
`MT_APP_CLIENT_ID`/`MT_APP_CLIENT_SECRET` configured at all (surfacing as
`"MT_APP_CLIENT_ID / MT_APP_CLIENT_SECRET not configured"` instead of a live
`AADSTS90002`, but the same real-fetch-reaches-license-gate root cause).

## User Review Required

None — this is a test-file-only fix with no product code change and no
product decision involved.

## Proposed Changes

[`config-pack-dry-run.test.ts`](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/4e244549245eb8ffbeb818b2066a2050d1921dcd/artifacts/api-server/src/lib/config-pack-dry-run.test.ts#L19-L23) —
replace the async `importOriginal()`-spreading factory with a **synchronous**
`vi.mock("./graph.ts", () => ({...}))` factory that returns the mock
`graphFetchForTenant` plus two real-shaped stand-in classes for
`ConsentRevokedError` / `LicenseGapError` (defined inside `vi.hoisted()` so
they're available at hoist time). The mocked `graphFetchForTenant` in this
suite never throws either error, so the stand-ins only need to satisfy
`license-gate.ts`'s `instanceof` checks (always false), not replicate real
throw behavior. A synchronous factory removes the await/race entirely: all
three importers resolve the identical mocked module object.

No other file changes — the defect is fully contained to this test's own
mock setup.
