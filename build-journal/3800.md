  **Design decision:** embedded the lookup in the template via a new
  `baseline_action_templates.resolve_steps` column rather than a standalone graph node,
  because an ADMX definitionValues write ALWAYS needs its definitionId resolved on EVERY
  execution path (config pack, execute_action, Launch Control, admin testing). A graph
  node would only work inside the pack graph and leave the template broken when executed
  directly. `config-pack-graph.ts` needs no structural change — the resolve is intrinsic
  to `execute_baseline_template` execution, and the container-id → next-write chaining KFM
  needs already exists via `parameter_mapping`.
