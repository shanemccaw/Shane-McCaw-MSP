  - **A real correctness bug found and fixed mid-build.** Cmdlet selection was `cmdlets.find(first mapped)`,
    but M365DSC lists `read_cmdlets` in call order, not importance — so `m365dsc:EXOHostedContentFilterRule`
    resolved to `Get-HostedContentFilterPolicy` and snapshot row 8 had duly stored 2 *policies* under a
    resource type named "…Rule". Latent with 5 keys mapped; would have become 7 wrong resources at 81.
    Replaced with `selectReadCmdlet()` — prefer the mapped cmdlet whose noun is a suffix of the resource's
    own DSC name, longest first, falling back to the registry's first mapped cmdlet for resources that
    genuinely read a differently-named object (`EXODnssecForVerifiedDomain` really is read via
    `Get-AcceptedDomain`). 7 new unit tests using verbatim real `read_cmdlets` arrays; suite 20/20 green.
    Not filed as a finding since it was fixed in this build.
