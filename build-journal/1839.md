  **Step 1 — pid storage.** New migration adds `bt_build_queue.build_pid` (integer) + `build_pid_started_at` (timestamptz). `QueueItem` (`BuildTrackerApiClient.cs`) + `MapRow`/all 13 MapRow SELECTs (`BuildQueuePostgresClient.cs`) carry them at ordinals 19/20. Stamped at launch next to the worktree owner-pid stamp via new `StampBuildPidAsync`, using `GetProcessTimes` creation time off the launched handle. Cleared to NULL on completion in `MarkCompleteAsync` (covers done/failed/verifying/orphaned) and `MarkLimitPausedAsync`. Direct-DB only (adoption is a local-DB mechanism; HTTP-fallback can't adopt).

  **Step 2 — liveness check.** `RecoverOrphanedRunningItemsAsync` (+ its #822 doc comment, corrected) now, per `running` row: no pid → orphan -2 as before; pid → `OpenProcess(SYNCHRONIZE | PROCESS_QUERY_LIMITED_INFORMATION)` (new `BuildProcessHandle.TryOpenExisting`); null/already-exited → orphan -2; creation time mismatch (> 1s) → pid reused → close handle, orphan -2; match → adopt, leave row `running`. The #943 multi-instance guard is untouched (adoption only when this is the sole console).

  **Step 3 — adopt.** `AdoptRunningItem` rebuilds a `RunningEntry` off the opened `SafeProcessHandle`, pointing at the existing `queue-{id}.log.raw`/`.err` + the #802 `logPath` (truncated so replay rebuilds the summary cleanly), re-arms `StartRawTailers(entry, id, adopt:true)` and registers it in `_running`, so the reap loop completes it normally (real exit code, session_id, completion write, `BuildFinished` → post-build deploy pipeline). Worktree name/path reconstructed deterministically (`ComposeWorktreeName` + `C:\wt\<name>`, guarded by `Directory.Exists`) so merge-back/stale-marking still run on adopted completion. Replay is from offset 0 (the `LineTailer` already opens at 0), bounded by each file's adoption-time length so side-effects are suppressed only for the already-processed region.

  **Replay double-fire audit (as required — what I checked in `HandleOutput`/`HandleStderr`):**
  - `UsageTrackingService.RecordCompletion` — **NOT idempotent**: durable, incremental (persists to `usage.json`, `+=`). Replay would double-count every prior turn. → **suppressed during replay** (`!entry.Replaying`); post-adoption turns still count.
  - `DetectSessionLimit` (stdout + stderr) — sets the reap-time "park limit-paused" flag; a historical limit line would wrongly park a live build. → **suppressed during replay**; a real current limit is caught live after replay.
  - session-id capture + `UpdateSessionIdAsync` — idempotent (fires once; writes the same value already persisted). Also seeded up-front from the DB row. → **kept**.
  - `ContextTokens` (`TryExtractContextTokens`) — idempotent by **overwrite** (per-line replace), converges to the true current value. → **kept**.
  - `AppendToLogFile` → summary `logPath` — would duplicate prior lines → handled by **truncating `logPath` at adoption**; replay rebuilds it. → kept + truncate.
  - `AppendEvent` → `Events` + `ActiveSubagents` — rebuilds the transcript (the point); fresh process → empty buffers, no dup; subagents are add/remove **balanced** so the end state = genuinely-in-flight subagents. Cosmetic only: an in-flight subagent's elapsed shows from adoption time. → **kept**.
  - state machine + `ScheduleAutoFinalize`/`CancelAutoFinalize` — in-memory; converges to the last line. `ScheduleAutoFinalize` is a **no-op** for adopted builds (`IdleFinalizeMs = 0`, since there's no stdin to close), so no timer thrash and no spurious finalize. → **kept**.

  - `LogRawSampleOnce` — one-shot per app run (Interlocked); ≤1 extra diagnostic line. → harmless, kept.

  **Step 4 — honest stdin.** `OwnsInteractive` now means "owns a live writable stdin" and is **false for adopted** (their `Stdin` is null) and for retained. Render/context/state were split into new `IsInteractiveRenderable` (true for adopted + retained) so live output, context meter and working/waiting state keep working — repointed at all render callers (BuildWatch render loop + OccupySlot + resume rebind; FocusImmersiveView `PumpTranscript`; GitDetailView `TailBuildLog`). Stdin callers stay on `OwnsInteractive` (BuildWatch send; FocusImmersiveView send-enable/send; GitDetailView send; BuildQueuePanel "Resume (unstick)" menu → correctly hidden for adopted). Applied in `ApplyInteractiveState` (Build Watch), `SetSlotState` Running (no first-mount flash), and `GitDetailView.ReconcileStatusPill`.

  **AdmitNewRunning / sweeps (verified, not assumed):** `BuildWatchWindow.AdmitNewRunning` needs no change — it admits any `running` row not already in a slot, so once the row stays `running` the slot remounts on the window's own next poll (confirmed by reading it). `ReclaimLegacyHeldRowsAsync` only touches `held` rows (adopted are `running`) → untouched. `MaybeSweepWorktrees` is non-force + ownership-gated on the worktree owner pid, which is the build pid and still alive → the adopted build's worktree is retained (confirmed via `StampOwnerAsync`/sweep code).
