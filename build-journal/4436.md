### Mechanism
- **Root cause closed (no password in argv):** new `scripts/db/pg-cli.mjs` `pgCli(databaseUrl)` parses the URL, removes
  the userinfo password (and any `?password=` query param), and returns `{ conninfo, env }`. `conninfo` is the
  password-free URL (`postgresql://postgres@localhost:5432/shanemccawmsp`) and goes in argv. `env` is `process.env` plus
  `PGPASSWORD=<percent-decoded password>`, which libpq reads when the conninfo carries none. Used at every psql/pg_dump
  call site: reset-dev-database.mjs `psqlValue`, `psqlRun`, `takeBackup` (pg_dump), `runResetSql` (psql -f), plus
  find-tenant-scoped-tables.mjs `queryAllFkEdges`, which had the same argv pattern and is called by the reset script and
  run directly by the palette. pg_restore takes a file only, no conninfo.
- **Defense in depth, script side:** `redactConnectionSecrets(text)` replaces `scheme://user:pw@` userinfo with
  `scheme://<credentials-redacted>@` (user AND password; host/port/db stay readable) and `password=…` / `PGPASSWORD=…`
  values with `<redacted>`. Applied in reset-dev-database.mjs's `main().catch`, the dry-run/real-run failure prints
  (stdout/stderr/error.stack), and the interactive confirm prompt (it used to print the raw `${databaseUrl}`, a second
  leak found in this build). find-tenant-scoped-tables.mjs's entry point now catches too and prints the redacted message.
- **Defense in depth, BuildConsole side:** `PaletteScriptProcess.RedactConnectionSecrets` (same two patterns,
  IPaletteConfirmGate.cs) runs inside `PaletteScriptProcess.Combine` (every gate's script output), on the whole
  DevDatabaseResetGate preview-failure and execute pane text, on `CleanDevDatabaseChainGate`'s `Render()`, and on the
  palette's find-tenant-scoped-tables runner output (MainWindow.CommandPalette.cs).
