- 2026-08-31 ✅ DONE — Implemented the state-aware hover popover on the Git Board `IssuesTree`
  (`CreateIssueHeader` in `Controls/LeftSidebar.xaml.cs`), replacing the plain per-dot native
  tooltips with a real `Popup` (`IssueHoverPopup` in `Controls/LeftSidebar.xaml`, placed inside
  the `IssuesView` Grid — not a sibling tab's, since a Popup nested under a
  `Visibility="Collapsed"` ancestor won't render). Status pill/title/snippet card plus one
  contextual primary action, resolved from the issue's most-recently-updated associated
  `QueueItem` (same lookup `GitDetailView.LoadIssue` already uses, via the cheap in-memory
  `GetQueueItems` delegate):
  - **Queued -> Dispatch Now** — fully wired, calls `BuildQueuePanel.QuickDispatchAsync` (same
    `_watcher.StartNowAsync` body as the right-click menu's "Start Now").
  - **In progress + In flight (running) -> progress bar + Cancel/Stop** — fully wired. Progress
    bar reads `BuildProgressTracker.GetProgress(build.Id)` (#2033, confirmed landed at
    `87c89c64a`, verified ancestor of main); Cancel/Stop calls `QuickCancelOrStopAsync` (same
    `_watcher.TryStop`/`_db.MarkCompleteAsync` body as the menu's "Stop").
  - **Done -> Open Build** — fully wired, fires the same `QueueItemChatRequested` event the
    "Open Originating Chat" menu item/chat badge already use.
  - **Failed -> Retry** — fully wired, calls `QuickRetryAsync` (same `_db.QueueBuildAsync` fresh-row
    body as the menu's "Retry (start over)").
  - **Has a question -> inline answer -> resume session** — GRACEFULLY DEGRADED. Confirmed #2036
    (the mechanism that would detect a specific pending question) is NOT built yet — its issue has
    only design-discussion comments, no code. There is no real signal on `QueueItem` to detect
    "this build is specifically waiting on an answer" vs. "just running." Rather than fake that
    detection, a running build's card always offers the same inline reply box -> resume-session
    action (`QuickReplyAsync`, same `_db.QueueBuildAsync(resumeSessionId:...)` body as the menu's
    "Reply..."), so the resolution mechanism is real and reused — only the specific-question
    detection is deferred to #2036.
  - **Blocked** — plain "waiting on #N — title" text fallback (already richer than a bare number,
    using the existing `BlockedByNumber`/`BlockedByTitle` fields). Confirmed #2062 (blocker
    "ghost entity" card) is NOT landed (no bookend file, no matching commit) — this matches
    current behavior per #2061's own comment, and is not blocked on #2062.
  - Parked/external/capped/limit-paused/verifying builds (not one of #2061's 6 canonical states)
    get a plain status readout + a universal "Open Chat" fallback rather than being forced into
    the wrong bucket.
  Also added public `BuildQueuePanel.Quick*Async` wrapper methods (`QuickDispatchAsync`,
