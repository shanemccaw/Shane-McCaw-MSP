- 2026-08-30 ✅ DONE — shipped in `cec70a647`, pushed to `main` at `c93cc7ae1`.

  **Step 1 (XAML/code-behind):** deleted `DowntimePanel`, `DowntimeHeader`, `SuggestionsPanel`,
  the "Tap one…" text and `BackNowBtn` from `FocusModeBar.xaml`. In `.xaml.cs` deleted
  `RefreshDowntime`, `OnDowntimeChanged`, `BackNowBtn_Click`, `BuildSuggestionChip`, the
  `DowntimeChanged` subscribe/unsubscribe, and the now-orphaned `SuggestionActivated` event +
  its now-unused `Res()` brush helper. `PickerPanel`/`ActivePanel`/`MiddlePanel`/`InProgressStrip`/
  `RightPanel` untouched.

  **Step 2 (service + wiring):** in `FocusModeService.cs` removed the whole downtime state
  machine (`_inDowntime`, `InDowntime`, `_pendingRestore`, `_suppressReentry`,
  `_lastDowntimeEnd`, `ReentryCooldown`, `EnterDowntime`, `ExitDowntime`) and — since `Tick()`
  was *entirely* the downtime detector, nothing else — removed `Tick()` itself along with the
  `DispatcherTimer` that drove it and `Start()`'s `ui`/`buildSaturation` parameters (now
  parameterless `Start()`). Removed `_captureContext`/`_restoreContext`, `RequestRestoreNow`,
  `NotifyBuildFinished`, the `DowntimeChanged` event, `SuggestionTaken`, `NoteSuggestionsShown`.
  Removed `_buildSaturation`/`GetBuildSaturation`/`FocusBuildSaturation` entirely — `Tick()` was
  their only reader and it's gone (confirmed by grep before removing: no other caller). Removed
  `FocusContextSnapshot`/`FocusContextTab` from `FocusModels.cs` and `CaptureFocusContext`/
  `RestoreFocusContext`/`PanesOf`/`DerivePaneMode`/`ReopenFocusTab` from `MainWindow.FocusMode.cs`
  (no other caller). Removed the `_queueWatcher.BuildFinished += … NotifyBuildFinished` wiring at
  the old `MainWindow.FocusMode.cs:58` — the *other*, distinct `BuildFinished` subscription in
  `MainWindow.FocusImmersive.cs` (`OnFocusImmersiveBuildFinished`, a celebration-toast handler,
  unrelated to restore) was left alone, confirmed untouched by diff.

  `_state.LastContext` / `FocusPersistState.LastContext`: nothing else read it (grep-confirmed),
  so the property is removed from the C# model and no longer written. The existing
  `%AppData%\BuildConsole\focus-mode.json` on disk still has a real `LastContext` value from a
  prior session — confirmed via `Get-Content | ConvertFrom-Json` before touching anything — and
  it was left exactly as-is; no migration/cleanup code was added, per the issue's instruction.

  `MainWindow.FocusMode.cs:31`'s `SuggestionActivated` wiring: removed, since the downtime band's
  chip builder (its only raiser) is gone. `OnFocusSuggestionActivated` itself was **kept**, not
  removed — `MainWindow.FocusImmersive.cs`'s `takeSuggestion` callback also calls it (a second,
  independent source I found by grep before deleting anything). Its body no longer calls the
  now-removed `SuggestionTaken`; it's now just `OpenChatForIssue(s.IssueNumber)`.

  **Step 3 (immersive empty state) — decision:** kept `Suggestions`, `RecomputeSuggestions`,
  `MaxSuggestions` and the `FocusSuggestion` model alive in `FocusModeService`, purely as the
  data source `FocusImmersiveView.ShowEmptyState`/`BuildSuggestionChip` already reads
  (`svc.Suggestions`) — untouched, not edited. `RecomputeSuggestions()` still runs off real board
  data (open issues under the active milestone) and is still called from `Activate()` and
  `UpdateBoardSnapshot()`, so the immersive empty state keeps getting fresh, real suggestions
  with no downtime tie-in at all.
