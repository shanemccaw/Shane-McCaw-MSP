- 2026-09-10T12:46:07Z ⏳ IN FLIGHT — Traced the real Dispatch call path. Both DispatchPanel.DispatchAsync (via `IssueDispatchService.DispatchAsync`) and `ForceDispatchAsync` construct a plain `GitHubApiClient`, whose single `HttpClient` is wrapped by `GitHubRateLimitHandler` (Git #2815). That handler consults the ONE shared `GitHubRateLimitCircuit` for EVERY request, so when automatic background polling trips the circuit, a manual Dispatch's `GetIssueAsync` gets a synthetic 403 → throws → "Couldn't reach GitHub". Fix: give manual, single, user-initiated actions a manual-priority client that skips the circuit's pre-emptive suppression (always makes the one immediate real attempt), still records the real outcome (a real rate-limit trips the circuit; a success closes it), and only backs off if THAT client's own call is itself rate-limited.
