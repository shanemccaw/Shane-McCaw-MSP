# #4838 — Plan

Posted: 2026-09-19T05:10:00Z

## Problem Description
`sharepoint:storage-utilization` stores `"mccawsoft2.sharepoint.com"` in `sharepointStorageUsagePercent`; two SIGNALS cards (Licensing, Health) render `non_numeric_value`.

## Root Cause Analysis
Live `monitor_checks` row: `endpoint=/sites`, `properties=["id"]`, `mapping=[{first, sourceField:"id", target:"sharepointStorageUsagePercent"}]`. Graph `GET /sites` returns site objects (`id` = `host,siteGuid,webGuid`); **no response field on that endpoint carries storage or a percent**, so this is not a wrong-sourceField swap: no correct sourceField exists for this endpoint. A tenant-wide percent has two real inputs on two surfaces:
- quota: SharePoint admin CSOM `Tenant.StorageQuota` (MB) — probed live for `mccawsoft2`: `StorageQuota = 1058816`.
- used: Graph usage report `/reports/getSharePointSiteUsageStorage(period='D7')`, column `Storage Used (Byte)`.

## User Review Required
None. (Sibling checks `sharepoint:storage-near-limit` / `sharepoint:site-count` share the same `/sites` shape; noted as findings, not changed here.)

## Proposed Changes
- [`sharepoint-admin` op registry](https://github.com/shanemccaw/Shane-McCaw-MSP/blob/main/artifacts/api-server/src/lib/monitor-executor.ts) — add `tenant-storage-utilization` op: quota from `getTenantProperties`, used bytes from the Graph report, returns `{sharepointStorageUsedBytes, sharepointStorageQuotaBytes, sharepointStorageUsagePercent}`; throws (no fabricated 0) when either input is missing.
- Migration `lib/db/migrations/manual/2026-09-19-sharepoint-storage-utilization-percent-4838.sql` (additive UPDATE of one row, run locally): `executor_type='sharepoint-admin'`, `sp_operation='tenant-storage-utilization'`, mapping `first` of `sharepointStorageUsagePercent`.
