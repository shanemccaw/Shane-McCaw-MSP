# #4416 — Command Center: "Reset RBAC test accounts" quick action — plan

(Written after investigation, before the work commit.)

## Real current state (read before wiring)
- `scripts/db/reset-rbac-test-accounts.mjs` (#4396): `--dry-run` = BEGIN...ROLLBACK; **no flag =
  real run with no interactive prompt** (unlike reset-dev-database.mjs there is no `--yes`). Exit
  code 1 on failure (`process.exitCode`). Prints `[resolve] real direct MSP id=<N>`, then on success
  `=== RESULT (JSON) ===` followed by `{ tenantId, mspId, deleted, swept, created[{tag,id,email,
  password,mspRole}], skipped[{tag,email,reason}] }`. The script does **not** write settings.json —
  its README says the plaintext is printed "for you to paste into settings.json". Writing it is
  BuildConsole's job in this issue.
- The dry run's JSON also carries plaintext passwords — for accounts that were rolled back and
  never existed. Showing them as-is would read like real credentials.
- settings.json convention (#3911, live names confirmed by listing names only):
  `TestEnvironmentVariables` pairs `TEST_RBAC_<ROLE>_EMAIL` / `TEST_RBAC_<ROLE>_PASSWORD`, where
  `<ROLE>` is the msp_role split on PascalCase (`MSPOperator` → `MSP_OPERATOR`) for ladder rungs,
  and the tag with `.`/`-` → `_` for the customer/capability accounts (`cap.team.manage` →
  `CAP_TEAM_MANAGE`, `billing` → `BILLING`).
- `BuildConsoleSettings.Load()` → mutate → `Save()` is the sanctioned writer (SaveGate lock,
  atomic replace, #3907 merge of untouched fields) — same as SettingsTabView / TestRunVariables.
- #4415's gate (`DevDatabaseResetGate` + palette "reset confirm mode" keyed on `reset msp #N`) is
  the confirm mechanism to reuse. Its window code is hard-wired to that one gate.
- `NeedsReview=true` is NOT a safe way to flag stale RBAC vars: the manifest scanner prunes
  unreferenced NeedsReview vars.

## Plan
1. Generalize, don't duplicate: `Services/IPaletteConfirmGate.cs` — the interface the palette's
   typed-phrase confirm mode drives (shape regex, phrase, Matches, ExecuteAsync, the confirm
   row/detail copy) plus the shared single-launch node runner moved out of DevDatabaseResetGate.
   `DevDatabaseResetGate` implements it with its exact existing copy/behavior.
2. `Services/RbacTestAccountsResetGate.cs` — preview runs `--dry-run`, arms
   `reset rbac #<live msp id>` only on exit 0 + the resolve line + the dry-run rollback line + a
   parseable RESULT JSON; the preview pane redacts the rolled-back passwords and lists exactly
   which settings.json vars a real run would write. Execute re-checks the phrase, consumes it,
   runs the script with no flag once, parses RESULT JSON, upserts the pairs into settings.json,
   **re-reads settings.json from disk and verifies every value**, and leads the result with the
   real credentials + per-var verification. Stale pairs for accounts deleted-but-not-recreated
   (skipped rungs) are left untouched and named. Nothing sensitive goes to ActivityLog/toasts.
3. Palette window: holds a list of gates; confirm mode = the gate whose shape the input matches.
   #4415's behavior unchanged. New "Reset RBAC test accounts" row (`RunWithResult = PreviewAsync`).
4. README: document the Command Center gate for the RBAC script.
5. Verify: `dotnet build`; headless probe (separate exe referencing BuildConsole.dll, never launches
   BuildConsole.exe) driving the real window key handler + real gates: phrase-before-preview,
   preview via Enter (DB + settings.json unchanged), accidental second Enter, wrong phrase, #4415
   phrase still routed to its own gate, exact phrase → real run, settings.json re-read shows the
   new values and a real `POST /api/auth/login` accepts them, Enter after consumption.
