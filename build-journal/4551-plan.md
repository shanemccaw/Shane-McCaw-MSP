# #4551 plan — config-pack-dry-run.test.ts #4513 P1 case, "no MT app creds" variant

## Problem Description
#4551 reported `config-pack-dry-run.test.ts`'s `#4513: on a P1 tenant, refuses
quickstart-v1 because its CA replacement is report-only` test failing with
`skuReadError: "MT_APP_CLIENT_ID / MT_APP_CLIENT_SECRET not configured"` instead of
the expected `security_defaults_replacement_not_enforcing` refusal, in an
environment with no MT app creds set (every agent worktree).

## Root Cause Analysis
Same defect as #4546 (already fixed and merged to main as 098c8ed60): the test's
`vi.mock("./graph.ts", async (importOriginal) => ({...await importOriginal()...}))`
factory was async, and one of three separate static importers of
`graphFetchForTenant` (`license-gate.ts`) lost the binding race and kept the real
implementation instead of the mock. That real implementation then hit a real Graph
token fetch, which fails differently depending on environment:
- Local dev with a fake tenant guid → `AADSTS90002` (the #4546 repro).
- No MT app creds at all → `MT_APP_CLIENT_ID / MT_APP_CLIENT_SECRET not configured`
  (#4551's exact variant).

Both are the same underlying bug: the mock never reached `license-gate.ts`'s SKU
read, so the SKU precondition failed closed as `license_required` regardless of the
specific transport error, masking the Security Defaults refusal the test asserts.

#4546's fix replaced the async `vi.mock` factory with a synchronous one (using
`vi.hoisted()` for stand-in error classes), which removes the binding race
entirely — all three importers now correctly bind to the mock.
