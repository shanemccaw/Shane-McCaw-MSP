## Log
- 2026-09-06T15:30:30Z ⏳ IN FLIGHT — Confirmed via `.pnpmfile.cjs` (Git #1986/#1988) that
  pnpm's own metered/worktree install gate already lives outside `preinstall` and is
  unaffected by this finding. Per the issue's own "Suggested follow-up": kept the
  `preinstall` guard (still correct for `npm`/`yarn`, its original purpose — pnpm never
  runs root lifecycle scripts at all, so there is nothing to "extend" for pnpm there;
  that enforcement correctly lives in `.pnpmfile.cjs` already). Replaced the opaque
  `sh -c '...case $npm_config_user_agent...'` one-liner with
  `scripts/guard-non-pnpm-install.cjs` — same behavior (removes stray
  `package-lock.json`/`yarn.lock`, refuses non-pnpm installs), but as a real, documented,
  cross-platform (no `sh` dependency) file whose header states plainly that it can never
  fire under `pnpm install` and why, so no future reader mistakes it for a pnpm gate.
  Verified directly: `npm_config_user_agent=pnpm/... node scripts/guard-non-pnpm-install.cjs`
  exits 0; `npm_config_user_agent=npm/... node scripts/guard-non-pnpm-install.cjs` prints
  "Use pnpm instead" and exits 1.
