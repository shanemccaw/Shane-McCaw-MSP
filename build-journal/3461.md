  **What shipped, real and working (all four checklist items):**
  - `Models/VaultEntry.cs` — data model: `Id`, `TenantGuid` FK, `Label`, `Username`, and the AES-GCM ciphertext triple for the password. Local-only, never the Postgres platform DB.
  - `Services/DpapiProtector.cs` — DPAPI via P/Invoke to `crypt32.dll` (`CryptProtectData`/`CryptUnprotectData`, CurrentUser scope). **Zero new NuGet** — chosen deliberately over the `System.Security.Cryptography.ProtectedData` package to avoid any metered download (Git #1987) and stay in-box.
  - `Services/VaultService.cs` (+ `IVaultService.cs`) — two real encryption layers: (1) the entire serialized vault file is DPAPI-wrapped at rest → tied to the Windows login, can't be read on another machine/user (also protects labels/usernames); (2) each password is AES-256-GCM encrypted with a PBKDF2-SHA256 (210k iters) key derived from the master password. Master-unlock is **session-gated**: the derived key is held in memory only while unlocked and `Lock()` zeroes it (`CryptographicOperations.ZeroMemory`); a verifier token validates the master password (wrong password → false, no lockout side effect). Atomic write (temp + move). Create-on-first-run vs unlock-on-restart.
  - `Shell/VaultPanelView.xaml(.cs)` — Admin-tab center document, three states (create master password / unlock / unlocked). Unlocked shows the per-tenant entry list (scoped to the active tenant), an add/edit form, and per-entry Reveal (masked by default)/Copy username/Copy password/Edit/Delete (confirm-armed in place per UI_RULES.md §3, no dialog) + a Lock button.
  - Wiring: `RegisterAdminTab()` adds the "Vault → Credential Vault" `Open`-intent ribbon command (Admin tab was previously unregistered/empty); a `dest:vault` command-palette destination; `VaultPanel` added to the document-overlay set; `ShowDocument` calls `OnShown()` to re-evaluate lock state on open.
