## Log
- 2026-08-30 ⏳ IN FLIGHT — read `PsExecutionDeployService.cs`'s `GetServingRevisionAsync` /
  `ParseFirstActiveRevision` in full. Confirmed root cause is actually **both** likely causes
  named in the issue, compounding: (1) `GetServingRevisionAsync` is called exactly once,
  immediately after `containerapp update` returns, with no poll/retry for Azure's traffic
  switch to settle; and (2) `ParseFirstActiveRevision` returns the **first** element of the
  `[?properties.active]`-filtered array unconditionally — during a revision transition, Azure
  can report more than one revision as `active: true` simultaneously (old revision still
  active with fading traffic, new one ramping up), and array order is not guaranteed to put
  the new one first. About to fix: poll with a bounded timeout, prefer a revision whose name
  matches the just-deployed suffix (deterministic), else accept an active revision carrying
  100% traffic, else keep retrying; return an honest "could not confirm" failure if the
  timeout expires.
- 2026-08-30 ✅ DONE — `PsExecutionDeployService.cs`: replaced `ParseFirstActiveRevision`
  (returned the first `active`-flagged array entry, unconditionally) with
  `ParseActiveRevisions` (returns ALL active entries) + `SelectServingRevision` (picks, in
  order: an active revision whose name matches the just-deployed suffix — deterministic —
  else the sole active revision carrying 100% traffic). Added `WaitForServingRevisionAsync`,
  a bounded poll (default 90s timeout, 3s interval) that retries `SelectServingRevision`
  against fresh reads until it gets a confident answer or times out; on timeout it returns
  null and the caller (`DeployDevAsync`) reports "could not confirm which revision is
  serving" rather than the prior single-shot read. `DeployDevAsync`'s step 3 now calls
  `WaitForServingRevisionAsync(suffix, ...)` with the suffix it just requested.
  `GetServingRevisionAsync` (the plain read-only path used by `psExecutionRevision`, no
  deploy context) now goes through the same `SelectServingRevision` logic with no expected
  suffix, so it also stops trusting array order.
