  published anywhere and, per the real third-party integration, exposes energy added, duration,
  battery range and location -- no cost field. `vehicle_state.odometer`, by contrast, is a
  long-documented, stable field (confirmed via the same research) -- safe to build against with
  full confidence.

## Real scope built
1. **Real odometer sync** (item 1) -- `core/tesla.mjs`'s new `getVehicleState()` reads the real
   `vehicle_state.odometer`. `core/vehicles.mjs`'s new `syncOdometerFromTesla()` writes it onto
   whichever one vehicle is marked `tesla_synced` (migration 060), wired into the existing 6-hour
   housekeeping sweep (`server.mjs`) and an on-demand `POST /api/tesla/sync` route. The Cars
   card/detail page (`public/app.js`) now shows a real, live "miles since last service / miles
   until next / overdue by mileage" figure (`vehicles.mjs`'s new `mileageStatus()`) computed ONLY
   from real numbers (synced odometer, Shane's own `maintenance_interval_miles`, a logged entry's
   own mileage) -- never a guessed driving rate or a fabricated calendar projection.
   `findDueCarReminders` now also surfaces a real `maintenance_mileage` overdue reminder.
2. **Real charging-session sync** (items 2/3, narrowed per the investigation above) --
   `tesla.mjs`'s new `getChargingHistory()` reads Tesla's real `/api/1/dx/charging/history`
   defensively (envelope AND field-name uncertainty both real and unresolved without a live
   account -- tries multiple plausible shapes/casings, keeps the untouched `raw` JSON on every
   row so nothing real is silently dropped). `vehicles.mjs`'s new
   `syncChargingSessionsFromTesla()` upserts sessions (migration 060's
   `tesla_charging_sessions`, idempotent on a real dedupe key) and computes a cost ESTIMATE from
   Shane's own real `charge_cost_per_kwh` (migration 056) x real kWh added -- never presented as
   a Tesla-sourced figure, same honest-estimate discipline #3238 already established. New
   `GET /api/tesla/charging-sessions` + Cars detail page "Charging" section, clearly labeled as
   an estimate.
3. New `PATCH /api/cars/:id/tesla-sync` + `vehicles.setTeslaSynced()` -- the real, explicit,
   at-most-one-vehicle link between a Money vehicle and the connected Tesla, with UI in the Cars
   detail page to turn it on/off.
4. Migration `060_tesla_odometer_charging_sync.sql` -- ran it myself against the real local
   Postgres (`vehicles.tesla_synced/current_mileage/mileage_synced_at`,
   `tesla_charging_sessions`). Confirmed via `\d` afterward.
