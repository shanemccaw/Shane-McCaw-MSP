- 2026-08-30 ⏳ IN FLIGHT — Replacing the stateless `hash % 10` in `GetBuildSetBrush` with a coordinated color registry that tracks currently-active build sets and assigns each a non-colliding palette color, freeing colors when a set goes inactive.
- 2026-08-30 ✅ DONE — Added `Services/BuildSetColorRegistry.cs`: `ReportActive(source, names)` from both the Build Queue panel (`ReportActiveBuildSets`, sets with any queued/running/limit-paused/verifying item) and Build Watch (occupied slots' build sets); `GetPaletteIndex`/`GetBrush` assign the lowest palette index not in use by another currently-active set; colors free after a 30s grace once a set is visible nowhere. `GetBuildSetBrush` now delegates to it. Overflow (>10 concurrent sets) gets a deterministic stable color + secondary differentiator (dashed accent underline + "⚠ shared color" note) in `BuildBuildSetHeader`.
  Verified by driving the real compiled `BuildSetColorRegistry` from PowerShell (reflection, off UI thread via the non-WPF `GetPaletteIndex` seam):
  - 10 concurrent sets → all 10 palette colors, each exactly once, zero collisions.
  - Colors stable across repeated refresh ticks (no flicker).
  - **>10 edge case HIT deliberately:** 14 concurrent sets → first 10 unique + `Shared=false`; 11th–14th `Shared=true` (deterministic color + dashed-underline differentiator). Uniqueness is mathematically impossible past 10 with a 10-color palette; the fallback is a stable color + shape/text cue, not a silent collision.
  - After the 30s grace, dropped sets' colors were freed and reclaimed by new sets, all unique.
