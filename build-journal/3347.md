## Log
- 2026-09-09T20:53:31Z ⏳ IN FLIGHT — Investigated the closed-sweep cascade. Root cause confirmed: `BatterUpQueueService.SweepClosedIssuesAsync` / `AiBatterUpQueueService.SweepClosedIssuesAsync` read stale "closed + still in Batter Up/AI Batter Up" candidates from the local mirror (whose board-status only refreshes on the slow #3337 full-sync interval), then fire `gh.SetIssueStatusByNumberAsync(number, Done)` **once per item** — and that method itself does a resolve query (`GetProjectItemIdForIssueAsync`) + a mutation (`SetProjectItemStatusAsync`), so 59 stale items ≈ 118 rapid GraphQL calls in ~2s. That burst trips GitHub's secondary rate limit → `GitHubRateLimitCircuit` opens → everything else (gh issue list, mirror incremental sync, Git Board blocked-by sweep, manual refresh) short-circuits for minutes. Fix: batch the resolve+verify+mutate the same way #3337 batched the mirror sync (aliased GraphQL, chunked), skip candidates already off the board (mirror is stale), pre-check the circuit, and cap per-run so a large backlog drains bounded instead of bursting.
