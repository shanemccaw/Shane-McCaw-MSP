Root cause confirmed: `BatterUpQueueService.SweepClosedIssuesAsync` / `AiBatterUpQueueService.SweepClosedIssuesAsync` read stale "closed + still in Batter Up/AI Batter Up" candidates from the local mirror (whose board-status only refreshes on the slow #3337 full-sync interval), then fire `gh.SetIssueStatusByNumberAsync(number, Done)` **once per item** — and that method itself does a resolve query (`GetProjectItemIdForIssueAsync`) + a mutation (`SetProjectItemStatusAsync`), so 59 stale items ≈ 118 rapid GraphQL calls in ~2s. That burst trips GitHub's secondary rate limit → `GitHubRateLimitCircuit` opens → everything else (gh issue list, mirror incremental sync, Git Board blocked-by sweep, manual refresh) short-circuits for minutes.
