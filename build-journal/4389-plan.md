# #4389 — plan

Root cause (from issue body): `PushArtifactCommitWithRebaseAsync` runs `git fetch`/`rebase`/
`push` against the checkout's whole local `main`. Two callers stage/commit onto the checkout's
real index first (`git add` + `git commit -- <path>`), then hand off to that rebase/push. That:
1. rebases+pushes any unrelated unpushed local commit sitting in the checkout, and
2. refuses outright (rebase abort) when the checkout has other staged/dirty tracked changes.

## Fix direction (from issue)
Publish the artifact commit in isolation, never touching the checkout's branch or real index:
- `git commit-tree` on top of current `origin/<branch>`, using a temporary/throwaway index
  (`GIT_INDEX_FILE` env var) populated via `read-tree origin/<branch>` + `add -- <relPath>` only.
- `git push origin <sha>:<branch>` with fetch-and-retry on non-fast-forward rejection.
- No `git add`/`git commit`/`git rebase`/`git reset` ever touches the real `.git/index` or HEAD.

## New method
`UiAutomationQaSessionService.PublishArtifactCommitIsolatedAsync(repoRoot, branch, sessionId,
relArtifactPath, commitMessage)` — replaces `PushArtifactCommitWithRebaseAsync` and absorbs the
`git add`/`git commit` staging step too (both are no longer needed against the real index).
Both callers (`FinalizeAutomationSessionAsync` and `VisualTestTrackerSessionSyncService.
StageCommitPushAsync`) switch to it. "Nothing to commit" case preserved by comparing the built
tree sha against `origin/<branch>^{tree}`.

## Verification
Real reproduction in a scratch repo for both failure modes named in the issue:
1. Unrelated unpushed local commit in the checkout survives untouched, unpublished.
2. Dirty/staged tracked file elsewhere in the checkout no longer blocks the artifact push.
