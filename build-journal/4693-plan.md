# #4693 — Plan: repoint Git Board `IsInFlight` / `IsComplete` off GitHub labels

Sub-issue of #4692 (Label & Board Architecture Simplification). Basis: the #4686 label audit.
All permalinks are pinned to `main` @ `5a0564bb78fecc2fd2c4ba61e5a759b63a8170bf`.

## Problem Description

BuildConsole's Git Board decides "is a build running on this issue?" and "is this issue done?" by
reading two GitHub **labels**, `in-flight` and `complete`. #4692 retires both labels (Real GitHub
issue close is the sole authority for "done"; local `bt_build_queue` is the authority for "running").
The follow-up #4694 stops BuildConsole *writing* them. Until the read side stops depending on them,
that stop would leave the board frozen/wrong — so this issue lands first.

Out of scope, per the issue: `blocked` and `Shane To-Do` reads (unchanged), the label writers
(#4694), the broken "Mark Complete" menu item (#4694), dead code (#4696).

## User Review Required

1. **`IsComplete` meaning changes** from "labelled `complete` (open, awaiting review)" to "issue is
   CLOSED". The board is OPEN-only, so `IsComplete` is now effectively false on board nodes; the only
   reader is the Mark Complete menu item, which #4694 removes. Between this landing and #4694, that
   (already non-functional, 410) item will read "Remove 'complete' label" on a closed issue. I am
   deliberately **not** touching it here — it is #4694's explicit deletion target and the issue says
   to leave the writers alone. Flagging so it isn't a surprise.
2. **`limit-paused` / `external` / `verifying` are not counted as in-flight.** #4693 specifies
   `('queued','running')`; I follow it. (`verifying` = agent finished, awaiting close, which the old
   `complete` label covered — closure now, per #4692, is the terminal signal.)
3. **In-Flight tile** groups by the issue's immediate parent, sourced from the local
   `bt_issue_mirror` (already synced, zero GitHub calls) instead of `gh`'s `parent` field. An issue
   the mirror has no row for falls back to the queue row's own title and the "No Epic" group.
4. The tile becomes live (re-renders when the local queue changes) instead of "once at tab open",
   since it no longer costs a GitHub call — this is why #2900's manual-only rule doesn't apply.
