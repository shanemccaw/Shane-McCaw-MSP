## What shipped

**The missing backend, built rather than stubbed.** Nothing let a UI ask "what may
*I* do" — #2455 built the evaluator, #2457 seeded the rows, #2458 put `requireRole`
on it, and `/admin/rbac/*` (#2461) answers "what may user N do" to an administrator.
New `GET /api/auth/me/context` returns the signed-in identity's real granted
capability keys per system, from the same `*_feature_role_mapping` rows the server's
own evaluator reads. Reports `model.available:false` when the model is unreadable, and
`can()` abstains to true on that — a presentation hint fails OPEN where an enforcement
gate fails closed.

**`artifacts/portal` now carries no role literal at all**, per #1696's rule for the
new artifacts. The `MspRole` seven-literal union became an opaque string; the two
copies of the landing chain (`:476`, `:801`) read `landingSurface` off the
impersonate-exchange response; `UserMenu`'s `Record<MspRole,string>` label table became
`presentation.roleLabel`. The Billing menu row is gated on `customer:billing.view` —
the capability #1696 was actually filed about. Hides nothing today; becomes real with
no code change.

**admin-panel's three role-literal decisions** now read the server:
`GET /admin/active-directory/roles` (new) for the role list + linkage requirement, and
server-decided grouping + `impersonationScope` on `/admin/view-as/accounts`.

**Real drift bug fixed in passing** (not filed — fixed here): `ActiveDirectoryUserPane`
and `AdUserCanvas` each held a copy of `roleLinkageRequirement()`, and the v1 copy had
diverged — it returned `"none"` for `Free` and `Assessment` where the server returns
`"customer"`, so that pane silently withheld the "requires a tenant linkage" hint for
two of the seven roles. Exactly the drift #1696 predicts.
