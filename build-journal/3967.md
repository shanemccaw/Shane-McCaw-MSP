## What shipped
- New route module `artifacts/api-server/src/routes/msp-azure-credentials.ts` — client-scoped CRUD:
  - `GET    /msp/:mspId/clients/:clientUserId/azure-credential` — fetch (or null), enriched with `expiresOn` via `safeGetExpiry`.
  - `POST   /msp/:mspId/clients/:clientUserId/azure-credential` — upsert (insert or update in place).
  - `PUT    /msp/:mspId/clients/:clientUserId/azure-credential` — update in place (404 if none yet).
  - `DELETE /msp/:mspId/clients/:clientUserId/azure-credential` — remove.
- Registered in `artifacts/api-server/src/routes/index.ts` (import + `router.use`) directly after `adminAzureCredentialsRouter`.
- **Gate:** `requireCapability("ladder.msp-operator")` + `requireMspScope("params")` (NOT `requireAdmin`). The capability guard is the standing MSP Console gate (mirrored from `msp-launch-control.ts`); `requireMspScope` alone would let any authed user whose own `mspId` matched the path through, so both are used together — consistent with sibling MSP Console routes.
- **Ownership filter:** every handler runs `clientBelongsToMsp(clientUserId, mspId)` first (`users.id = clientUserId AND users.msp_id = mspId`); a client in another MSP (or with no `msp_id`) is treated as 404. No cross-MSP read or write is possible.
- **Key Vault reuse:** raw secret written via `setSecretValue` under the same deterministic `client-${clientUserId}-appreg` name the admin surface uses; only the KV secret NAME is persisted. The raw secret value is NEVER returned in any response (responses are metadata rows / `{ok:true}` / `null`).
