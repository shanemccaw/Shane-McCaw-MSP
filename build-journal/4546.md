## Changes Made
- `artifacts/api-server/src/lib/config-pack-dry-run.test.ts`: replaced the async
  `vi.mock("./graph.ts", async (importOriginal) => ({...await importOriginal()...}))`
  factory with a synchronous one (`vi.mock("./graph.ts", () => ({...}))`), using
  `vi.hoisted()` to define stand-in `ConsentRevokedError`/`LicenseGapError` classes
  instead of spreading the real module's exports.

## Root Cause
Three separate modules (`config-pack-dry-run.ts`, `config-pack-orchestrator.ts`,
`license-gate.ts`) each independently import the named export `graphFetchForTenant`
from `./graph.ts`. With an **async** `vi.mock` factory awaiting `importOriginal()`,
at least one of those importers' static-import bindings resolved before the awaited
promise inside the factory settled, binding it to the REAL `graphFetchForTenant`
instead of the mock. Confirmed empirically with a scratch debug test file
(not committed): `license-gate.ts`'s `getProvisionedServicePlanNamesForTenant` was
the importer that lost the race, so its `/subscribedSkus` read always hit a real
Graph token fetch and failed (`AADSTS90002` locally with a real fake tenant guid,
or `MT_APP_CLIENT_ID / MT_APP_CLIENT_SECRET not configured` per #4551 with no MT app
creds set at all). The SKU precondition then failed closed as `license_required` —
which happens to be the SAME refusal code 6 of the file's 7 tests already expect for
a genuinely-unlicensed tenant, masking the bug until #4513's P1-tenant case (which
expects the run to get PAST the license check to
`security_defaults_replacement_not_enforcing`) exposed it.
