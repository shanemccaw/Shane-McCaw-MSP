  **Placement decision:** new section lives inside `BuildQueuePanel` itself
  (docked Top, right below its own header Border, above the QUEUE ScrollViewer) —
  NOT reusing BatterUpPanel/AiBatterUpPanel's header row. Reasons: (a) the rollup's
  data (`_lastItems` from `bt_build_queue`) is already owned by BuildQueuePanel —
  putting it in a sibling UserControl would mean duplicating that data or wiring a
  new cross-panel event for no benefit; (b) BatterUpPanel/AiBatterUpPanel's
  post-#1816 header only has room for a short inline count string (`TxtCount`), not
  a multi-row expandable rollup; (c) MainWindow docks
  `AiBatterUpPanel → BatterUpPanel → BuildQueuePanel` top-to-bottom, so a new
  top-docked section at the very top of BuildQueuePanel is the next visual element
  after the (now minimal) Batter Up rows — it visually occupies the freed space
  without surgery on a different panel's XAML.

  **Grouping/format decisions:**
  - Buckets are "up next" (`queued` + `limit-paused`), "running" (`running` only),
    "verifying" (`BuildQueuePostgresClient.VerifyingStatus`) — a finer split than
    QueueFilterCombo's own Running/Queued (#1829 folds verifying into Running),
    because Shane's own example line names all three separately.
  - A build set with all three counts at zero is dropped entirely (done/canceled/
    parked/external members don't count as "current activity") — satisfies the
    "don't clutter" verification requirement.
  - null/blank `BuildSet` buckets under literal "Ungrouped", sorted last (only
    shown if it has real activity); real named sets sort alphabetically.
  - Collapsed line format matches Shane's example exactly, with issue numbers only
    next to "verifying" (his stated example — the most actionable of the three,
    since it means "session done, waiting on GitHub issue closure"). A separate
    per-row chevron (independent click target from the row body) expands to show
    the full per-category breakdown with numbers for all three — real "reveal more
    detail" content, not a no-op expand affordance.
  - Clicking the row body itself (not the chevron) drills the Build Queue DAG below
    down to that build set. Per the issue's addendum: this **composes (AND)** with
    the QueueFilterCombo status filter and the search box, rather than overriding
    either — e.g. viewing "Queued" + drilling into "BuildConsole" shows queued
    BuildConsole-set items only. Clicking the same row again, or a "Showing: X ✕"
    clear affordance in the section header, resets the drill-down without touching
    the other two filters.
