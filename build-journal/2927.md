     `link-deps.mjs`'s `nodeModulesHosts()` only considers hosts whose
     `node_modules` already exists in the main checkout — so this package was
     silently excluded from linking in EVERY worktree, not just a stale one.
     Fixed: added the missing `@types/react` devDependency, matching the
     working sibling pattern, plus the one resulting `TS7006` implicit-any
     (`useVoiceRecorder.ts`'s `forEach((t) => t.stop())` callback).
  2. `lib/db`'s `vitest` devDependency (added Sep 4, #1907) never reached
     `C:\dev-server`'s own long-lived worktree: `linkDeps()` treated ANY
     existing link at a host as fully current and skipped it outright, but a
     per-package-linked host (Git #2152 — a real `node_modules` dir with
     individually-junctioned entries, NOT a live view of the target) goes
     stale the moment a new dependency lands in the source `package.json`
     after that worktree's `node_modules` was first built. Fixed `linkDeps()`
     to branch on what the EXISTING link actually IS (reparse point = live
     view, skip; real directory = re-sync via the already-idempotent
     `linkHostPerPackage()`) instead of solely on the host's *current*
     `hostHasWorkspaceScope()` classification, which can drift from whatever
     produced the existing link.
