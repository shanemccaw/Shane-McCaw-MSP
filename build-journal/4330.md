## Part 2: stopping it from happening again (9a1f7abf0)
- Root cause: #4122 had already fixed the auto-push path, but `%AppData%BuildConsolesettings.json` still has `"AutomationQaAutoPushEnabled": false`, so every automated run committed without pushing. The manual sync path (`StageCommitPushAsync`) pushed once, and when the push was rejected it kept the commit ("commit is safely local!").
- Both paths now skip committing when push is off, and use fetch+rebase+push with retries. On failure they undo only the artifact commit (`reset --soft HEAD~1` + unstage that path), only when HEAD touches nothing but that path, and not at all if the push actually landed. #4122's old `reset --keep origin/<branch>` deleted the artifact files from disk (confirmed in a scratch repo) and dropped any other unpushed commits. Commits are now limited to the artifact path so they can't pick up anything else staged.
- `request-restart.mjs` now checks on every call whether the serving HEAD is an ancestor of origin/main (`assessServingDivergence`), and exits **4** with a `DIVERGED` line when it isn't. This fires even when the commit itself reads as live, or its restart is deferred in a build set.
- Verification: `serving-checkout.selftest.mjs` all passed (7 new #4330 cases); `selftest.mjs` 59 passed, 0 failed; `dotnet build BuildConsole.csproj` 0 warnings, 0 errors. I also replayed the rejected-push undo with git commands in scratch repos: files stayed on disk and other staged files stayed staged. The C# path itself was not exercised end to end inside a running BuildConsole.
